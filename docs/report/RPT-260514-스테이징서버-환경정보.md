## 5. 배포 파이프라인

### 배포 스크립트
- 경로: `platform/scripts/deploy-staging.sh`
- 모드: `full` | `build` | `restart` | `verify`
- 타깃: `all` | `platform` | `car-manager` | `stock` | `sales` | `hscode`

### 명령 예시
```bash
# 전체 배포 (pull → build --no-cache → down/up → verify)
ssh ambAppStore@stg-apps.amoeba.site \
  "cd ~/ambAppStore && bash platform/scripts/deploy-staging.sh"

# 특정 앱만 재빌드
ssh ambAppStore@stg-apps.amoeba.site \
  "cd ~/ambAppStore && bash platform/scripts/deploy-staging.sh build car-manager"

# 무중단 재기동 (빌드 없이)
ssh ambAppStore@stg-apps.amoeba.site \
  "cd ~/ambAppStore && bash platform/scripts/deploy-staging.sh restart"

# 헬스체크
ssh ambAppStore@stg-apps.amoeba.site \
  "cd ~/ambAppStore && bash platform/scripts/deploy-staging.sh verify"
```

### Verify 동작
- `curl http://localhost:{bff_port}/api/v1/health`
- `curl http://localhost:{web_port}/` (HTTP code)
- `web-*` 컨테이너 내 `mng.amoeba.site` 오타 도메인 잔존 검사
- `docker compose ps`

### 정책
- **금지**: `docker compose build` 직접 실행 → `.env` 누락 위험. 반드시 스크립트 경유.
- **금지**: 프로덕션 직접 배포. 스테이징 검증 후 `main → production` PR로만 진행.
- **VITE 변수**: `VITE_*`는 빌드 시점 인라인이므로 변경 시 반드시 이미지 재빌드.

## 8. 환경변수 관리

- 템플릿: 각 앱 `apps/{app}/.env.staging.example`
- 실제 `.env`: **git 미포함, 서버에 직접 관리** (`apps/{app}/.env`)
- 주요 변수
  - `PORT=31xx` (BFF)
  - `DB_HOST=mysql-apps`, `DB_PORT=3306`, `DB_USERNAME`, `DB_PASSWORD`, `DB_DATABASE=db_app_*`
  - `JWT_SECRET` (AMA JWT 검증)
  - `VITE_API_BASE_URL=/api` (프론트엔드 빌드 인라인)
  - `VITE_AMA_LOGIN_URL` (AMA SSO 로그인)
- 검사: `deploy-staging.sh`가 빌드 전 `.env` 존재 여부 경고 표시 (없어도 진행은 됨 → 누락 시 빌드 실패 가능)

- AMA(AI Management Assistant) JWT SSO Passthrough

- CSP `frame-ancestors`에 `ama.amoeba.site`, `stg-ama.amoeba.site` 허용 (iframe 임베드 대응)
