## 1. 시스템 개발 현황 분석

### 1.1 기존 구조

| 항목 | 현황 |
|------|------|
| 디렉토리 | `apps/app-car-manager/{backend,frontend}/src/domain/trip-log` 기존 도메인 |
| 기술 스택 | NestJS 10 + TypeORM 0.3 + MySQL 8.0 (BE) / React 18 + Vite 5 + RHF + Zustand + RQ5 (FE) |
| 인증 | `@Auth()` 데코레이터 — JWT + `ent_id` 격리 (모든 trip-log endpoint 적용 중) |
| 상태 머신 | `IN_PROGRESS → COMPLETED → VERIFIED` (3단계). VERIFIED 이후 수정 불가 (`CAR-E6002`). |
| 삭제 인프라 | `@DeleteDateColumn ctl_deleted_at` 컬럼 존재하나 미사용 (이번 작업에서도 그대로 미사용) |

### 1.2 제약사항

- 스테이징/프로덕션 DB 는 `synchronize: false` → 모든 schema 변경은 수동 SQL.
- `VITE_*` 환경변수 변경 없음 → 이미지 재빌드 불필요. (FE 빌드는 코드 변경으로 인해 어차피 재실행됨.)
- 다국어 3종(ko/en/vi) 동시 추가 필수.
- 기존 컨벤션 준수: snake_case request / camelCase response / `ent_id` 멀티테넌시 / Mapper static / BusinessException 에러 코드.

### 1.3 기존 코드 참고 지점

| 위치 | 참고 사유 |
|------|----------|
| `trip-log.service.ts:145-182` `update()` | guard 패턴 재사용 (VERIFIED 차단 로직) |
| `trip-log.service.ts:184-200` `submit()` | 상태 전이 로직 패턴 |
| `trip-log.service.ts:57-77` proxy dispatch 생성 | 무효 시 dispatch 동기화 참고 |
| `trip-log.controller.ts:108-118` `@Patch(':id/submit')` | 동일 패턴으로 `/void` 추가 |
| `enums.ts:64-74` `DispatchStatus.CANCELLED` | 이미 존재 — proxy 동기화에 활용 |

## 2. 단계별 구현 계획

### Phase 1 — DB & Backend 기반

**Step 1.1: Enum 확장**
- `apps/app-car-manager/backend/src/common/constants/enums.ts:76-80`
- `TripLogStatus` 에 `VOIDED = 'VOIDED'` 추가.
- └─ 사이드 임팩트: TypeORM `enum` 컬럼이 자동으로 새 값 인식하나, DB 는 별도 ALTER 필요.

**Step 1.2: Entity audit 컬럼 추가**
- `apps/app-car-manager/backend/src/domain/trip-log/entity/trip-log.entity.ts`
- `ctlVoidedAt`, `ctlVoidedBy`, `ctlVoidedByName`, `ctlVoidedReason` 4 column 추가.
- 모두 nullable, `type:` 명시 (CLAUDE.md 규칙).
- └─ 사이드 임팩트: 신규 컬럼은 nullable 이므로 기존 row 영향 없음. Response/Mapper 도 같이 노출되어야 함.

**Step 1.3: DTO 추가**
- 신규 파일: `apps/app-car-manager/backend/src/domain/trip-log/dto/request/void-trip-log.request.ts`
- 필드: `reason: string` + `@IsString() @MinLength(5) @MaxLength(500) @IsNotEmpty()`.
- └─ 사이드 임팩트: 없음 (신규).

**Step 1.4: Service `void()` 메서드 + Guard 강화**
- `trip-log.service.ts`:
  - 신규: `async void(entityId, id, reason, userId, userName): Promise<TripLogEntity>` (REQ §3.4 로직).
  - 수정: `update()` 시작부의 status 가드에 `VOIDED` 추가 (CAR-E6002 메시지 갱신).
  - 수정: `submit()` 시작부에서 `VOIDED` 차단 (별도 분기 또는 통합).
- proxy dispatch 동기화: 같은 서비스에서 `dispatchRepo.update()` 호출 (이미 주입되어 있음).
- └─ 사이드 임팩트: `update()` 동작 변경 — VOIDED 상태에서 update 차단됨 (의도된 변경).

**Step 1.5: Controller 엔드포인트 추가**
- `trip-log.controller.ts`:
  - `@Auth() @Patch(':id/void')` 추가, `@CurrentUser()` + `@Body() req: VoidTripLogRequest`.
  - `tripLogService.void()` 호출 후 `successResponse(TripLogMapper.toResponse(...))` 반환.
- └─ 사이드 임팩트: 없음 (신규 endpoint).

**Step 1.6: Mapper 확장**
- `trip-log.mapper.ts:29` 부근 — response 에 `voidedAt`, `voidedBy`, `voidedByName`, `voidedReason` 4 필드 추가.
- └─ 사이드 임팩트: response payload 사이즈 증가 (~80 bytes/record, 무시 가능). 기존 FE 클라이언트는 미지의 필드 무시.

**Step 1.7: Excel Export 컬럼 추가**
- `excel-export.service.ts:32` 컬럼 정의 + `:57` 행 매핑.
- 한글 헤더: "무효처리일", "무효사유".
- └─ 사이드 임팩트: Excel 컬럼 순서 변경 시 기존 사용자 매크로/스프레드시트 깨질 가능 → **새 컬럼은 맨 끝에 추가**.

**Step 1.8: 에러 코드 등록**
- `CAR-E6005`: Cannot void verified trip log
- `CAR-E6006`: Trip log already voided
- `CAR-E6007`: Void reason is required (또는 class-validator 422 활용 시 생략 가능 — class-validator 가 처리)
- └─ 사이드 임팩트: 없음 (에러 코드 prefix 는 CAR-E60xx 영역에 미사용 번호).

## 5. DB 마이그레이션

### 5.1 적용 SQL (staging → production 동일 적용)

```sql
-- Migration: 2026-05-26 trip-log void feature
-- Target DB: db_app_car

-- 1) Enum 확장
ALTER TABLE car_trip_logs
  MODIFY COLUMN ctl_status ENUM('IN_PROGRESS','COMPLETED','VERIFIED','VOIDED')
    NOT NULL DEFAULT 'IN_PROGRESS';

-- 2) Audit 컬럼 4개 추가
ALTER TABLE car_trip_logs
  ADD COLUMN ctl_voided_at DATETIME NULL AFTER ctl_status,
  ADD COLUMN ctl_voided_by CHAR(36) NULL AFTER ctl_voided_at,
  ADD COLUMN ctl_voided_by_name VARCHAR(100) NULL AFTER ctl_voided_by,
  ADD COLUMN ctl_voided_reason VARCHAR(500) NULL AFTER ctl_voided_by_name;
```

### 5.2 적용 순서

1. **스테이징**:
   - `ssh ambAppStore@stg-apps.amoeba.site` → MySQL container 접속 → `db_app_car` 에서 위 SQL 실행.
   - 메모리 노트(staging-server-is-local): 스테이징은 로컬이므로 SSH 불필요, `docker exec ... mysql -u... -p... db_app_car` 로 직접 실행 가능.
2. **코드 배포**: `bash platform/scripts/deploy-staging.sh` 로 빌드 + restart.
3. **검증**: 스테이징 환경에서 TC 수행 → TR 작성.
4. **프로덕션**: 동일 SQL → 프로덕션 DB 적용 → 프로덕션 배포 (별도 PR `main → production`).

### 5.3 롤백 SQL

```sql
-- Rollback: VOIDED row 를 COMPLETED 로 되돌린 후 enum 축소
UPDATE car_trip_logs SET ctl_status='COMPLETED' WHERE ctl_status='VOIDED';

ALTER TABLE car_trip_logs
  DROP COLUMN ctl_voided_at,
  DROP COLUMN ctl_voided_by,
  DROP COLUMN ctl_voided_by_name,
  DROP COLUMN ctl_voided_reason,
  MODIFY COLUMN ctl_status ENUM('IN_PROGRESS','COMPLETED','VERIFIED')
    NOT NULL DEFAULT 'IN_PROGRESS';
```

### 5.4 검증 쿼리

```sql
-- 적용 후 확인
DESCRIBE car_trip_logs;
SHOW CREATE TABLE car_trip_logs;

-- 신규 컬럼이 모두 NULL 인지 확인
SELECT COUNT(*) FROM car_trip_logs WHERE ctl_voided_at IS NOT NULL;  -- 0 이어야 함
```
