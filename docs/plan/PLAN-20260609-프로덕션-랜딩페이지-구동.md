## 1. 시스템 개발 현황 분석
- 스테이징은 `docker-compose.platform.yml`로 `bff-platform`+`web-platform`+`mysql-apps` 구동 중(검증 완료).
- 프로덕션은 동일 compose를 재사용 가능. 배포 스크립트 `deploy-staging.sh`는 `build`/`restart`/`verify` 서브커맨드가 환경 무관(네트워크 자동 생성, `--env-file .env` 빌드).
- 제약: prod엔 node 없음(빌드는 Docker 내부), `amb-apps-network` 미생성, 리포 미체크아웃, nginx 정적 conf만 존재.

---

## 2. 단계별 구현 계획

### Phase 0 — 리포 배포 자산 (로컬, 커밋 대상)
- **Step 0.1** `platform/scripts/deploy-production.sh` 신규작성
  - `deploy-staging.sh` 기반, 차이: `git pull origin production`, 대상 앱 기본 `platform`만.
  - └─ 사이드 임팩트: 신규 파일, 기존 staging 스크립트 무영향.

### Phase 1 — 프로덕션 박스 사전 준비
- **Step 1.1** 리포 clone: `git clone <repo> ~/ambAppStore` → `git checkout production` (없으면 main)
  - └─ 사이드 임팩트: 디스크 사용. 기존 서비스 무영향.
- **Step 1.2** `apps/platform/.env` 생성 (JWT_SECRET=스테이징 동일, MYSQL_ROOT_PASSWORD=prod 신규)
  - └─ 사이드 임팩트: git 미포함. 평문 비밀 — 권한 600.
- **Step 1.3** `docker network create amb-apps-network` (스크립트가 자동 생성하나 명시적 선확인)
  - └─ 사이드 임팩트: 신규 네트워크. 기존 `production_amb-network` 무관.

### Phase 2 — 컨테이너 빌드/기동
- **Step 2.1** `bash platform/scripts/deploy-production.sh build platform`
  - └─ 사이드 임팩트: 이미지 빌드(CPU/디스크). 기동 전이라 트래픽 무영향.
- **Step 2.2** `bash platform/scripts/deploy-production.sh restart platform` → mysql-apps 최초 기동 시 init/seed 자동 실행
  - └─ 사이드 임팩트: 포트 3100/5200/3308 점유(현재 비어있음). 신규 mysql 볼륨.
- **Step 2.3** 내부 검증: `curl localhost:3100/api/v1/health`, `curl localhost:5200/`, `curl localhost:3100/api/v1/apps`
  - └─ 사이드 임팩트: 없음(읽기).

### Phase 3 — nginx 컷오버 (라이브)
- **Step 3.1** 백업: `cp apps.amoeba.site.conf apps.amoeba.site.conf.bak-20260609`
- **Step 3.2** conf 교체: `/`→127.0.0.1:5200, `/api/`→127.0.0.1:3100, `/app-car-manager-v2/`→Render(유지), CSP/SSL 보존
- **Step 3.3** `nginx -t` 통과 확인 → `systemctl reload nginx` (restart 아님, 무중단)
  - └─ 사이드 임팩트: **apps.amoeba.site 라이브 라우팅 변경.** nginx -t 실패 시 reload 안 함 → 롤백.

### Phase 4 — 검증 + 보고
- **Step 4.1** 외부 검증: `curl https://apps.amoeba.site/` (200), `/api/v1/apps` (success), v2 health
- **Step 4.2** TR/RPT 작성.

## 4. 사이드 임팩트 분석
| 범위 | 위험도 | 설명 | 완화 |
|------|--------|------|------|
| nginx 컷오버 | **높음** | 라이브 도메인 라우팅 변경 | `.bak` 백업 + `nginx -t` 게이트 + reload(무중단) + 즉시 롤백 절차 |
| v2 Render 라우트 | 중 | 교체 중 누락 시 v2 회귀 | 신규 conf에 v2 블록 명시 보존 + 배포 후 v2 health 확인 |
| 신규 mysql 볼륨 | 낮음 | 빈 DB 시드 | init 스크립트 idempotent(`IF NOT EXISTS`, `ON DUPLICATE KEY`) |
| 포트 점유 | 낮음 | 3100/5200/3308 | 사전 확인 결과 전부 비어있음 |
| 비밀값 노출 | 중 | .env 평문 | 권한 600, git 미포함 |

## 5. DB 마이그레이션
- 수동 SQL 불필요. mysql-apps 신규 볼륨 최초 기동 시 `init-db.sql`(스키마)+`seed-apps.sql`(앱 5종) 자동 적용.
- 롤백: 컨테이너+볼륨 제거(`docker compose down -v`)로 초기화 가능.

---

## 6. 롤백 절차
1. nginx: `cp apps.amoeba.site.conf.bak-20260609 apps.amoeba.site.conf && nginx -t && systemctl reload nginx`
2. 컨테이너: `docker compose --env-file .env -f docker-compose.platform.yml down`
→ 1번만으로 즉시 404 이전 상태 복귀(외부 영향 종료).
