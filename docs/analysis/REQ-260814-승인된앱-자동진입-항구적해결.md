## 2. AS-IS 현황 분석

### 2.1 진입 계약 (AMA → 플랫폼)

AMA는 커스텀 앱 클릭 시 아래로 진입시킨다:

```
GET /apps/:slug?ama_token=<JWT>&locale=<xx>
```

`ent_id` / `ent_code` / `ent_name` 쿼리 파라미터는 **보내지 않는다**(구 iframe 계약). entity 정보는 JWT의 `entityId` 클레임에만 존재한다.

### 2.2 현재 코드 상태

| 파일 | 현황 | 문제 |
|---|---|---|
| `src/lib/ama-token.ts` | 모듈 로드 시점 `window.location.search` 1회 캡처 (`initialSearch`, L35) | 캡처 실패 시 복구 경로 없음 |
| `src/stores/entity-context.store.ts` | 순수 in-memory Zustand (L20-24), persist 미적용 | **F5 시 컨텍스트 전량 소실** |
| `src/App.tsx` `EntityContextInitializer` | 쿼리 파라미터 → 토큰 클레임 폴백 (L63-78) | 두 경로 모두 실패 시 조용히 `null` |
| `src/pages/AppDetailPage.tsx` L53 | `useEntitySubscriptions(!isAuthenticated ? effectiveEntId : null)` | `entId=null` → `enabled:false` → **API 호출 자체가 없음** |


DB 상태는 정상 — 데이터 문제 아님:

| ent_code | app_slug | sub_status | sub_approved_at |
|---|---|---|---|
| CARGO434 | app-car-manager-v2 | ACTIVE | 2026-08-12 04:26:06 |

즉 **토큰은 도착했고 승인도 되어 있으나, 프론트가 구독 조회를 하지 않아** 미신청으로 오판한다.

### 2.4 백엔드 확인 결과 (변경 불필요)

`subscription.controller.ts` L27-31:

```ts
/** Entity별 구독 현황 조회 (Public — AMA custom-apps 연동) */
@Get('entity/:entId')
async findByEntity(@Param('entId') entId: string) { … }
```

`@Auth()` 없음 = **공개 엔드포인트**. 프론트엔드에서 entId만 있으면 조회 가능하므로 이번 작업은 **프론트엔드 단독**으로 완결된다.

### 2.5 재발 시나리오 (FIX-260813 배포 후에도 남는 것)

| # | 시나리오 | 결과 |
|---|---|---|
| S1 | 앱 진입 후 F5 새로고침 | `initialSearch` 비어 있음 + store 초기화 → **동일 증상 재발** |
| S2 | `/apps/:slug` 북마크 진입 | 토큰 없음 → 미신청 오판 |
| S3 | 토큰 `exp` 경과 후 재진입 | `getInitialAmaClaims()` → `null` → 미신청 오판 |

## 3. TO-BE 요구사항

### 3.1 AS-IS → TO-BE 매핑

| 영역 | AS-IS | TO-BE |
|---|---|---|
| entity 컨텍스트 수명 | 탭 메모리 (F5 시 소실) | `sessionStorage` persist — 탭 세션 동안 유지 |
| 토큰 캡처 | 모듈 로드 1회, 실패 시 끝 | 1회 캡처 + persist 복원 폴백 |
| 구독 상태 | `ACTIVE` / `PENDING` / … / `null`(=미신청) | 위 + **`unknown`** 명시 구분 |
| ACTIVE 사용자 동선 | 카탈로그에서 "사용하기" 수동 클릭 | 조건 충족 시 **자동 진입** |
| unknown 시 UI | "신청하기" 버튼 | 안내 배너 + 재진입 유도 |

### 3.2 비즈니스 로직 — 자동 진입 조건 (R1)

아래 **전부** 충족 시에만 자동 리다이렉트한다:

1. `currentStatus === 'ACTIVE'`
2. `appScopedTokenFor(slug)` 가 non-null (해당 앱용 유효 토큰 보유)
3. 세션 내 해당 slug로 아직 자동 진입한 적 없음 (`sessionStorage` 가드)

3번이 없으면 앱이 다시 카탈로그로 돌려보낼 때 **무한 리다이렉트 루프**가 발생한다. 반드시 1회로 제한한다.

조건 미충족 시에는 기존 수동 버튼 동선을 100% 유지한다 (회귀 방지).

### 3.3 UI 설계 — unknown 상태 (R3, R4)

```
┌────────────────────────────────────────────┐
│ ⚠  세션 정보를 확인할 수 없습니다              │
│    AMA에서 앱을 다시 열어주세요.               │
│    (구독 여부를 확인하지 못했습니다)            │
└────────────────────────────────────────────┘
        [ AMA에서 다시 열기 ]  ← 안내 전용
```

기존 "신청하기" 버튼은 **진짜 미신청일 때만** 노출한다.

```
   │

   │                  │

   │
   ▼

   │
   ├─ ACTIVE + 앱 토큰 보유 + 미진입 → 자동 진입 ★R1
   ├─ ACTIVE (토큰 없음)            → "사용하기" 버튼 (기존)

   └─ 없음                          → "신청하기" (기존)
```

## 6. 기술 제약사항

| 구분 | 내용 |
|---|---|
| 호환성 | 구 iframe 파라미터 경로(`from=iframe&ent_id=…`)는 우선순위 유지 — 기존 동작 무회귀 |
| 저장소 | `localStorage` 아닌 **`sessionStorage`** 사용 — 공용 PC에서 탭 종료 시 org 컨텍스트 잔존 방지 |
| 보안 | 토큰은 서명 검증 없이 디코드만 (카탈로그에 `JWT_SECRET` 없음). 용도가 ①공개 읽기 전용 조회 대상 선택 ②UI 분기뿐이므로 허용. 실제 검증은 v2 미들웨어가 수행 |
| 보안 | **원본 JWT는 저장하지 않는다** — `entId` 등 식별자만 persist |
| 루프 방지 | 자동 진입은 세션당 slug별 1회로 제한 (§3.2 조건 3) |
| 배포 | `VITE_*` 불변 — 프론트 번들만 재빌드. `mysql-apps` 포함 compose이므로 `down` 금지, `--no-deps --force-recreate web-platform` 사용 |
