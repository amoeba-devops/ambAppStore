## 1. 요구사항
`https://stg-apps.amoeba.site/`는 정상이나 `https://apps.amoeba.site/`가 404. 프로덕션 랜딩페이지를 동작시킨다.

## 2. 원인
프로덕션 nginx `apps.amoeba.site.conf`가 존재하지 않는 정적 루트(`/var/www/apps_amoeba`)를 `try_files ... =404`로 서빙. app-store 컨테이너(web/bff/mysql)가 prod에 전무 — 플랫폼이 한 번도 배포된 적 없음(zero-touch 전략으로 car-v2만 계획).

## 3. 조치 (풀스택 컨테이너 prod 배포 — 사용자 승인)
1. **리포 clone**: prod 박스 `~/ambAppStore` (main, 8a714f8).
2. **배포 스크립트**: `platform/scripts/deploy-production.sh` 신규(스테이징 스크립트 prod 변형, 기본 대상 platform).
3. **`.env` 생성**: perms 600. `JWT_SECRET`은 동일 박스 `amb-api-production` 컨테이너에서 서버 내부 복사(메모리 G1: prod AMA JWT==staging, fp:96dba2f3…). `MYSQL_ROOT_PASSWORD`/`DB_PASSWORD` 신규 생성.
4. **컨테이너 빌드/기동**: `bff-platform`(3100)+`web-platform`(5200)+`mysql-apps`(3308). mysql 신규 볼륨 최초 기동 시 `init-db.sql`+`seed-apps.sql` 자동 적용(카탈로그 4건).
5. **nginx 컷오버**: `apps.amoeba.site.conf` 백업(`.bak-20260609`) 후 교체 — `/`→127.0.0.1:5200, `/api/`→127.0.0.1:3100. `nginx -t` 통과 → `systemctl reload`(무중단). v2 블록은 주석 보존(Render 안정화 후 활성화).

## 6. 잔여/후속 과제
1. **car-v2 prod 연결(별도)**: Render prod(`car-manager-production.onrender.com`) 현재 무응답(HTTP 000). 안정화 후 nginx의 `/app-car-manager-v2/` 블록 주석 해제. PR #66 진행 건.
2. **car-v2 카탈로그 노출**: prod 시드 4건(main 기준) → v2 시드 반영 시 5건. `feature/car-v2-prod-deploy` 머지 후 `seed-apps.sql` 재적용 필요(또는 수동 INSERT).
3. **나머지 앱 컨테이너**(car-manager/stock/sales): 카탈로그엔 노출되나 prod 미배포 → 클릭 시 라우트 미연결. 필요 시 후속 배포.
4. **리포 반영**: `deploy-production.sh`는 prod에 scp로 배치됨(미커밋). 정식 반영하려면 커밋/푸시 필요(사용자 지시 대기).
5. **mysql-apps 포트(3308)**: 현재 호스트 노출. 보안상 `127.0.0.1` 바인딩 권장(후속).
