## TC-01: DB 마이그레이션 적용

**목적**: `car_trip_logs` 테이블 enum 확장 및 audit 컬럼 추가가 정상 적용되었는지.

| Step | 동작 | 기대결과 |
|------|------|---------|
| 1 | `DESCRIBE car_trip_logs;` | `ctl_status` 가 `enum('IN_PROGRESS','COMPLETED','VERIFIED','VOIDED')` 로 보임 |
| 2 | `DESCRIBE car_trip_logs;` | `ctl_voided_at`/`ctl_voided_by`/`ctl_voided_by_name`/`ctl_voided_reason` 컬럼 존재, 모두 NULL 허용 |
| 3 | `SELECT COUNT(*) FROM car_trip_logs WHERE ctl_voided_at IS NOT NULL;` | `0` |
| 4 | `SELECT ctl_status, COUNT(*) FROM car_trip_logs GROUP BY ctl_status;` | 기존 상태 유지 (IN_PROGRESS/COMPLETED/VERIFIED). VOIDED 는 없음. |

**합격 기준**: 모든 step 의 기대결과 충족.

## TC-03: IN_PROGRESS 상태 trip log void (정상 케이스)

**목적**: 가장 일반적인 무효처리 시나리오 검증.

| Step | 동작 | 기대결과 |
|------|------|---------|
| 1 | 새 trip log 수동 등록 (POST /trip-logs) | 상태=IN_PROGRESS, 200 OK |
| 2 | 상세 페이지 진입 | `[Void]` 버튼 표시됨 (Edit, Back 옆) |
| 3 | `[Void]` 클릭 | 모달 표시: 제목·경고문·textarea·[확인][취소] |
| 4 | textarea 비워둔 채로 `[확인]` 클릭 시도 | 버튼 disabled (또는 validation 에러 메시지) |
| 5 | "출발 마일리지 잘못 입력" 입력 후 `[확인]` 클릭 | API: `PATCH /trip-logs/:id/void { reason: "..." }` 호출 → 200 OK |
| 6 | 페이지 자동 refetch | 상태 배지: `VOIDED` (회색), 사유·처리자·시간 표시 |
| 7 | `[Edit]` 버튼 | 표시되지 않음 |
| 8 | `[Void]` 버튼 | 표시되지 않음 |
| 9 | DB 직접 확인: `SELECT ctl_status, ctl_voided_at, ctl_voided_by, ctl_voided_by_name, ctl_voided_reason FROM car_trip_logs WHERE ctl_id = ?` | status=VOIDED, voided_at=현재시각, voided_by=user.sub, voided_by_name=사용자명, voided_reason="출발 마일리지 잘못 입력" |

## TC-04: COMPLETED 상태 trip log void

**목적**: 제출 완료 후에도 검증 전이면 void 가능.

| Step | 동작 | 기대결과 |
|------|------|---------|
| 1 | trip log 생성 → submit 호출 (status: COMPLETED) | 200 OK |
| 2 | 상세 페이지 | `[Void]` 버튼 표시됨 |
| 3 | 사유 입력 후 void 실행 | 200 OK, status=VOIDED |
| 4 | DB: `ctl_voided_at` 기록 확인 | NOT NULL |

## TC-05: VERIFIED 상태 void 차단

**목적**: 검증 완료된 trip log 는 void 불가.

| Step | 동작 | 기대결과 |
|------|------|---------|
| 1 | trip log → COMPLETED → VERIFIED 까지 진행 | 200 OK |
| 2 | 상세 페이지 | `[Void]` 버튼 표시되지 않음 |
| 3 | 직접 API 호출 (Postman/curl): `PATCH /trip-logs/:id/void` | 400 Bad Request, errorCode: `CAR-E6005` |
| 4 | DB | 상태 변경 없음, VERIFIED 유지 |

## TC-06: VOIDED 상태 재void 차단 (멱등성)

| Step | 동작 | 기대결과 |

| 2 | API 직접 재호출: `PATCH /trip-logs/:id/void { reason: "재시도" }` | 400 Bad Request, errorCode: `CAR-E6006` |
| 3 | DB | `ctl_voided_at` 변경되지 않음 (최초 void 시각 유지) |

## TC-07: proxy dispatch 동기화

**목적**: 수동 등록된 trip log void 시, 함께 생성된 proxy dispatch 도 CANCELLED 됨.

| Step | 동작 | 기대결과 |
|------|------|---------|
| 1 | `POST /trip-logs` 로 수동 등록 (proxy dispatch 자동 생성) | trip_log + dispatch_request 둘 다 생성됨, `cdr_is_proxy=1`, `cdr_status=COMPLETED` |
| 2 | trip log void | 200 OK |
| 3 | DB: `SELECT cdr_status FROM dispatch_requests WHERE cdr_id = ?` | `CANCELLED` |
| 4 | non-proxy dispatch (cdrIsProxy=0) 가 있는 trip log void | dispatch_request 상태 변경 **없음** (보존) |

## TC-08: 월간 통계에서 VOIDED 제외

**목적**: `TripLogListPage` 통계 카드가 VOIDED 를 제외하는지.

| Step | 동작 | 기대결과 |
|------|------|---------|
| 1 | 같은 달에 trip log 3개 생성 (각각 100km, 200km, 150km), 연료비 100k/200k/150k | 3건 모두 IN_PROGRESS |
| 2 | 목록 페이지 통계 확인 | 총 운행수: 3, 총 거리: 450km, 총 연료비: 450,000 |
| 3 | 3번째 trip log void 처리 | 200 OK |
| 4 | 목록 페이지 refetch | 총 운행수: 2, 총 거리: 300km, 총 연료비: 300,000 |
| 5 | 목록 행 — VOIDED row | 회색 + 취소선, 사유 툴팁 표시 |
