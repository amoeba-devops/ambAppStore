# FIX-261120 JWT 기본 비밀값 제거

> **작성일**: 2026-11-20
> **범위**: `JWT_SECRET` 미설정 시 쓰이던 기본 비밀값 제거. 그 밖의 인증 개선은 별도 비공개 문서로 관리한다.

## 1. 증상
`JWT_SECRET` 환경변수가 없으면 앱스토어 백엔드 4개가 코드에 박힌 기본값(`'default-secret'` 등)으로 토큰을 서명·검증했다. 운영 환경에서 env 가 한 번이라도 빠지면 누구나 토큰을 만들 수 있는 구조였다.

- 위치: `apps/{platform,app-car-manager,app-sales-report,app-stock-management}/backend/src/auth/{auth.module,jwt.strategy}.ts`

## 2. 원인
개발 편의용 기본값이 운영 코드에 남아 있었다.

## 3. 수정
- 앱 4개 백엔드에 `src/auth/jwt-secret.ts` 의 `getJwtSecret()` 추가 — 값이 없거나 16자 미만이면 **부팅 실패**.
- `JwtModule.register` → `registerAsync`(의존성 주입 시점에 읽음, `.env` 를 `ConfigModule` 로 읽는 로컬 환경 호환), `JwtStrategy` 는 생성자에서 `getJwtSecret()`.
- 배포 전 확인(2026-11-20): 스테이징·프로덕션 대상 컨테이너 모두 `JWT_SECRET` 이 16자 이상으로 설정됨 → 배포해도 부팅 영향 없음.

## 4. 변경 파일
| 파일 | 내용 |
|------|------|
| `apps/*/backend/src/auth/jwt-secret.ts` (4개, 신규) | `getJwtSecret()` |
| `apps/*/backend/src/auth/auth.module.ts` (4개) | `registerAsync` + `getJwtSecret()` |
| `apps/*/backend/src/auth/jwt.strategy.ts` (4개) | `getJwtSecret()` |

## 5. 시험
- 4개 백엔드 `tsc --noEmit` 통과.
- 배포 후: 각 컨테이너 부팅 로그 정상·`/api/health` 200, 플랫폼 로그인·앱 실행 정상.

## 6. 재발 방지
- 비밀값은 기본값 없이 `getJwtSecret()` 같은 필수 읽기 함수로만 접근.
- 새 앱 템플릿에도 같은 규칙을 넣는다.
