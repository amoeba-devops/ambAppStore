# FIX-260814 — 승인된 org 사용자의 v2 앱 자동 진입 항구적 해결

- **날짜**: 2026-08-14
- **앱**: platform (frontend) → 영향: `app-car-manager-v2`, `app-sales-report-v2`
- **환경**: `apps.amoeba.site`
- **선행**: [FIX-260812](FIX-260812-platform-app-launch-missing-ama-token.md), [FIX-260813](FIX-260813-platform-catalog-ama-token-entity-context.md)
- **문서**: [REQ-260814](../analysis/REQ-260814-승인된앱-자동진입-항구적해결.md) · [PLN-260814](../plan/PLN-260814-승인된앱-자동진입-항구적해결.md) · [TC-260814](../test/TC-260814-승인된앱-자동진입-항구적해결.md)

## 1. 증상

AMA에서 org(CargoRush/`CARGO434`)에 대해 차량관리 v2를 **승인(ACTIVE)했는데도**, 사용자가 AMA 커스텀 앱 메뉴로 앱을 열면 `apps.amoeba.site` 카탈로그에 머물고 **"신청하기"** 버튼이 보인다. 이미 승인된 사용자에게 재신청을 요구하는 상태.

FIX-260813이 같은 증상을 다뤘으나 재발했다. 이번 조사에서 **두 가지 서로 다른 원인**이 확인됐다.

## 2. 원인 분석

### 2.1 원인 A — FIX-260813이 배포되지 않았음

수정 커밋은 존재했으나 push/merge/배포가 되지 않아 프로덕션은 수정 전 번들 그대로였다.

```
$ sudo docker exec web-platform ls -la /usr/share/nginx/html/assets/
index-VTaU2tbh.js   Aug 12 09:29        ← FIX-260813(8/13) 이전 번들

$ grep -c "subscriptions/entity" apps.amoeba.site-access.log
0                                        ← 구독 조회 요청 0건

$ grep "GET /apps/app-car-manager-v2?ama_token" … | tail -1
14/Aug/2026:03:39:28 +0000  200          ← 토큰은 정상 도착
```

DB는 정상 — 데이터·승인 문제가 아니었다:

| ent_code | app_slug | sub_status | sub_approved_at |
|---|---|---|---|
| CARGO434 | app-car-manager-v2 | ACTIVE | 2026-08-12 04:26:06 |

### 2.2 원인 B — 배포해도 남는 구조적 재발 경로

FIX-260813의 폴백은 `ama-token.ts`가 **모듈 로드 시점에 1회 캡처한 URL**에만 의존했고, entity 컨텍스트는 **메모리 전용 Zustand 스토어**에 있었다. 따라서 아래 경로에서 동일 증상이 그대로 재현된다:

| # | 경로 | 결과 |
|---|---|---|
| S1 | 새로고침(F5) | `initialSearch` 빈 값 + 스토어 초기화 → 컨텍스트 소실 |
| S2 | 북마크/직접 진입 | 토큰 없음 |
| S3 | 토큰 `exp` 경과 | `getInitialAmaClaims()` → `null` |

세 경우 모두 `useEntitySubscriptions(null)` → `enabled:false` → **구독 조회 자체가 없음** → `currentStatus=null` → 최종 else 분기 → "신청하기".

핵심 결함은 **"미신청"과 "알 수 없음"을 같은 `null`로 뭉갠 것**이다. 조회가 통째로 사라지는데 예외도 로그도 없어 조용히 실패한다.

## 3. 수정 내용

### 3.1 `stores/entity-context.store.ts` — 컨텍스트 영속화 (S1/S2 해소)

zustand `persist` 미들웨어 적용. `sessionStorage`에 `entity`만 저장한다.

- **`localStorage` 아닌 `sessionStorage`**: 공용 PC에서 탭 종료 후 이전 사용자의 org 컨텍스트가 남지 않도록. 탭 세션 동안만 유지되어도 F5 재발 경로를 막기에 충분하다.
- **원본 JWT는 저장하지 않는다** — 식별자만. 토큰은 매 진입마다 URL로 새로 오고 만료 판정도 그때 이뤄져야 한다.

### 3.2 `App.tsx` — 복원값 보존

토큰 폴백 성공 시 `return`으로 분리해, 복원된 컨텍스트를 덮어쓰지 않도록 했다. 우선순위는 **쿼리 파라미터 > 토큰 클레임 > sessionStorage 복원**으로, 명시적 진입이 항상 이긴다.

### 3.3 `AppDetailPage.tsx` — UNKNOWN 분리 (S3 가시화)

```ts
const contextResolved = isAuthenticated || !!effectiveEntId;
const isContextUnknown = !contextResolved;
```

로딩 상태를 함께 보지 않는 이유: `contextResolved`가 false면 구독 쿼리는 애초에 `enabled:false`라 로딩이 영원히 끝나지 않는다. 즉 "아직 모른다"가 아니라 **확정된 상태**다. (초안에서 `isLoading`을 AND로 묶었다가, React Query v5에서 비활성 쿼리의 pending 처리에 의존하게 되어 배너가 영영 안 뜰 수 있어 제거했다.)

UNKNOWN일 때 신청 버튼 대신 안내 배너 + 비활성 버튼을 노출한다. **컨텍스트가 있는데 구독이 없으면 그것은 진짜 미신청**이므로 기존 "신청하기" 동선을 100% 유지한다 — 이 구분이 회귀 방지의 핵심이다.

### 3.4 `AppDetailPage.tsx` — 자동 진입 (요구사항 R1)

조건 3종을 모두 충족할 때만 리다이렉트한다:

1. `currentStatus === 'ACTIVE'`
2. `isEntityUser`
3. `appScopedTokenFor(slug)` non-null — 토큰이 없으면 앱이 어차피 `/login`으로 튕기므로 자동 진입이 무의미

**무한 루프 방지가 가장 큰 위험이었다.** 앱이 어떤 이유로든 카탈로그로 되돌려보내면 자동 진입이 무한 반복된다. `sessionStorage['plt-auto-entered:{slug}']` 가드로 세션당 slug 1회로 제한했다. 새 탭/새 세션에서는 정상 재발동한다(영구 차단 아님).

`sessionStorage` 접근 불가 환경(Safari 프라이빗 모드 등)에서는 `hasAutoEntered()`가 `true`를 돌려주어 **자동 진입을 포기**한다 — 가드를 세울 수 없으면 루프 위험이 크므로, 수동 버튼 동선으로 안전하게 후퇴한다.

전환 중에는 `isRedirectingRef`로 안내 문구를 표시한다. 가드는 진입 '직전'에 기록되므로 그것만으로 판단하면 기록 직후 리렌더에서 카탈로그(=신청하기 버튼)가 잠깐 번쩍인다.

### 3.5 i18n 키 4종 (ko/en/vi)

`detail.contextUnknown`, `detail.contextUnknownDesc`, `detail.reopenFromAma`, `detail.enteringApp`

## 6. 배포

FIX-260813 미배포분과 같은 파일을 건드리므로 **함께 배포**한다.

```bash
sudo docker stop tei-hscode
sudo bash platform/scripts/deploy-staging.sh build platform
sudo docker compose --env-file .env -f docker-compose.platform.yml \
     up -d --no-deps --force-recreate web-platform
sudo docker start tei-hscode
```

`deploy-staging.sh restart platform` **금지** — 이 compose에 `mysql-apps`가 포함되어 `down`이 MySQL까지 내리고 같은 DB를 쓰는 앱 4개가 함께 죽는다.

## 7. 남은 한계 (범위 밖)

- **`SubscriptionCard`(내 구독 목록) 경로**: URL에 앱 스코프 토큰이 없어 자동 로그인이 성립하지 않는다. **AMA의 앱 토큰 발급 API가 없으면 플랫폼 단독으로 해결 불가** (FIX-260812 §3.2). 이번 수정은 조용한 실패 대신 UNKNOWN 안내를 띄우는 것까지만 한다.
- **중복 구독 레코드**: CARGO434에 `app-car-manager-v2` ACTIVE 2건. `findByEntity()`가 최신 1건만 쓰므로 동작은 정상이나 정리 필요.
- **`entCode`/`entName` 클레임 부재**: AMA가 토큰에 넣어주면 신청 모달 자동 입력과 헤더 뱃지가 완전해진다.

## 8. 재발 방지 패턴

1. **"수정했다"와 "배포됐다"는 다르다.** 이번 재발의 절반은 순수하게 미배포였다. 번들 타임스탬프 + 특징 문자열 `grep` 한 번으로 확인된다.
2. **조용한 실패를 상태로 승격시킬 것.** `null`이 "없음"과 "모름"을 겸하면 UI가 반드시 오판한다. React Query `enabled:false`는 네트워크 탭에도 콘솔에도 흔적을 남기지 않는다.
3. **자동 리다이렉트에는 반드시 세션 가드를 함께 넣을 것.** 상대편이 되돌려보내는 순간 무한 루프가 된다.
4. **URL에서만 오는 상태는 반드시 영속화할 것.** 새로고침 한 번에 사라지는 컨텍스트는 언젠가 반드시 사라진다.
