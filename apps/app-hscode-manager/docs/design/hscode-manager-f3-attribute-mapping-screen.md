# 기능3 — 속성기반 HS코드 매핑 화면구성안 (Attribute-based HS Mapping Screen Layout)

## 1. 개념 (Concept)

기능3은 **두 개의 책임**을 한 화면군에서 다룬다. 둘은 "참조 데이터(근거) → 속성 조회(질의)"의 선후 관계로 연결된다.

| 영역 | 책임 | 사용자 | 근거 FR/FN |
|------|------|--------|-----------|
| ① 속성기반 조회 | 제품 속성(품명·재질·용도·원산지·단위 등)을 입력 → HS코드 후보 추천 | 일반 사용자 | FR-030, FR-033 / FN-030, FN-001 |
| ② 면장리스트 참조 데이터 관리 | 면장리스트와 **동일 형식**의 엑셀을 업로드하여 매칭 근거 테이블(`hsm_hs_references`)을 적재·관리 | 데이터 담당자 | FR-040, FR-044 / FN-040, FN-041 |

**핵심 설계 원칙**
- ②에서 적재한 면장리스트 데이터가 ①의 의미검색(임베딩) 근거가 된다. 즉 ②는 ①의 정확도를 좌우하는 *데이터 공급* 화면이다.
- 사용자가 올리는 엑셀은 **면장리스트 폴더의 원본 양식 그대로**(`BaoCaoHangChiTiet` / `BaoCaoToKhai` / `VMSG`)다. 별도 변환 없이 업로드하며, 시스템이 어댑터로 정규화한다(FN-040).
- 일괄 조회용 업로드(FR-031, 고정 템플릿)와 참조 데이터 적재용 업로드(FR-040, 면장리스트 원본)는 **목적이 다른 두 업로드**다. 본 화면구성안은 양쪽을 모두 포함한다.

> 관리 범위(본 안 확정): **업로드 + 배치 목록 + 검증 리포트**까지. 참조 데이터의 행 단위 직접 수정/삭제(CRUD)는 본 버전 범위에서 제외한다.

## 3. 화면 흐름 (Flow)

```
                    ┌─────────────────────────────────────────────┐
                    │  SCR-003  속성/엑셀 메인 (탭 컨테이너)        │
                    └─────────────────────────────────────────────┘
        ┌───────────────────────┬───────────────────────┬───────────────────────┐
        ▼                       ▼                       ▼
  [T1] 속성 폼 조회       [T2] 엑셀 일괄 조회      [T3] 면장리스트 데이터 관리
        │                       │                       │
   속성 입력→Classify      템플릿 .xlsx 업로드      면장리스트 원본 업로드
        │                       │                       │  (FN-040 어댑터 정규화)
        ▼                       ▼                       ▼
   후보 리스트              검증→배치 분류           검증 리포트(SCR-003-M1)
        │                       │                       │
        ▼                       ▼                       ▼
   카드 클릭→SCR-004       결과 테이블/다운로드      배치 목록에 누적 → ①·② 조회 근거로 반영
```

핵심: **T3로 적재된 데이터가 T1·T2의 매칭 정확도에 즉시 기여**한다. 적재 → 임베딩(FN-041) → 검색 근거(FN-001)로 순환한다.

### Layout
```

|  재질/조성           [_____________________________]                 |
|  용도/가공상태       [_____________________________]                 |

|                                         [ 초기화 ]  [ Classify ▶ ]   |
+---------------------------------------------------------------------+
|  후보 결과 (신뢰도 내림차순)                                          |
|  ┌───────────────────────────────────────────────────────────────┐ |
|  │ 8452.21.00  자동 재봉기, 차량 에어백용  · VN · SETS  · 92% [상세]│ |
|  │ 출처: SARAH / HANS VN_2025.4.28 · line 1                        │ |
|  ├───────────────────────────────────────────────────────────────┤ |
|  │ 8452.29.00  기타 산업용 재봉기            · VN · SETS  · 71% [상세]│ |
|  └───────────────────────────────────────────────────────────────┘ |
+---------------------------------------------------------------------+
```

### Components
| 요소 | 유형 | 설명 | 동작 |
|------|------|------|------|
| 속성 입력 폼 | Form | 품명(필수)·재질·용도·원산지·단위·수량 | 검증 후 매칭 엔진 호출(FN-030 → FN-001) |
| HS 자릿수 토글 | Radio | HS6 / 국가 확장(8~10자리) | 국가 선택 시 FN-015 확장(FR-043) |
| Classify 버튼 | Button | 조회 실행 | `POST /api/v1/attribute/classify` |
| 후보 카드 | Card | HS·매칭 설명·원산지·단위·신뢰도% | 클릭 → SCR-004(FR-004) |
| 출처 표기 | Link | 근거 면장 행(회사/파일/라인) | FR-006 |
| 신뢰도 배지 | Badge | % + 밴드 색상(고/중/저) | 저신뢰 시 경고색 |

### States
- **로딩**: 후보 영역 스켈레톤, 응답 P95 < 2s(NFR-001).
- **빈 결과**: "확신 가능한 매칭 없음 → Q&A 검색 또는 데이터 관리에서 근거 보강" CTA.
- **검증 실패**: 품명 미입력/2자 미만 시 인라인 오류, API 미호출(FR-001 규칙 준용).

## 7. SCR-003-T3 — 면장리스트 데이터 관리 (참조 데이터 적재)

면장리스트 폴더의 파일을 **원본 양식 그대로** 올려 매칭 근거를 누적한다. 관리 범위는 **업로드 · 배치 목록 · 검증 리포트**.

### Layout
```
+----------------------- 면장리스트 데이터 관리 ----------------------+
|  지원 양식: BaoCaoHangChiTiet · BaoCaoToKhai · VMSG (자동 판별)      |
|  ┌──────────────────────────────────────────────────────────────┐ |
|  │   면장리스트 .xls/.xlsx 를 끌어다 놓거나  [ 파일 선택(다중) ] │ |
|  │   업로드 즉시 양식 자동 감지 → 어댑터 정규화(FN-040)          │ |
|  └──────────────────────────────────────────────────────────────┘ |
|  [ 중복 제거 적용 ✔ ]  (HS+정규화 품명+원산지+단위 기준, FR-044)     |
+--------------------------------------------------------------------+
|  가져오기 배치 목록 (hsm_import_batches)                            |
|  파일명                         | 양식        | 전체 | 적재 | 실패 | 상태   | |
|  HANS VN_2025.4.28.xls          | HangChiTiet | 183  | 180  | 3 ⚠  | 완료 [리포트]|
|  OKIA nhap-khau-2024.xls        | ToKhai      | 412  | 412  | 0    | 완료 [리포트]|
|  VMSG 수입건 리스트_4.25.25.xls  | VMSG        | 96   | -    | -    | 처리중 ▣   | |
+--------------------------------------------------------------------+
```

### Components
| 요소 | 유형 | 설명 | 동작 |
|------|------|------|------|
| 다중 업로드 드롭존 | Upload | 면장리스트 원본(다중 선택) | 양식 자동 판별 → 어댑터 디스패치(FN-040) |
| 양식 배지 | Badge | HangChiTiet/ToKhai/VMSG | 헤더 시그니처로 자동 인식 |
| 중복 제거 토글 | Toggle | 적재 시 근접 중복 제거 | 키=HS+정규화품명+원산지+단위(FR-044/FN-041) |
| 배치 목록 | Table | 파일별 전체/적재/실패/상태 | `hsm_import_batches` 조회 |
| 리포트 링크 | Link | 실패행 상세 | SCR-003-M1 열기 |
| 처리중 표시 | Status | 임베딩 생성까지 진행(FN-041) | 완료 시 ①·② 조회 근거 반영 |

### 일괄 초기 적재 (면장리스트 폴더 전체)
- 최초 1회, 면장리스트 폴더의 **27개 파일 전체**를 다중 업로드로 적재한다(FR-040). 양식 혼재 가능 → 어댑터가 파일별로 분기 처리.
- 적재 후 중복 제거·임베딩이 끝나야 검색 근거로 활성화된다.

## 9. 면장리스트 컬럼 → 정규화 스키마 매핑

업로드된 원본 54컬럼 중 매칭에 사용하는 필드만 `hsm_hs_references`로 정규화한다(FN-040). 헤더 행은 파일 상단 메타(약 9행) 다음에 위치하며 어댑터가 헤더 시그니처로 데이터 시작 행을 탐지한다.

| 면장리스트 컬럼(원본) | 의미 | 정규화 필드 | 용도 |
|----------------------|------|-------------|------|
| `Mã HS` (col21) | HS코드(8자리) | `hs_full` / 파생 `hs6` | 결과·검색 키 |
| `Tên hàng` (col22) | 품명+상세(전압·출력·치수·모델·제조사·신/구) | `description` | 임베딩 근거(FN-041) |
| `Xuất xứ` (col23) | 원산지 | `origin` | 속성 필터·중복키 |
| `Đơn vị tính` (col27) | 단위 | `unit` | 속성 필터·중복키 |
| `Mã loại hình` (col3) | 수출입 구분(A12 등) | `trade_type` | 통계/필터 |
| `Thuế suất XNK` (col33) | 관세율 | `duty_rate` | 관세/부가세 연계(FR-042) |
| `Thuế suất VA` (col44) | 부가세율 | `vat_rate` | 관세/부가세 연계(FR-042) |
| `Tên doanh nghiệp` (col48) | 신고 기업명 | `source_company` | 출처 표기(FR-006) |
| (파일명/행번호) | — | `source_file` / `source_line` | 출처 추적(FR-006) |

- **중복 제거 키**(FR-044): `hs_full` + 정규화(`description`) + `origin` + `unit`.
- **HS6 파생**: `hs_full` 앞 6자리 → `hs6`(국가 무관 글로벌 베이스, FR-043).
- 양식별 차이(HangChiTiet/ToKhai/VMSG)는 어댑터 매핑 테이블로 흡수하여 동일 스키마로 수렴.

## 10. 반응형 / 프레임워크

- **데스크톱**: T1은 폼·결과 2단, T2·T3는 업로드 상단 + 테이블 하단.
- **모바일**: 단일 컬럼, 폼/업로드 먼저·결과 아래로 적층.
- **스택**: React + React Query / Zustand · 대용량 업로드는 Redis(BullMQ) 비동기 · 라우팅 React Router(`?tab=` 동기화).
- **권한**: T3는 역할 제한(NFR-007), 감사 로깅(FR-020 계열).
