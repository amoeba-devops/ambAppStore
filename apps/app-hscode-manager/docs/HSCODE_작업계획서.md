# HS Code Manager — 작업계획서

> 범위: 「HSCODE_설계문서」「HSCODE_이벤트시나리오 Rev.2」「HSCODE_요구사항명세서」를 기반으로, 시스템을 어떤 순서로 어떤 단위로 만들지를 정의한다. 화면 구성도, 작업 분해(WBS), 일정 골격, 산출물, 리스크를 한 문서에 담는다.
> 핵심 변경: 수입국·수출국이 추가 가능하다는 요건을 반영한다. 기존 SRS의 *CN-01 (수입국=베트남 기본)* 가정을 폐기하고, 외부 권위 데이터·세율 정책·정규화 규칙·UI 표시까지 *국가 쌍(수입국, 수출국)에 매개되는 어댑터 구조*로 재설계한다.
> 작성 기조: 개념과 설계 수준의 작업계획. 실제 스프린트 단위·담당자·툴 선택은 별도 운영 문서로 분리한다.

---

## 1. 멀티 국가 확장 반영 사항

원래 시나리오는 베트남을 단일 수입국으로 가정해 BIEU THUE XNK 2026을 1차 권위로 박아 두었다. 수입국·수출국이 추가될 수 있다는 요건이 들어오면 *권위 데이터의 위치, 협정세율 산출, 정규화 규칙, 사용자 UI, 정책 임계값* 다섯 개 축이 모두 국가 매개로 일반화되어야 한다. 본 절은 그 변경 지점을 모은다.

**변경 1. 국가 마스터의 일급화.** `ImportCountry`와 `ExportCountry`를 별도 마스터 테이블로 둔다. 두 테이블은 같은 ISO 3166-1 코드 체계를 쓰지만 *지원 상태(active/beta/not_supported)와 권위 데이터 어댑터 식별자*가 다르므로 분리한다. Inquiry는 두 마스터 모두를 FK로 가진다(`exporter_country_code`, `importer_country_code`).

**변경 2. 외부 데이터 어댑터의 플러그인화.** 「설계문서」§1.2 M2에서 베트남 BIEU THUE만 가리키던 외부 조회를 *수입국별 어댑터 인터페이스*로 추상화한다. 어댑터는 `lookupByAttributes(attributes, importCountry) → CandidateList` 라는 동일 시그니처를 갖되, 내부 구현은 수입국마다 다르다. 신규 수입국 추가는 어댑터 1개 구현 + `ImportCountry` 마스터 등록 두 단계로 끝나야 한다.

**변경 3. FTA·협정세율 매트릭스.** 세율은 *(수입국, 수출국, HS코드)* 3항 키로 조회된다. 기존 SRS의 IR-03을 일반화해 *FTA 매트릭스 마스터*를 둔다. 한-베·AKFTA·ATIGA·RCEP는 그 매트릭스의 행 데이터일 뿐이다.

**변경 4. 정규화 규칙의 국가 의존성.** 같은 "철강 합금"이라도 수입국에 따라 분류 기준 키워드가 다를 수 있다(예: 베트남 BIEU THUE의 합금 분류 구분과 EU CN code의 구분). 따라서 정규화 규칙은 *(카테고리, 수입국) 쌍*에 매개되도록 설정 가능해야 한다. 카테고리 단위 정규화는 기본값, 수입국별 오버레이는 옵션이다.

**변경 5. 정책 임계값의 국가 분리.** 보수적 세율 룰(§2.2)의 격차 임계, 에스컬레이션 트리거(§2.4)의 금액 임계는 *수입국별로 별도 설정* 가능해야 한다. 베트남의 50,000 USD 임계가 다른 수입국에서는 적절하지 않을 수 있다.

**변경 6. UI의 미지원 국가 처리.** 사용자가 신규 수입국·수출국을 선택할 때, 어댑터·세율·정규화 규칙이 모두 준비된 경우만 정상 진행한다. 그렇지 않으면 *지원 상태에 따른 명시적 경고*(beta) 또는 *추가 요청 폼*(not_supported)으로 유도한다.

이 여섯 가지 변경은 본 작업계획의 모든 Phase에 스며든다. 멀티 국가 확장을 별도 Phase로 두지 않는다 — 처음부터 어댑터 구조로 만든다.

## 2. 화면 구성도

### 2.1 전체 네비게이션 맵

상단 글로벌 내비는 다섯 묶음이다 — *대시보드 / 새 작업 / 누적 조회 / 검증 이벤트 / 관리*. 새 작업은 단계형 플로우(Step Flow)이며, 나머지는 화면 간 자유 이동이다.

```
┌─ HSCM 상단 내비 ────────────────────────────────────────────────┐
│  [대시보드]  [새 작업]  [누적 조회]  [검증 이벤트]  [관리]      │
└────────────────────────────────────────────────────────────────┘

  ├─ S01 대시보드
  │     ├─ 진행 중 Inquiry 카드 리스트
  │     ├─ 추징·정정률 KPI (요약)
  │     └─ 최근 작업 히스토리
  │
  ├─ S02→S09 새 작업 (Step Flow)
  │     S02 Inquiry 생성
  │       └─ 수출업체 · 수출국가 · 수입국가 지정
  │     S03 입력 채널 선택
  │       └─ 엑셀 / 직접 / 바코드(보조)
  │     S04 엑셀 업로드·헤더 매핑
  │       └─ S05 보류 큐 편집
  │     S06 직접 입력 폼 (카테고리 동적)
  │     S07 검색·추천 진행 (단계별 표시)
  │     S08 추천 리스트·컨펌
  │     S09 응대 양식 출력
  │
  ├─ S10 누적 조회 (수출업체·국가·기간·HS코드 필터)
  │     └─ S11 Classification 상세 (이력·근거·VerificationEvent)
  │
  ├─ S12 검증 이벤트 등록 (샘플 분석 / 추징 / 세관 확인)
  │     └─ S13 재검토 큐 (추징 파급 Item 자동 적재)
  │
  ├─ S14 에스컬레이션 큐 (전문가 권한)
  │     └─ S15 검토 회신 양식
  │
  └─ S16 관리 (관리자 권한)
        ├─ S17 마스터: 수입국 / 수출국 / 수출업체 / 외부 데이터 소스
        ├─ S18 정책 임계값 (국가별)
        ├─ S19 사용자·권한
        └─ S20 KPI 대시보드
```

### 2.2 핵심 화면 와이어프레임

본 절은 의사결정에 영향을 주는 핵심 8개 화면만 다룬다. 나머지 화면의 와이어프레임은 Phase 7 운영 단계에서 디테일을 채운다.

**S02. Inquiry 생성** — 수입국이 진입 시점에 확정되는 것이 핵심이다. 수입국에 따라 이후 검색 어댑터·세율 매트릭스·UI 표기가 분기되기 때문이다.

```
┌────────────────────────────────────────────────────────┐
│  새 작업 생성                                  S02     │
├────────────────────────────────────────────────────────┤
│  수출업체 (필수)    [ 검색·선택  ▼ ]   [+ 신규 등록]   │
│  수출국가 (필수)    [ 국가 선택  ▼ ]                   │
│  수입국가 (필수)    [ 국가 선택  ▼ ]                   │
│      └ 지원 상태: ● active | ◐ beta | ◌ not_supported │
│         (beta·미지원 선택 시 경고/추가요청 다이얼로그) │
│  작업명/메모        [                                ] │
│  등록일자           [ 2026-05-13 (오늘, 변경 가능) ]   │
├────────────────────────────────────────────────────────┤
│                              [ 취소 ]    [ 다음  → ]   │
└────────────────────────────────────────────────────────┘
```

**S03. 입력 채널 선택** — 채널 셋 중 하나를 고른다. 세 채널 모두 결과적으로 동일한 입력 큐로 합류한다.

```
┌────────────────────────────────────────────────────────┐
│  입력 방식                                     S03     │
├────────────────────────────────────────────────────────┤
│  ┌──────────────┐ ┌──────────────┐ ┌──────────────┐   │
│  │ 엑셀 일괄 등록│ │ 앱 직접 입력  │ │ 바코드 스캔  │   │
│  │ (다수 행)     │ │ (단건·소량)   │ │ (기성품 보조) │   │
│  │   [ 선택 ]    │ │   [ 선택 ]    │ │   [ 선택 ]    │   │
│  └──────────────┘ └──────────────┘ └──────────────┘   │
│  표준 템플릿 다운로드 ▼   ※ 양식이 다르면 헤더 매핑     │
├────────────────────────────────────────────────────────┤
│  [ ← 이전 ]                                              │
└────────────────────────────────────────────────────────┘
```

**S04. 엑셀 업로드·헤더 매핑** — 고객사마다 시트 구조가 다르므로 매핑은 *사용자가 통제*한다. 매핑되지 않은 컬럼은 spec_attributes(JSON)로 보존한다.

```
┌────────────────────────────────────────────────────────┐
│  엑셀 일괄 등록 — 헤더 매핑                    S04     │
├────────────────────────────────────────────────────────┤
│  파일: parts_2026Q2.xlsx        [재선택]                │
│  시트: [ Sheet1 ▼ ]    헤더 행: [ 1 ]                   │
├────────────────────────────────────────────────────────┤
│  시스템 필드            파일 컬럼                       │
│  품명           ◀─▶  [ Item Name      ▼ ]              │
│  카테고리       ◀─▶  [ Type            ▼ ]              │
│  재질           ◀─▶  [ Material        ▼ ]              │
│  성분(CAS+%)    ◀─▶  [ Composition     ▼ ]              │
│  용도           ◀─▶  [ Usage           ▼ ]              │
│  ※ 매핑 못한 컬럼 → spec_attributes(JSON) 보존         │
├────────────────────────────────────────────────────────┤
│  미리보기(10행)      ✔ 정상 7   ⚠ 보류 3                │
│  [─ 행별 표 미리보기 ──────────────────────────────────] │
├────────────────────────────────────────────────────────┤
│  [ ← 이전 ]   [ 검증 실행 ▶ ]   [ 보류큐 보기 (S05) ]   │
└────────────────────────────────────────────────────────┘
```

**S06. 직접 입력 폼 (카테고리 동적)** — 카테고리 선택에 따라 필수 속성이 분기한다. 완성도 점수가 바 형태로 항상 보인다.

```
┌────────────────────────────────────────────────────────┐
│  원부자재 정보 입력                            S06     │
├────────────────────────────────────────────────────────┤
│  ▣ 공통 필드                                            │
│  품명 (원어/한글/영문)  [______________________]        │
│  카테고리         ( ) chemical                          │
│                   ( ) steel_mechanical                  │
│                   ( ) equipment                         │
│                   ( ) other  ← 자동 에스컬레이션         │
│  용도 설명        [ 최소 30자 _________________ ]       │
│  사진/도면        [ + 업로드 ] (jpg/png/pdf, ≥1장)      │
├────────────────────────────────────────────────────────┤
│  ▣ 카테고리별 필드 (선택 시 동적 표시)                  │
│    예: chemical                                          │
│      MSDS               [ + 업로드 ]                    │
│      주요 성분 (CAS+%)  [ + 행 추가 ]                   │
│      UN 번호            [______]                        │
├────────────────────────────────────────────────────────┤
│  완성도 점수  ████████░░  0.78                          │
│  ※ < 0.7 이면 다음 단계 연성 차단 (사유 입력 필요)      │
├────────────────────────────────────────────────────────┤
│  [ ← 이전 ]  [ 임시저장 ]  [ 매칭 시작 ▶ ]              │
└────────────────────────────────────────────────────────┘
```

**S07. 검색·추천 진행** — 단계별 진행을 사용자에게 *명시적으로* 노출한다. 시스템이 무엇을 하는 중인지 보여주는 것 자체가 신뢰의 절반이다.

```
┌────────────────────────────────────────────────────────┐
│  HS코드 검색 진행                              S07     │
├────────────────────────────────────────────────────────┤
│  ✔ 1. 정규화 및 해시 산출  (composition_hash: 7f2a…)    │
│  ✔ 2. 내부 ERP 매칭         (후보 1건, 신뢰도 0.72)     │
│  ⟳ 3. 외부 권위 데이터 조회 (수입국 어댑터: VN-BIEU)    │
│  ◌ 4. AI 추천 엔진 호출      (대기 중)                  │
│  ◌ 5. 후보 랭킹·세율 룰      (대기 중)                  │
├────────────────────────────────────────────────────────┤
│  ※ 외부 데이터 미응답 시 캐시 fallback + 신뢰도 -0.2    │
│  [ 취소 ]                                                │
└────────────────────────────────────────────────────────┘
```

```
│  ※ 어댑터·세율 매트릭스가 함께 등록되어야 active 가능   │
└────────────────────────────────────────────────────────┘
```

## 3. 작업 분해 구조 (WBS)

작업은 8개 Phase로 나눈다. Phase 간 의존성은 *대체로 순차적이되 일부 병렬 가능*하다. 각 Phase는 *완료 정의(Definition of Done)*를 끝에 명시한다. 일정은 1인 풀타임 기준 상대치이며, 팀 인원과 동시 진행 여부에 따라 단축된다.

### Phase 0 — 기반(Foundation) · 1~2주

스택·리포지터리·CI·환경 변수·기본 라우팅·데이터 마이그레이션 도구까지의 골격을 만든다. 데이터 모델은 「설계문서」§3.1의 5개 엔티티 + 「SRS」§5의 추가 엔티티를 *마이그레이션 1차*로 적용한다. 이 시점에는 비즈니스 로직이 없어도 좋다.

산출물: 빈 골격 앱이 로컬·스테이징에서 기동, DB 마이그레이션 통과, S01 빈 대시보드 라우팅, 인증 스텁.

DoD: 새 개발자가 README만으로 1시간 안에 로컬에서 앱을 띄울 수 있다.

### Phase 1 — 마스터 데이터 & 권한 · 2~3주

멀티 국가 확장의 골격을 여기서 박는다. `ImportCountry`·`ExportCountry`·`Exporter`·`ExternalDataSource` 마스터, `FTA Matrix`(국가쌍×HS코드×세율) 스켈레톤, 사용자·역할·권한 모델. UI로는 S17 마스터 관리, S19 사용자·권한. 권한은 *수출업체 단위 격리*를 1차 가드레일로 둔다.

요구사항 매핑: FR-IN-01 부분, DR-01·DR-03, NFR-SE-01.

DoD: 관리자가 새 수입국을 *데이터만으로* 등록할 수 있고(어댑터 미연결은 not_supported 상태 유지), 수출업체별 권한 격리가 작동.

### Phase 2 — 입력 채널(Intake) · 3~4주

S02→S06의 입력 흐름을 완성한다. 동적 폼(§4 설계문서), 엑셀 헤더 매핑, 보류 큐 편집, 바코드 보조까지. 정규화·매칭은 다음 Phase로 미루고, 입력 결과는 *정규화 큐*에만 적재된다.

요구사항 매핑: FR-IN-01~08, DR-04, NFR-PF-03.

DoD: 1,000행 엑셀이 정상 + 보류 분리되어 큐에 적재되고, 동일 Inquiry에 직접 입력과 엑셀이 섞여 들어가도 정합성 유지.

### Phase 3 — 정규화·매칭·추천 엔진 · 4~5주

본 앱의 가치 중심. 세 단계로 나누어 점진 개발한다.

3.1 **정규화 모듈** — 카테고리별 정규화 규칙, `composition_hash` 산출. 수입국 오버레이는 인터페이스만 두고 기본값으로 시작.

3.2 **내부 매칭 엔진** — 우선순위 (1)~(3)을 구현(동일 업체·수입국 → 동일 수입국 → 속성 fuzzy). 인덱스(DR-06, DR-07) 함께 적용.

3.3 **외부 어댑터 + AI 추천** — 베트남 BIEU THUE 어댑터를 첫 번째 구현으로. 인터페이스는 다른 수입국에 동일하게 적용 가능해야 한다. AI 추천(FR-AI-01~03)은 *검색된 후보 범위 제약·환각 가드·근거 생성·실패 시 폴백*까지 포함.

UI로는 S07 진행 표시, S08 추천·컨펌 1차 렌더.

요구사항 매핑: FR-MA-01~05, FR-AI-01~04, IR-01~04, NFR-PF-01·02, NFR-AV-01.

DoD: 1순위 히트율과 AI 환각 비율을 자동 측정해 대시보드에 노출. 외부 API 다운 상태에서도 내부만으로 추천이 작동.

### Phase 4 — 컨펌·영속화 · 2주

S08 컨펌 흐름의 완성, `Classification` 영속화(추천 근거·외부 출처·사유 포함), S09 응대 양식 출력. 중복 컨펌 감지(X6)와 supersede 처리도 이 Phase에서.

요구사항 매핑: FR-CO-01~05, DR-02, NFR-DI-01, NFR-SE-02.

DoD: 동일 입력 컨펌 직후 누적 조회(S10)에서 즉시 검색되며, 다음 매칭 작업에서 1순위로 회수된다.

### Phase 5 — 검증·피드백 루프 · 2주

S12 검증 이벤트 등록, S13 재검토 큐, 신뢰도 갱신, supersede 자동화. 추징·정정률 KPI 1차 집계.

요구사항 매핑: FR-VR-01~03, DR-02 보강.

DoD: 추징 이벤트 1건 등록 시 동일 코드 사용 Item이 자동으로 재검토 큐에 적재되고, 해당 코드 후속 추천에서 경고가 표시된다.

### Phase 6 — 에스컬레이션·전문가 검토 · 2주

§2.4 6개 트리거 검사 엔진, 라우팅(Mr. Nguyen / Ms. Hau / 병렬), S14·S15 전문가 큐 화면, M3 blocking 동작.

요구사항 매핑: FR-ES-01~03.

DoD: 트리거 발동 시 응대 단계 진행이 차단되고, 전문가 회신이 들어오면 자동으로 차단 해제.

### Phase 7 — 관리·KPI·운영 · 2~3주

S16~S20의 나머지 관리 화면. 정책 임계값을 *수입국별*로 분리한 설정 UI(변경 4 반영). KPI 대시보드(추징·정정·세관확인·1순위 히트율·외부 호출 비율). 운영 지표(NFR-AD-03).

요구사항 매핑: FR-AD-01~03, FR-QU-03.

DoD: 6개월 운영 후 임계값 재교정을 코드 배포 없이 관리 화면에서 수행 가능.

### Phase 8 — 신규 국가 확장 절차(상시) · Phase 1 이후 상시

신규 수입국 추가는 *어댑터 1개 + 마스터 등록*으로 끝나야 한다(변경 2). 본 Phase는 *작업 절차 자체를 문서화 + 자동화*하는 메타 트랙이다.

내용: 어댑터 인터페이스 명세, 어댑터 신규 추가 시 회귀 테스트 스위트, 베타 → active 승격 체크리스트, 수출국 추가 시 FTA 매트릭스 보강 절차.

DoD: 신규 수입국 1개를 *문서 따라 5일 안에* beta 단계까지 올릴 수 있다.

## 4. 일정 마일스톤 (상대치)

Phase 0부터 Phase 7까지 1인 풀타임 기준 누적 약 18~21주. 핵심 마일스톤은 세 개다.

**M1 — 단건 매칭 가능(Phase 0~3 완료)**: 직접 입력 한 건이 내부 매칭 → 외부 어댑터 → AI 추천을 통과해 추천 리스트로 표시. 컨펌은 아직 영속화 미완. (≈ 누적 10~12주 시점)

**M2 — 누적·재사용 가능(Phase 4~5 완료)**: 컨펌이 ERP에 누적되고, 다음 매칭 작업에서 1순위로 회수. 사후 검증 이벤트가 신뢰도를 갱신. (≈ 누적 14~15주)

**M3 — 운영 가능(Phase 6~7 완료)**: 에스컬레이션·관리 화면·KPI 운영 모드. 운영 6개월 후 임계값 재교정 가능. (≈ 누적 18~21주)

신규 국가 확장(Phase 8)은 M1 이후 어느 시점에라도 적용 가능하다.

## 6. 리스크와 대응

본 작업의 위험은 대부분 *외부 의존*과 *데이터 누적이 충분해지기 전 구간*에 몰려 있다.

**R1. AI 추천의 환각.** 후보 범위 제약(FR-AI-01)이 핵심 가드레일이지만, 모델 변경 시 행동이 달라질 수 있다. **대응**: Phase 3에 환각률 자동 측정 메트릭을 함께 만든다. 임계 초과 시 자동 폴백(X3) 동작 확인.

**R2. 신규 수입국 어댑터 부재.** 어댑터 없는 수입국 선택 시 운영 마비. **대응**: S02에서 not_supported 단계에서 *추가 요청 양식*으로 우회. Phase 8에 어댑터 추가 표준 절차를 둔다.

**R3. 데이터 누적이 적은 초기.** 내부 매칭이 거의 비어 있어 외부·AI 호출 비용이 높다. **대응**: 초기 6개월은 *수동 시드* 트랙(과거 사례를 관리자가 입력)을 별도 운영. Phase 7 KPI에 *내부 히트율 추세*를 1급 지표로.

**R4. 권한 격리 누락.** 수출업체 단위 격리(NFR-SE-01)는 한 줄의 누락으로 정보 유출이 된다. **대응**: Phase 1에서 *행 수준 보안(RLS) 또는 동등 기제*를 DB 차원에서 강제. 애플리케이션 레이어 단독 의존 금지.

**R5. 엑셀 양식의 무한 다양성.** 헤더 매핑(S04)이 사용자에게 너무 어렵게 느껴질 수 있음. **대응**: Phase 2에 *고객사별 매핑 프로파일 저장* 기능을 우선 포함. 첫 등록 시 매핑이 다음부터 자동 제안되어야 한다.

**R6. 다국어 UI.** NFR-LO-01은 한>베>영 우선순위지만, 전문가(베트남)는 베트남어 화면이 필요하다. **대응**: Phase 0에서 i18n 기제를 박는다. 텍스트 하드코딩 금지를 코드 리뷰 룰로.

## 7. 가정과 의존성

본 계획은 다음 가정 위에 선다. 가정이 깨지면 일정·범위가 재조정된다.

- 베트남 BIEU THUE XNK 2026 데이터는 일정 형식으로 *프로그램적 조회 가능*하다(불가하면 어댑터 비용이 크게 증가).
- AI 추론 서비스(Claude 등)의 한국어·베트남어·영어 혼재 컨텍스트 처리가 *현실적 품질로 가능*하다.
- 카고러시 운영팀이 *마스터 데이터 시드*(국가·수출업체·과거 사례)를 Phase 1·2 시점에 제공할 수 있다.
- 신규 수입국 추가는 *비즈니스 의사결정* 영역이고, 본 시스템은 *그 결정 후의 운영 가능성*만 보장한다.

## 8. 다음 단계

본 작업계획서 직후의 설계 작업은 다음 순서를 권장한다.

1. **어댑터 인터페이스 명세** — `lookupByAttributes(attributes, importCountry)`의 입출력 스키마, 에러 모델, 캐시 정책.
2. **속성 정규화 규칙 v0** — 카테고리(chemical/steel/equipment/other)별 정규화 변환표, composition_hash 산출식.
3. **엑셀 표준 템플릿 + 매핑 프로파일 모델** — 고객사별 자동 매핑 저장 구조.
4. **AI 프롬프트 v0** — 컨텍스트 구성, 후보 범위 제약, 환각 방지, 출처 인용 강제 형식.
5. **권한·격리 모델 상세** — 수출업체 단위 RLS, 관리자/전문가/담당자 권한 매트릭스.
6. **수입국·수출국 마스터 시드** — 운영 초기 active로 시작할 국가 셋과 그 어댑터 매핑.

이 여섯 가지가 끝나면 Phase 0~1의 개발이 동시에 시작될 수 있다.
