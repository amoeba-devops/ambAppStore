# EAGLE VINA 면장 데이터 분석 — HS Code Manager 반영 제안

> 입력 자료: `BaoCaoHangChiTiet EAGLE VINA 수출입 기록.4.28.25.xls` (베트남 골프공 제조사 EAGLE VINA의 2024-01 ~ 2025-04 수출입 면장 명세).
> 작성 목적: 실제 운영 데이터의 구조와 패턴을 「설계문서/이벤트시나리오/요구사항명세서/작업계획서」에 *역으로 반영*하기 위한 분석. 추정으로 잡았던 데이터 모델·UI·정책을 실측에 맞춰 보정한다.
> 작성 기조: 분석은 짧게, 반영 제안은 구체적으로.

## 1. 데이터 한눈에 보기

본 파일은 두 시트(수입·수출), 54개 컬럼으로 구성된 면장 라인 명세다. 한 행 = 한 신고서(`Số TK`)의 한 품목(`STT hàng`). 즉 *신고서 1건이 여러 품목 라인을 가진다*(1:N).

| 구분 | 행 수 | 고유 면장 수 | 고유 HS코드 | 거래처 | 원산지 | 기간 |
|---|---|---|---|---|---|---|
| 수입 | 910 | 348 | 110 | 48 | 14개국 | 2024-01-02 ~ 2025-04-28 |
| 수출 | 219 | 188 | 6 | 8 | 3개국(주 VN) | 2024-01-02 ~ 2025-04-26 |

수입은 다양한 원부자재(폴리우레탄·고무·페인트·아연·종이·기계부품 등 110종 HS코드)가 14개국에서 들어오고, 수출은 사실상 골프공 1품목(HS 9506.32.00, 177회) + 반제품 코어(HS 4016.99.99, 37회)에 수렴한다. 전형적인 *가공무역* 패턴(원부자재 다국적 수입 → 베트남에서 가공 → 단일 완제품 수출)이다.

## 2. 54개 컬럼의 의미 그룹화

54컬럼은 *6개 의미군*으로 나뉜다. 이 분류가 HS Code Manager의 데이터 모델 보강을 결정한다.

**G1. 신고서 메타** (8개) — `STT, Số TK, Ngày ĐK, Mã loại hình, 거래조건(CIF/FOB/CFR), 환율, 통화, Ghi chú`. 신고서 단위 식별·시점·거래조건.

**G2. 운송·반입지** (7개) — 목적지 코드/명, 양하지, 운송수단, 출발일, 포장기호. 본 앱의 분류 의사결정에는 영향이 적음 — 면장 출력 시 그대로 통과시키면 충분.

**G3. 포장·중량** (6개) — `Số lượng kiện, Mã ĐVT kiện, Trọng lượng, Mã ĐVT trọng lượng, Số quản lý nội bộ`. M4 응대 양식에 필수.

**G4. 품목·분류** (5개) ★ — `STT hàng, Mã NPL/SP, Mã HS, Tên hàng, Xuất xứ`. **본 앱의 핵심 입력·출력**. `Mã NPL/SP`는 *고객사 자체 관리코드*(예: `NDBR`, `RUH3600`, `38B`, `DH1000000004`)로, 동일 거래처에서 반복 등장하는 강력한 매칭 키.

**G5. 가격·수량** (6개) — 단가, 과세단가, 수량(1·2), 단위(1·2), 외화가, 총액. 세금 산출의 입력.

**G6. 세금** (15개) ★ — *6종 세금이 각각 (세율·세액) 쌍으로 분리*: XNK(수출입세), TV(특별소비세 추정), PB(반덤핑세), TTĐB(개별소비세), BVMT(환경보호세), VA(부가가치세). 실측에서는 XNK와 VA만 실질적으로 채워지고 나머지는 거의 0/공란.

**G7. 거래 주체·계약** (7개) — 사업자코드/명(=신고인), `Tên đối tác`(=실제 거래 상대방), 인보이스/계약 번호·일자.

특기 사항: **`Tên doanh nghiệp`(신고인)과 `Tên đối tác`(거래처)이 다른 컬럼**이다. 현재 SRS의 `Exporter` 단일 마스터로는 부족 — 신고인(자사·관계사)과 거래처(공급사·구매사)를 분리해야 한다.

## 3. 발견된 핵심 패턴 (8개)

**P1. 거래유형(Mã loại hình)이 세율의 1차 분기자다.** 수입측은 A12(일반수입) 341건 / E31(가공무역 원자재 수입) 292건 / A42(가공후 재반입 추정) 271건이 거의 균등. 수출측은 E62(가공무역 완제품 수출)가 213/219로 압도. **이 코드가 면세·환급·관세 적용 여부를 결정**하므로, 추천 흐름에서 *(수입국, 수출국, HS, 거래유형)* 4항 키가 세율을 결정해야 한다.

**P2. 동일 HS코드는 거래처·원산지에 걸쳐 세율이 매우 일관적이다.** 상위 5개 HS 모두 단일 세율로 수렴한다(예: HS 32100099 → 100% R.KOREA → 100% 20% / HS 39095000 → 거의 100% R.KOREA → 100% 3% / HS 79039000 → JP·CN·TW 혼재 → 100% 0%). 즉 **(HS, 원산지)의 페어가 세율을 거의 결정한다** — 내부 매칭의 1순위 검색이 처음부터 매우 높은 정확도를 가질 것임을 시사.

**P3. `Mã NPL/SP`(자체관리코드)는 매우 강력한 매칭 키지만 38% 결측이다.** NDBR(40회), RUH3600(29회), HUT005(29회), 48C(19회) 등 동일 SKU가 반복된다. 결측 비율이 크므로 *필수 키로는 불가*하지만, *있을 때는 1순위 매칭에 즉시 사용*해야 한다(composition_hash보다 우선).

**P4. 품명(`Tên hàng`)은 정보의 보고다.** `38B#&Hạt nhựa nhiệt dẻo polyurethane 38B (Thermoplastic polyurethan resin 38B), 원료 골프공.Hàng mới 100%` 형식으로 *자체관리코드 + 베트남어 품명 + 영문 학명 + 등급 + 용도 + 신품여부*가 한 셀에 박혀 있다. CAS 번호(예: `CAS:14643-87-9,557-05-1`)도 본문에 매몰되어 있음. **이 텍스트의 LLM 파싱이 정규화 단계의 가장 큰 가치**가 된다.

**P5. 신고서 1:N 품목.** 한 면장(`Số TK`)에 평균 2.6품목(910÷348). 가장 큰 신고서는 수십 품목까지 가능. **`Inquiry → 여러 Classification`이 자연 모델**이지만, 면장 자체를 묶는 *신고서 단위 엔티티*가 누락되어 있다(현재 SRS에는 없음).

**P6. 세금은 6종이지만 운영 데이터는 사실상 2종(XNK·VAT).** TV·PB·TTĐB·BVMT는 거의 비어 있음. **스키마는 6종을 모두 수용하되, UI 기본 노출은 XNK·VAT만 하고 나머지는 조건부 노출**.

**P7. 신고인과 거래처의 분리.** `Tên doanh nghiệp = CONG TY TNHH EAGLE VINA`(자사·관계사 271행)와 `Tên đối tác`(SUNGJOO·QINGDAO 등 48개)이 다른 축. 본 앱의 `Exporter`는 *거래처(=고객사의 수출업체)*에 해당하며, 신고인(=카고러시의 의뢰사인 EAGLE VINA)은 *Inquiry의 소유 회사*다. **두 마스터를 분리해야 권한·검색이 깨끗해진다**.

**P8. 가공무역 사이클 — 수입↔수출이 한 회사 안에서 연결된다.** EAGLE VINA는 원부자재 수입(E31)→가공→완제품 수출(E62)을 하는 동일 법인. 한 회사 단위로 *수입·수출 통합 뷰*를 보여줄 수 있어야 운영에 의미가 있다.

## 4. HS Code Manager에 반영할 사항

### 4.1 데이터 모델 보강

**DR-10 (추가) CustomsDeclaration(면장) 엔티티 신설.** Inquiry와 Classification 사이에 *신고서 단위*가 들어간다. 한 면장은 여러 Classification(품목)을 가진다(P5). 컬럼: `declaration_id (PK)`, `inquiry_id (FK)`, `declaration_no (Số TK)`, `declaration_date (Ngày ĐK)`, `loai_hinh_code (Mã loại hình)`, `incoterm (CIF|FOB|CFR|...)`, `currency`, `exchange_rate`, `package_count`, `package_unit`, `weight`, `weight_unit`, `port_of_discharge`, `transport_mode`, `notes`. 이 엔티티가 있어야 면장 출력 양식이 자연스럽게 모인다.

**DR-11 (추가) Classification에 `loai_hinh_code` 추가.** 거래유형이 세율의 1차 분기자(P1)이므로 *Classification 단위에도 거래유형*이 붙어야 한다. 같은 HS코드라도 거래유형이 달라지면 세율·면세가 달라진다.

**DR-12 (추가) Classification.tax_breakdown JSON 컬럼.** 세금 6종을 (코드, 세율, 세액) 트리플의 리스트로 보관(P6). 단일 `basic_tariff_rate` 컬럼은 표시용 보조로 남기고, 실제 응대 데이터는 JSON에서 끌어쓴다.

**DR-13 (추가) Customer SKU 매칭 키.** `Item`에 `customer_sku_map JSON`을 두어 *수출업체(=거래처)별 자체 관리코드*를 누적한다(P3). 매칭 시 (수출업체, customer_sku) 페어가 일치하면 composition_hash보다 *우선 1순위*로 사용한다.

**DR-14 (추가) Declarant(신고인) 마스터 분리.** 기존 Exporter 마스터 외에 `Declarant`(=면장 신고 의뢰사) 마스터를 둔다(P7). Inquiry는 `declarant_id`(신고인)와 `exporter_id`(거래처) 둘을 모두 FK로 가진다. 권한 격리도 둘 다에 적용.

**DR-15 (보강) FTA 매트릭스의 키 확장.** 기존 *(수입국, 수출국, HS코드)*에 **거래유형**과 *원산지*를 추가한 *(수입국, 수출국, 원산지국, HS코드, 거래유형)* 5항 키로 일반화. 세율표코드(`Mã biểu thuế XNK` = B01, B05 등)는 행 속성으로 저장.

### 4.2 신규/보강 기능 요구사항

**FR-IN-09 (추가, M) 품명 텍스트의 LLM 파싱.** 입력 폼·엑셀 등록 시 `Tên hàng` 류의 자유 텍스트에서 *자체관리코드·CAS·영문명·용도·함량·신품여부*를 자동 추출해 정규화 필드를 프리-필한다(P4). 사용자는 추출 결과를 검토·수정한다. *왜*: 실측 데이터의 가장 큰 정보 손실 지점이 자유 텍스트의 정규화다.

**FR-IN-10 (추가, S) 면장 엑셀 직접 등록.** 본 파일과 같은 *54컬럼 면장 양식*을 표준 템플릿으로 추가한다. 헤더 매핑이 사실상 자동(컬럼명 1:1). 시드 데이터 마이그레이션·신규 고객사의 과거 면장 일괄 등록에 즉시 활용.

**FR-MA-06 (추가, M) 매칭 우선순위 확장.** 기존 (1) 동일 수출업체·수입국 → (2) 동일 수입국 → (3) 속성 fuzzy 순서에 **(0) `(수출업체, customer_sku)` 정확 일치**를 최상위로 추가(P3). 실측 패턴상 단일 키로 즉시 매칭되는 비율이 매우 클 것.

**FR-MA-07 (추가, M) 세율 산출은 (수입국, 수출국, 원산지국, HS, 거래유형) 키 조회로.** 거래유형이 세율을 바꾸므로(P1) S07/S08 표시 세율은 항상 5항 키로 조회한 결과여야 한다.

**FR-CO-06 (추가, M) Classification 영속화 시 면장 메타 동반.** 컨펌 결과를 면장 양식(54컬럼)으로도 즉시 export 가능해야 한다(P5, 5.3 응대 양식). 거래조건·운송·포장·세금 6종이 모두 포함된 행 단위 출력.

**FR-QU-04 (추가, S) 신고인 통합 뷰.** 동일 신고인(예: EAGLE VINA)에 대해 수입·수출 양 트랙을 *한 화면에서 조회*(P8). 가공무역 사이클의 원부자재-완제품 추적에 필수.

### 4.3 신규 화면

**S04-b (S04 확장) 면장 엑셀 등록 — 표준 모드.** S04의 자유 매핑 화면 옆에 *"면장 양식(54컬럼)" 표준 모드* 탭을 둔다. 표준 모드는 컬럼 매핑이 사전 정의되어 매핑 단계를 스킵, 검증과 보류 큐로 직행.

**S09-b (S09 확장) 면장 출력 미리보기.** M4 응대 양식을 *면장 54컬럼 행* 형태로 미리보고 엑셀/PDF로 내보낸다. 세금 6종은 운영 데이터가 채워진 것만 표시(XNK·VAT 위주).

**S11-b (S11 확장) Classification 상세에 면장 컨텍스트.** 어떤 면장(`Số TK`)의 몇 번째 품목인지, 같은 면장의 다른 품목은 무엇인지 함께 본다.

**S21 (신규) 신고인 통합 뷰.** 좌측 수입 라인, 우측 수출 라인을 시간 축으로 묶어 *원부자재 → 완제품 흐름*을 한 화면에 표시(P8).

### 4.4 시드 데이터로의 활용 전략

본 파일은 *그 자체로 1,129행의 시드 데이터*다. Phase 1~3 개발 중에 다음 순서로 활용한다.

첫째, **마스터 시드**: 14개 원산지국, 48개 거래처, 110개 HS코드, 1개 신고인(EAGLE VINA)을 Phase 1 마스터 테이블에 즉시 시드. 모두 active로 시작 가능.

둘째, **Classification 누적 시드**: 910행 수입 + 219행 수출을 `Classification` (status=adopted) 레코드로 일괄 로드. 이로써 시스템이 *0일차부터 내부 매칭 1순위 검색이 작동*하는 상태로 시작한다. 신뢰도는 *과거 면장에서 채택되었음이 증명된* 0.90으로 부여.

셋째, **AI 평가 셋**: 동일 데이터를 *예측 vs 정답* 평가셋으로 사용. 품명+속성을 입력해 AI가 추천한 HS와 *실제 채택된 HS*를 비교 → 1순위 히트율·환각율·세율 일치율 측정. Phase 3의 가드레일 튜닝 입력.

넷째, **시연용 데모 시나리오**: 신규 고객사 데모 시 "당신 회사의 과거 1년치 면장을 등록하고 추천을 받아보라"는 *제로 콜드 스타트 데모*가 가능. 본 파일이 그 템플릿이 된다.

### 4.5 응대 양식의 표준화

지금까지 응대 양식은 「설계문서」§1.2 M4에 *"채널별 다르게 렌더링"*으로만 기술되어 있었다. 본 파일이 사실상 *베트남 통관 신고의 정형 양식*이므로, **면장 54컬럼이 카고러시 표준 응대 출력**이 된다. 채널별 변형(이메일·메신저)은 이 54컬럼의 부분 발췌·요약일 뿐이다. M4 설계의 *기준 양식*을 본 파일로 픽스한다.

### 4.6 정책·UI 보정

**보정 1. UI 라벨의 다국어 우선.** 본 파일의 컬럼명은 모두 베트남어. 베트남 측 전문가·세관 대응 시 *베트남어 라벨이 1순위*가 되는 경우가 있음을 확인. NFR-LO-01의 *한>베>영* 우선순위는 **사용자 역할별로 토글 가능**해야 한다.

**보정 2. 카테고리 분류의 재교정.** 본 데이터의 110개 HS코드를 카테고리(`chemical | steel_mechanical | equipment | other`) 분포로 보면 *chemical(28·32·34·38·39·40)과 equipment(84)가 압도적*이고 steel_mechanical(73·79)는 부수. 본 회사 한정으로는 카테고리 4개가 충분하지만, *카테고리는 (회사, 산업)에 종속될 수 있음*을 확인 — NFR-EM-01(설정 기반 카테고리 확장)의 우선순위를 Should → Must로 올린다.

**보정 3. 응대 양식의 세금 6종.** 노출 정책은 *"운영 데이터가 한 번이라도 채워진 종류만 기본 노출, 나머지는 펼치기"*가 적절. 본 데이터 기준으로는 XNK·VAT만 기본, 나머지는 펼침.

## 5. 즉시 활용 가능한 시드 시나리오

본 분석 직후 만들 수 있는 4개 데모 시나리오를 제안한다. Phase 3 종료 시점에 *실 데이터로 시연 가능*해진다.

**Demo-1 — 동일 거래처 반복 매칭**: "SUNGJOO T&C에서 폴리우레탄 38B가 또 들어왔습니다" → 내부 매칭 즉시 (HS 39095000, 3% B01), 외부·AI 호출 없이 1초 안에 추천 표시.

**Demo-2 — 신규 거래처, 동일 카테고리**: 신규 한국 거래처에서 *유사 폴리우레탄* 입고 → composition_hash 부분 일치 + 동일 HS의 누적 패턴 → 0.85 이상 신뢰도로 동일 코드 추천.

**Demo-3 — 거래유형 분기 데모**: 같은 폴리우레탄을 A12(일반)와 E31(가공무역)로 따로 등록 → 세금 산출이 달라지는 것을 한 화면에서 비교. 거래유형의 의미를 사용자에게 학습시키는 시연.

**Demo-4 — AI 환각 가드 테스트**: 본 데이터에 없는 가공의 화학물질 속성을 입력 → AI가 *검색된 후보 범위 내에서만* 추천하고 *"근거 출처 없음"*을 명시하는지 확인. 가드레일 회귀 테스트의 1번 케이스.

## 6. 산출물에 대한 후속 조치 요약

다음 4가지 작업이 *본 분석의 즉시 후속*이다.

1. **「HSCODE_요구사항명세서」 패치**: DR-10~15, FR-IN-09/10, FR-MA-06/07, FR-CO-06, FR-QU-04, NFR-LO-01 보정, NFR-EM-01 우선순위 상향.
2. **「HSCODE_작업계획서」 Phase 1·2 보강**: Declarant 마스터, 면장 양식 표준 등록, CustomsDeclaration 엔티티를 Phase 1 골격에 포함.
3. **시드 데이터 적재 스크립트**: 본 파일 → DB 시드 변환 스크립트(엑셀 → Item·Classification·CustomsDeclaration). Phase 0 끝에 합류.
4. **카테고리·정규화 규칙 v0**: 실측 110개 HS코드를 입력으로 카테고리 분포·정규화 규칙을 잡는다.

본 파일 한 건이 *추정으로 잡았던 데이터 모델과 정책의 절반을 실측으로 교체*할 만큼의 정보를 담고 있다. 같은 형태의 면장 데이터를 2~3개 고객사에서 더 받으면, 카테고리·세금·거래유형의 *베트남 운영 표준*을 본 시스템 안에 박아 넣을 수 있을 것이다.
