# 테스트케이스 — 문서 업로드 매칭 대량 비동기 (BullMQ)

- 문서 ID: TC-20260710-대량비동기매칭
- 선행: REQ/PLAN-20260710-대량비동기매칭
- 우선순위 P0/P1 · 판정 Pass/Fail

## 1. 스키마 (TC-D)
- TC-D01(P0): 마이그레이션 후 `hsm_match_requests.mrq_processed_count` 존재(default 0), 기존 컬럼 무변경.

## 2. 비동기 파이프라인 (TC-A)
- TC-A01(P0/R2): POST /matching/upload → **즉시** 요청건 요약(status=PROCESSING, mrqId, itemCount) 반환(전체 매칭 대기 없음).
- TC-A02(P0/R2): 업로드 직후 품목(items)은 생성됨(추천 없음/미처리).
- TC-A03(P0/R1): 워커가 큐 job 처리 → 품목별 matchItem → 추천 저장. 완료 시 status=READY.
- TC-A04(P0/R3): 처리 중 GET /matching/requests/:id 의 mrq_processed_count 가 증가(진행률).
- TC-A05(P0/R1): 100행 초과(예: 300행) 업로드 정상 처리(잘림 없음, MAX_ITEMS 상향).
- TC-A06(P0/R4): 특정 품목 매칭 오류가 나도 나머지 계속 처리(격리), 전체 status 결국 READY.
- TC-A07(P1/R5): 워커 concurrency 상한(≤3)으로 동시 요청 시 서버 과부하 없음.
- TC-A08(P0/R6): READY 후 추천 리스트·승인(confirm)·LEARNED 재저장 기존과 동일 동작.

## 3. 매칭 정합 (TC-M)
- TC-M01(P0): matchItem 결과가 기존 동기 matchOne과 동일(면장+지식 RAG→AI/폴백→top3 추천·신뢰도·근거).
- TC-M02(P0): 품명 미검출/저신뢰 품목은 needsReview 유지.
- TC-M03(P1): AI 키 미설정 시 검색 폴백으로 처리(무중단).

## 4. 프론트 (TC-U)
- TC-U01(P0/R3): 업로드 → 결과 화면 이동 → **진행바(processed/itemCount)+"분석 중"** 표시.
- TC-U02(P0): status PROCESSING 동안 폴링, READY 시 폴링 중지+결과 렌더.
- TC-U03(P1): i18n ko/en/vi(분석 중/진행률).

## 5. 비기능 (TC-N)
- TC-N01(P0): ent_id 격리(요청건/품목/추천) 유지.
- TC-N02(P1): 대량(수백행) 처리 중 bff 응답성 유지(업로드/조회 API 정상).
