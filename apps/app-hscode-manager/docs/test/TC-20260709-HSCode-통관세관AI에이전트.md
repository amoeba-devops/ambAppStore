# HS Code 통관 에이전트 — 테스트케이스 (v1.1 · 컨셉 재정의 반영)

## 0. 개요
| 항목 | 내용 |
|------|------|
| 대상 | ① 문서 업로드 → AI 분석 → RAG 매칭 → HS 추천/승인/저장(주) · ② Q&A 챗봇 · RAG 구축 |
| 환경 | 개발/스테이징/프로덕션(app-hscode-manager, PostgreSQL+pgvector, TEI BGE-M3, Claude) |
| 우선순위 | P0/P1/P2 · 판정 Pass/Fail/Blocked/N/A |
| 전제 | AMA SSO, ent_id(UUID), 유효 Claude 키, RAG 시드(면장 표본 + VN/KR/CN/US 기준표) |

| 그룹 | TC | 요구사항 | Phase |
|------|-----|--------|-------|

## 1. RAG 구축 (최우선, TC-G)
- **TC-G01**(P0/R1): **면장 업로드** → 파싱·정규화 → `hsm_hs_references`/지식 저장, 자동 임베딩(BGE-M3 1024) 생성.
- **TC-G02**(P0/R1): 면장 다건 업로드 진행률·중복 dedupe(동일 성분↔HS 병합).
- **TC-G03**(P0/R2): **VN HS 기준표** 적재 → `hsm_hs_codes` 마스터(코드·구조), 해설=지식문서.
- **TC-G04**(P0/R2): **KR/CN/US 기준표** 보조 적재, VN 매핑 참조 가능.
- **TC-G05**(P0): 판단기준(분류원칙·해설) 지식문서 청킹 → `hsm_doc_chunks`(hnsw) 임베딩.
- **TC-G06**(P0): 전역 지식(ent_id NULL=슈퍼관리자) + 엔티티 LEARNED 결합 검색(`ent_id=현재 OR NULL`).
- **TC-G07**(P0): 매칭·챗봇 검색 시 **VN 가중 우선**, KR/CN/US 보조.
- **TC-G08**(P1): 업로드 즉시 청킹·임베딩 반영(신규 지식이 다음 매칭에 노출).

## 2. 문서 업로드 매칭 (주 기능, TC-M)
- **TC-M01**(P0/R4): **다양한 양식** 엑셀 업로드 → 시트/행 추출.
- **TC-M02**(P0/R4): PDF 업로드 → 텍스트 추출.
- **TC-M03**(P0/R4): **LLM 컬럼 의미 추론**(품명·성분·용도·수량 등) → 정규화 품목 리스트. 알려진 양식은 어댑터 fast-path.
- **TC-M04**(P0): 파싱 실패/모호 행 **검토 플래그**(무단 폐기 금지).
- **TC-M05**(P0/R4): 품목별 하이브리드 RAG 매칭(면장+기준표) → **HS 추천(신뢰도·근거[유사면장/기준]·확인필요)**.
- **TC-M06**(P0): 대량 업로드 **BullMQ 비동기** 처리·진행률·결과 조회.
- **TC-M07**(P0/R5): 추천 리스트 **행별/일괄 승인·컨펌** → **요청건(Recommendation 묶음) 저장**.
- **TC-M08**(P0/R5·R8): 승인분 → 면장/지식(LEARNED) **재저장·임베딩**(자기개선) → 이후 매칭 노출.
- **TC-M09**(P1): 결과 엑셀 내보내기(추천 HS·신뢰도·근거·상태).

## 3. Q&A 챗봇 (TC-Q)
- **TC-Q01**(P0/R3): 자연어 질문 → 하이브리드 RAG 검색 → **대화형 답변**(HS 후보·근거·확인쟁점).
- **TC-Q02**(P0): 세션 내 **대화 이력 유지**(후속 질문 맥락 반영).
- **TC-Q03**(P0): 근거는 RAG 문서/면장 **인용**(환각 금지).
- **TC-Q04**(P0): 정보 부족 시 **되묻기**(명확화 질문).
- **TC-Q05**(P1): 키/코퍼스 미설정 시 폴백(무중단 안내).

## 4. 쉬운 UI/UX (TC-U)
- **TC-U01**(P0/SCR-1): 홈 = **드래그&드롭 업로드** 즉시 분석, 최근 업로드 바로가기.
- **TC-U02**(P0/SCR-1): **[직접 입력(고급)]** 은 별도 버튼(주 흐름 비침습).
- **TC-U03**(P0/SCR-2): 매칭 결과 = HS 크게·**신뢰도 색상(🟢🟡🔴)**·근거 접이식·행 체크 **일괄 승인**.
- **TC-U04**(P0/SCR-2): ⚠ 검토필요/사전심사 권고 시각 강조, 최소 클릭 승인.
- **TC-U05**(P0/SCR-3): Q&A 챗봇 대화 UI(입력·전송·근거 표시).
- **TC-U06**(P0/SCR-4): 레퍼런스 구축(관리자) — 면장/기준표/지식 업로드·적재 현황.
- **TC-U07**(P1/SCR-5): 요청건 이력 — 승인/검토 건수·다시열기·재사용 표시.
- **TC-U08**(P1): i18n ko/en/vi, 하드코딩 없음.

## 5. 수동입력(고급) + 규칙엔진 (TC-R)
- **TC-R01**(P1/R6): [고급] 별도 화면에서 Item+성분(소재·기능·함량%) 입력, 합계 100% 검증.
- **TC-R02**(P1): 규칙엔진 — 주성분(최대함량)·본질특성·혼합/적층/코팅 플래그 산출.
- **TC-R03**(P1): 위험점수 → 임계 초과 시 사전심사/HIGH 플래그.
- **TC-R04**(P1): 규칙 결과가 RAG 질의·LLM 컨텍스트 힌트로 전달.
- **TC-R05**(P2): 고급 경로가 주 흐름(업로드) 무영향.

## 6. 스키마 (TC-D)
- **TC-D01**(P0): 마이그레이션 적용 → 신규 테이블(hsm_items·compositions·documents·doc_chunks·class_cases·recommendations + 마스터) 생성, 기존 `hsm_*` 무변경.
- **TC-D02**(P0): `hsm_doc_chunks.chk_embedding vector(1024)` + hnsw 코사인 인덱스 존재.
- **TC-D03**(P0): 지식문서 `hsm_documents.ent_id` NULL 허용(전역/슈퍼관리자), 트랜잭션 테이블 NOT NULL.
- **TC-D04**(P1): FK CASCADE, 인덱스(ent_id·status·risk·escalation) 존재.

## 7. 비기능/멀티테넌시 (TC-N)
- **TC-N01**(P0/R7): 추천 기준국 VN 우선 표시.
- **TC-N02**(P0): 모든 추천/답변에 근거·확인 포인트 동반.
- **TC-N03**(P0/R9): 면장/지식(전역=슈퍼관리자)/요청건/확정 `ent_id` 스코핑, 인증 가드(타 테넌트 차단).
- **TC-N04**(P0/R9): 키/코퍼스 미설정 폴백 무중단.
- **TC-N05**(P0/R8): 지속 사용 → 지식 축적이 정확도에 반영(자기개선).
- **TC-N06**(P1): 대량 업로드·LLM 파싱 비용/지연 관리(비동기·캐싱·예산가드).
