## 0. 구현 컨셉 재정의 (v1.3 — 최상위 방향)

통관/세관 HS 분류 AI 에이전트는 **두 가지 역할**을 한다.

| 역할 | 메뉴 | 동작 | 비중 |
|------|------|------|------|
| **① Q&A 챗봇** | 기존 Q&A(`/search/qa`) | 사용자가 **자연어로 질문** → RAG 지식(면장·기준표·규칙) 기반 답변 | 주 |
| **② 문서 업로드 매칭** | 기존 속성/엑셀(`/search/attribute`) | 고객사가 **기존 양식 문서(주로 엑셀, PDF) 업로드** → AI가 내용 분석 → RAG(면장 등)에서 **동일/유사 케이스**를 찾아 **HS 추천 매칭** → 리스트 | **주** |

- **주 기능 = ② 문서 업로드 매칭.** 사용자가 성분을 입력폼에 일일이 적는 것은 **주 기능이 아니다.** **수동 입력 = 부가/고급 기능(별도 버튼).**
- 추천 매칭된 **리스트를 사용자가 검토 → 승인/컨펌 → 요청건별로 저장**.
- **이번 업데이트 최우선 = 레퍼런스(RAG) 구축.**
  - 기존 **면장**(성분과 매칭된 HS를 가진 문서)을 **미리 업로드해 RAG 지식으로 저장**.
  - **베트남·한국·중국·미국** 등 **HS 기준표** 정보 기반으로 **매칭 판단기준** 구성.
  - 지속 사용으로 **추가 지식을 쌓고 정확도 향상**.
- **UI/UX는 무조건 쉬워야 한다.** hscode를 **보다 쉽게 확인**할 수 있는 화면이 목표.

> **이전 v1.2와의 차이**: 규칙엔진·BOM 수동입력 중심 → **문서 업로드 자동 매칭 + Q&A 챗봇 중심**으로 전환. 규칙엔진·Item/Composition 정형입력은 **고급/수동 경로**로 보조. **RAG 구축이 최우선.**

## 1. 요구사항 요약

| # | 요구사항 | 유형 |
|---|----------|------|
| R1 | **레퍼런스 RAG 구축(최우선)**: 면장(성분↔HS) 업로드 → RAG 저장·임베딩 | 필수 |
| R2 | **HS 기준표(VN 기준 + KR/CN/US 보조)** 적재 → 매칭 판단기준 | 필수 |
| R3 | **① Q&A 챗봇**: 자연어 질문 → RAG 근거 답변(대화형, 근거·확인쟁점 포함) | 필수 |
| R4 | **② 문서 업로드 매칭(주 기능)**: 다양한 양식 엑셀/PDF 업로드 → AI 분석 → RAG 유사 매칭 → HS 추천 리스트 | 필수 |
| R5 | 추천 리스트 **승인/컨펌 → 요청건별 저장**(재활용·자기개선) | 필수 |
| R6 | **수동 성분 입력 = 부가/고급**(별도 버튼), 주 흐름 방해 금지 | 필수 |
| R7 | **쉬운 UI/UX** — 업로드 즉시 결과, HS를 한눈에 확인·승인, 최소 클릭 | 필수 |
| R8 | 지속 사용으로 지식 축적 → 정확도 향상(피드백 루프) | 필수 |
| R9 | 키/코퍼스 미설정 시 폴백 무중단, 멀티테넌시 `ent_id` 격리 | 필수 |

> **핵심**: 사용자는 "자기 회사 엑셀을 올리면 HS가 매칭돼 나오는" 쉬운 경험을 얻고, 관리자는 면장·기준표를 RAG로 쌓아 정확도를 높인다.

|---|------|
| P1 | 엑셀 분류가 **고정 템플릿 + 어댑터**라 "다양한 고객 양식"을 AI가 분석하지 못함(R4) |

## 3. TO-BE 요구사항

### 3.1 역할 ① Q&A 챗봇 (R3)
- 자연어 질문 → 하이브리드 RAG(면장+지식+기준표) 검색 → **설정 Claude가 대화형으로 답변**(HS 후보·근거·확인쟁점, 필요 시 되묻기). 세션 내 대화 이력 유지.
- 근거는 RAG 문서/면장 인용(환각 금지).

### 3.2 역할 ② 문서 업로드 매칭 (R4, 주 기능)
```
[업로드] 고객사 양식 엑셀/PDF (다양한 형식)
   → AI 문서 분석: 행/품목 추출(품명·성분·용도 등), 형식 자유(LLM 파싱 + 어댑터 병행)
   → 각 품목 RAG 매칭: 면장·기준표에서 동일/유사 케이스 검색(하이브리드)
   → HS 추천 리스트(품목별 VN HS + 신뢰도 + 근거[유사 면장/기준] + 확인필요)
   → 사용자 검토 → 승인/컨펌(행별/일괄)
   → 요청건별 저장(Recommendation/Case) + 확정분 RAG 재저장(자기개선)
```
- 고정 템플릿 외 **자유 양식**은 AI가 컬럼 의미 추론(품명/성분/수량 등). 실패 행은 검토 플래그.
- 대량은 기존 BullMQ 비동기 유지.

### 3.3 최우선 — 레퍼런스 RAG 구축 (R1/R2)
- **면장 업로드**: 기존 `reference/imports` 재사용·강화 → 성분↔HS 실적을 RAG(임베딩)로 축적.
- **HS 기준표**: VN(기준)+KR/CN/US 코드·구조·세율/FTA를 **마스터/지식**으로 적재(`hsm_hs_codes`, `hsm_documents`). VN 우선 가중.
- **판단기준 지식**: 분류원칙·기준표 해설을 지식문서로.
- 슈퍼관리자 전역 지식 + 엔티티 LEARNED.

### 3.4 수동 입력 = 부가/고급 (R6)
- Item/Composition(성분비) 정형 입력·규칙엔진은 **"고급 입력" 별도 버튼**으로 제공(주 흐름은 업로드).

### 3.5 확정·저장·자기개선 (R5/R8)
- 승인/컨펌 → 요청건(Recommendation 묶음)·Case 저장 → 확정 HS를 면장/지식(LEARNED)로 재저장 → 이후 매칭 정확도↑.

### 3.6 쉬운 UI/UX (R7)
- **업로드 한 번 → 결과 리스트 → 승인**의 최소 단계. HS를 크게·명확히, 신뢰도 색상, 근거는 접이식, 승인 버튼 눈에 띄게. (와이어프레임=PLAN)

## 6. 기술 제약사항
- **RAG 구축 선행(최우선)**: 면장·HS 기준표(VN/KR/CN/US) 확보·적재가 정확도의 근간.
- **자유 양식 파싱**: LLM 기반 컬럼 의미 추론 + 기존 어댑터 병행. 파싱 실패 행 검토 플래그.
- **VN 기준 우선**: 매칭·답변에서 VN 우선, KR/CN/US 보조.
- **쉬운 UX**: 최소 클릭·즉시 결과·명확한 HS/승인. 접근성·모바일 고려.
- **비용/성능**: 대량 업로드=비동기(BullMQ), 프롬프트 캐싱·예산가드.
- **멀티테넌시**: 면장·지식(전역=슈퍼관리자)·요청건·확정 `ent_id` 스코핑.
- **범위 외(후속)**: 규칙엔진 고도화·외부 분류 API·증빙 자동파싱(MSDS/COA).
