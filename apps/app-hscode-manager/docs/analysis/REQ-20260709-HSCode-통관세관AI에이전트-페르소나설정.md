|---|----------|------|

| R2 | 품명만으로 부족 → **재질/성분·성분 함량비율·용도·가공단계·제조/처리방식**을 정형 입력받아 판단 | 출처 §2 분류 판단 요소 |

| R5 | **위험점수 높으면 사전심사(어드밴스 룰링) 필요 플래그 자동** → 관세사 검토 대상 분류 | 출처 §운영원칙·구현 |
| R6 | **2원 RAG 지식베이스**: ① 면장 신고이력 ② **통관 지식문서**(제도/체계·분류규칙·실무검증) | 출처 §RAG 저장 지식 |
| R7 | **확정된 추천 코드를 지식으로 재저장·재활용**(자기개선) | 사용자 지시 |
| R8 | 통관 페르소나(시스템프롬프트)·모델·규칙을 **어드민(설정)에서 엔티티별 관리** | 사용자 지시 |
| R9 | 키/코퍼스 미설정 시 **강화 기본 페르소나 + 검색 폴백** 무중단 | 기술 제약 |

> **핵심**: 목적은 자동신고가 아니라 **담당자 검토용 HS 후보 추천 + 근거 제시**. 단순 벡터검색만으론 함량·주기능·가공도 차이를 못 잡으므로 **규칙 기반 판단을 RAG/LLM과 결합**한다.

## 2. AS-IS 현황 분석

### 2.1 RAG / 코퍼스

|------|------|------|
| 코퍼스 | `hsm_hs_references` | **면장 신고이력 1종**(품명→HS). 규칙/지식 문서·사전심사·FTA 스키마 없음 |

### 2.2 AI/규칙/입력
| 항목 | 현재 |
|------|------|
| AI | `ai-classification.service.ts` 단일샷, 시스템프롬프트 **하드코딩 범용** |
| **규칙엔진** | **없음**(주성분·본질적특성·용도우선·가공도·위험점수 계산 로직 부재) |
| 입력 | 자연어/속성폼(material·usage·processing·origin·unit)/엑셀. **성분 함량비율·수출국·기존 KR/CN 코드·증빙문서·BOM 배열 없음** |
| 출력 | candidates(HS·신뢰도·근거). **"확정/검토필요"·"VN 최종확인"·사전심사 플래그 없음** |

### 2.3 어드민/저장
| 항목 | 현재 |
|------|------|

| 확정저장 | `POST /reference/entries`(이번 세션) → 신고이력 저장. **지식(LEARNED) 저장 없음** |

## 3. TO-BE 요구사항

### 3.1 파이프라인 (규칙엔진 × 2원 RAG × LLM 하이브리드)
```
[정형 입력] 품명(국/영/거래명)·수입국(VN 기본)·수출국(KR/CN)·용도·
            원재료목록(명·재질·기능)·성분비율[배열]·기존코드(KR/CN/공급사)·
            가공정보(혼합/반응/압출/성형/도포)·증빙(MSDS/COA/사양서/BOM)
   ↓ ① 규칙엔진: 주성분·본질적 특성·용도우선·가공도(원재료/반제품/완제품)·위험점수 선계산
   ↓ ② 2원 RAG(VN 우선): 신고이력 + 지식문서(규정·사례·유권해석·사전심사·FTA)
   ↓ ③ LLM(설정 통관 페르소나): 규칙결과+검색결과 결합 → VN HS 복수후보
        + 추천사유·분류근거·확인쟁점·VN 최종확인여부·"확정/검토필요"
   ↓ ④ 위험점수↑ → 사전심사 필요 플래그(관세사 검토)
   ↓ ⑤ 확정 → 신고이력 + 지식(LEARNED) 재저장·임베딩 → 재활용
```

### 3.2 정형 데이터(입력) — Feature C 확장
| 항목 | 필드 |
|------|------|
| 품명 | ko/en/trade |
| 수입국 | 기본 `VN` |
| 수출국 | `KR`|`CN` |
| 용도 | 생산용 원부자재/판매용/샘플 등(enum) |
| 원재료목록 | `[{name, material, function}]` |
| **성분비율** | `[{component, ratio}]` (합계 검증) — **배열/테이블 저장(텍스트 아님)** |
| 기존코드 | KR HS / CN HS / 공급사코드 |
| 가공정보 | 혼합/반응/압출/성형/도포(enum) — **단순혼합 vs 화학변성 구분** |
| 증빙 | MSDS/COA/사양서/카탈로그/BOM(첨부·메타) |

### 3.3 규칙엔진(신규 `RuleEngineService`)
- 입력 정형 데이터로 **주성분(최대 함량)·본질적 특성·용도우선·가공도** 계산(GRI 통칙 취지).
- **위험점수**: 함량 근소차·복합소재·용도별 분기·해석 상이 이력 등 → 임계 초과 시 `advanceRulingNeeded=true`.
- 결과를 RAG 질의 강화 + LLM 컨텍스트로 전달(결정론적 힌트).

### 3.4 지식베이스(신규 `hsm_knowledge_docs`, ent_id NULL=전역/슈퍼관리자, LEARNED=엔티티별)
| doc_type | 내용(출처 §RAG 저장 지식) |
|----------|------|
| `SYSTEM`(제도/체계) | VN HS 체계·자리수·세율조회·통관, VN 수입코드 vs HS, KR/CN HS 구조·차이, FTA HS/원산지/세번변경 |
| `RULE`(분류규칙) | HS 기본원칙(성분·가공도·산업·용도), 혼합물/복합소재(주성분·본질적특성·기능우선), 원재료/중간재/완제품 구분 |
| `CASE`(사례) | 섬유혼방·화학혼합·플라스틱복합·도료/코팅 등 품목별 사례 |
| `ADVANCE_RULING`(실무검증) | VN 사전심사 제도·사례, KR/CN 상이 적용 사례, 원산지증명·BOM·세번변경 실무지침 |
| `LEARNED`(확정 재저장) | 질의/BOM 요지 + 확정 HS + 근거 |

필드: `kd_country(VN|KR|CN|GLOBAL)`·`kd_hs_scope(Chap/Heading)`·`kd_title/body`·`kd_source`·`kd_embedding vector(1024)`. 검색: `ent_id=현재 OR NULL`(전역+LEARNED), **VN 가중**.

### 3.5 출력 계약(확장)
`{ candidates:[{ hsCode(VN 8/10), hs6, confidence, rationale(추천사유),
   basis(분류근거: 적용 규칙·사례·실적), issues(확인 쟁점),
   vnFinalCheck(VN 기준 최종확인 필요 여부), status: "CONFIRMED"|"REVIEW" }],
   advanceRulingNeeded, needQuestion, attributeKey }` — 서비스가 JSON 계약·그라운딩 강제.

### 3.6 페르소나(설정화)
- 강화 기본(코드): 베트남 수입통관 HS 분류 전문가, VN 기준·KR/CN 보조, GRI·본질적특성·함량·가공도·용도, 근거 필수·환각 금지.
- 엔티티 override: `system_prompt` + `customs_rules`(`hsm_app_settings`). 공통 규칙은 지식문서(전역)로.

## 6. 기술 제약사항
- **콘텐츠 소싱(핵심 의존성)**: 우선순위(§7) 순으로 자료 확보·적재 선행. 저작권·최신성·출처관리.
- **정형 우선**: 성분비율·용도·공정은 AI 이전 규칙엔진·검색질의 안정화의 핵심(배열 저장·용도 필수·공정 구분).
- **VN 기준 우선순위**: 검색·프롬프트·출력에서 VN 우선, 상충 시 VN 명시, KR/CN 보조.
- **출력 안정성**: 설정 프롬프트가 JSON·그라운딩 못 깨게 강제 + 폴백.
- **멀티테넌시**: 지식(전역=슈퍼관리자, LEARNED=엔티티)·설정·저장 `ent_id` 스코핑.
- **비용/성능**: 규칙 선계산으로 LLM 부담↓, 프롬프트 캐싱·`daily_budget` 가드.
- **범위 외(후속)**: 에이전트 tool-use 루프, 외부 분류 API(Zonos), 규칙 자동수집, 증빙(MSDS/COA) 자동파싱.
