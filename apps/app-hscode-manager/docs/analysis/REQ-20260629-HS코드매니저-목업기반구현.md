# HS Code Manager — 요구사항분석서 (목업 기반 실제 구현)

> 본 문서는 `hscode-manager-mockup.html`(SCR-001~005)을 **구현 기준 화면**으로 삼고, `docs/design/` 설계문서 8종을 참조하여 **실제 구현을 위한 현황 기반 요구사항**을 정리한다. 설계 단계 산출물(요구사항정의서 FR-xxx, 기능정의서 FN-xxx)을 구현 관점으로 재정렬하고, 코드/스키마/스캐폴드의 실제 AS-IS와 대조하여 갭을 도출한다.

## 0. 확정 전제 (Decision Log)

| # | 결정 사항 | 선택 | 영향 |
|---|-----------|------|------|
| D-1 | DB 엔진 | **PostgreSQL 15 + pgvector** (설계문서 ERD/DDL 기준) | hsm_ 스키마·JSONB·`gen_random_uuid()`·`TIMESTAMPTZ`·벡터 인덱스 그대로 사용. 플랫폼 표준 MySQL과 분리 운영(아래 §6 위험) |
| D-2 | 구현 범위 | **MVP 우선 (Feature A + Feature C + 참조 Import + 결과 상세)** | Feature B(바코드)는 L1 직접매핑·체크디지트까지만, 외부 L2(GS1)/L4(AI) 레이어는 후속 Phase |
| D-3 | AI/외부 스택 | **Claude `claude-sonnet-4-6` + 기존 어댑터(VN-bieu-thue/KR-customs)** (`.env` 기준) | L4 AI 분류 폴백·명확화 질문 생성에 Claude 사용. GS1/Zonos/Pitney Bowes는 후속 옵션으로 명시 |

> **임베딩 공급자 [TBD]**: 의미검색(FR-002)은 pgvector에 저장된 임베딩이 필요하다. Claude는 텍스트 생성용이며 임베딩 API가 아니므로, **다국어(KR/EN→VI) 임베딩 모델**(예: multilingual-e5 / Cohere multilingual / OpenAI text-embedding-3)을 별도로 선정해야 한다. MVP는 임베딩 인프라 확정이 선행 조건이다. (§6, Phase 0)

## 2. AS-IS 현황 분석

### 2.1 결론 요약
`apps/app-hscode-manager/`는 **소스 부재 그린필드** 상태이며, 과거 빌드 산출물(`dist/`)만 남아 있다. 그 `dist/`는 **목업/설계문서와 다른 별개 설계 계보**를 컴파일한 것이어서 재사용 대상이 아니다. 따라서 본 구현은 **목업(SCR-001~005) + hsm_ 설계문서 계보**에 맞춘 **신규 풀스택 구현**이다.

### 2.2 프론트엔드 현황
| 항목 | 현황 | 근거 경로 |
|------|------|-----------|
| 소스 | **없음** (`frontend/src` 비어 있음) | `frontend/` 하위 `src` 미존재, `tsconfig.tsbuildinfo`만 잔존 |
| 빌드 산출물 | 과거 빌드 `dist/index.html` + `dist/assets/`만 존재 | `frontend/dist/` |
| i18n | 미구현. **단, 목업에 ko/en/vi 전체 사전 내장** (재사용 가능) | `mockup.html` `I18N{ko,en,vi}` 객체 (약 90키) |
| 평가 | 목업 화면 5종에 대응하는 React 페이지/컴포넌트 전무 → 전면 신규 | — |

### 2.3 백엔드 현황
| 항목 | 현황 | 근거 경로 |
|------|------|-----------|
| 소스 | **없음** (`backend/src` 비어 있음) | `backend/` 하위 `src` 미존재 |
| 빌드 산출물 | **다른 설계 계보**의 컴파일 결과만 존재 | `backend/dist/domain/*` |
| dist 도메인 모델 | item·classification·inquiry·verification·expert-review·master-country·master-fta·master-exporter·master-data-source·matching·intake·external(ai-claude/adapter-vn-bieu-thue/adapter-kr-customs)·admin·audit-log | `backend/dist/domain/` 트리 |
| 설계문서 계보와의 관계 | **불일치** — 목업/ERD의 `hsm_*`(GTIN 4계층, gpc/country-ext) 모델과 도메인 구성이 상이 | ERD `hsm_gtin_hs_maps` 등 vs dist `classification/item` |
| 인증 스캐폴드 | `auth/`(jwt.strategy, entity-scope.guard, role.guard, @Auth/@Public/@Roles 데코레이터) 컴파일본 존재 → 패턴 참고용 | `backend/dist/auth/` |
| 공통 | `common/`(api-response.dto, pagination.dto, error-codes, global-exception.filter, normalizer/keywords util) 컴파일본 존재 → 패턴 참고용 | `backend/dist/common/` |
| 평가 | dist는 **재사용 불가(소스 없음, 모델 불일치)**. auth/common **패턴**만 신규 소스 작성 시 참고 | — |

**TO-BE 추가 (DDL 보강 필요)**:

- **신규 `hsm_app_settings`** (SCR-006 어드민/설정, R-18): `ent_id`별 AI/외부 API/임베딩/임계치/캐시 설정 저장. 컬럼 예: `aps_id` PK, `ent_id`, `aps_category`(AI/EXTERNAL/EMBEDDING/THRESHOLD/CACHE), `aps_key`, `aps_value`(암호화 대상=API 키), `aps_is_secret`, `aps_updated_by`, `aps_created_at/updated_at`. 비밀값은 암호화 저장(평문 노출 금지).

> **RAG 관점 (중요)**: 참조(Reference)로 적재된 코퍼스(`hsm_hs_references`)는 단순 조회 테이블이 아니라 **검색 증강 생성(RAG)의 지식 소스**다. Feature A(질문식)·Feature C(속성/엑셀)의 분류는 ① 입력 임베딩으로 pgvector ANN 검색 → ② 상위 참조 행을 컨텍스트로 회수(retrieve) → ③ (모호 시) Claude가 컨텍스트 기반으로 명확화/판정. 즉 참조 데이터 품질·임베딩 정합성이 분류 정확도(NFR-003)를 직접 좌우한다.
