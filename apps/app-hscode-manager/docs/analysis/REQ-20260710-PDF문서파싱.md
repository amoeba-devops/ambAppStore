# 요구사항분석서 — 문서 업로드 매칭 PDF 파싱

- 문서 ID: REQ-20260710-PDF문서파싱
- 작성일: 2026-07-10
- 대상: HS Code Manager `/app-hscode` — 문서 업로드 매칭(Phase 2)
- 선행: 대량 비동기(BullMQ) 완료(#101), 프로덕션 유효 Claude 키 활성

## 1. 요구사항 요약
| # | 요구사항 | 유형 |
|---|----------|------|
| R1 | 문서 업로드 매칭에서 **PDF 파일** 분석 지원(현재 400 거부) | 필수 |
| R2 | PDF에서 품목(품명·성분·용도·수량) 추출 → 기존 매칭 파이프라인에 투입 | 필수 |
| R3 | 스캔본(이미지 PDF)도 처리(면장·인보이스 스캔) | 필수 |
| R4 | 추출 실패/모호 행은 검토필요 플래그(무단 폐기 금지) | 필수 |
| R5 | 유효 Claude 키 필요 — 미설정 시 명확한 안내(무크래시) | 필수 |
| R6 | 비용·용량 보호(페이지/토큰 상한, 예산 인지) | 필수 |

## 2. AS-IS 현황
- `DocumentParserService.parse`가 `.pdf` 확장자면 **명시적 400**:
  `"PDF parsing is not yet available. Please upload an Excel/CSV file."`
- 엑셀/CSV는 SheetJS로 처리(#100), 매칭은 비동기(#101).
- 통관 문서 상당수가 PDF(세관 출력 면장, 공급사 인보이스/패킹리스트, 스펙시트/MSDS) → 현재는 사용자가 수작업 엑셀 변환 필요.

## 3. TO-BE
```
업로드(.pdf) → DocumentParserService.parsePdf
  → 유효 Claude 키 확인(없으면 400 안내)
  → Claude 문서 입력(Anthropic document 블록, base64 PDF) + 추출 프롬프트
     → JSON {items:[{name,material,usage,quantity}]} (표/스캔 모두 비전으로 이해)
  → ParsedItem[] 정규화(품명 없는 행 검토필요)
  → 기존 uploadAndEnqueue(품목 생성→BullMQ 워커 매칭) 그대로
```
- **방식 = Claude 문서 입력**: 유효 키가 이미 있으므로 OCR 인프라 불필요, 텍스트+스캔 PDF 동시 커버.
- 추출은 업로드 요청 내 1회 Claude 호출(품목 매칭은 기존 비동기).
- 엑셀/CSV 경로·매칭·승인/저장 무변경.

## 4. 갭 분석
| 영역 | 현재 | 변경 | 영향 |
|------|------|------|------|
| PDF 처리 | 400 거부 | Claude 문서입력 추출 | 높음(신규 경로) |
| 파서 | xlsx/csv만 | + parsePdf 분기 | 중 |
| 키 의존 | AI 컬럼추론 선택적 | **PDF는 키 필수** | 중(안내 필요) |
| 비용 | 없음 | PDF 추출 1콜/업로드(토큰↑) | 중(상한·예산) |

## 5. 사용자 플로우
```
PDF 업로드 → "분석 중" → (키 있으면) 품목 추출 → 즉시 요청건(PROCESSING) → 진행률 → 결과
키 없으면 → "PDF 분석은 AI 설정(Claude 키)이 필요합니다" 안내
```

## 6. 기술 제약
- Anthropic document 블록: base64 PDF, 페이지/용량 한도(대략 ≤100p, ≤32MB) — 초과 시 명확한 400. 상한 페이지만 처리 시 note.
- 스캔 화질 낮으면 추출 오류 → 검토필요(R4).
- 예산 가드/최대 출력 토큰 상한(R6).
- **동기 추출**: 업로드 요청 내 1회 호출(대형 PDF는 수 초~수십 초) — 매우 큰 PDF의 추출 비동기화는 후속.
- 범위 외(후속): PDF 표 좌표 기반 정밀 파싱, 페이지별 분할 비동기 추출, 증빙(MSDS) 전용 스키마.
