### 2.6 문제점/공백 요약

1. 지식창고(게시판) 도메인·테이블·페이지·서비스가 **전무** → 전 계층 신규 구현 필요.

### 3.4 비즈니스 로직 — 권한/테넌시

- **읽기**(목록/상세/검색/다운로드/번역요청): `@Auth()` — 일반 사용자(USER_LEVEL) 허용.
- **쓰기**(게시글 CRUD, 대시보드 편집, 카테고리·태그·파일 업로드, RAG 승격): `@AdminOnly()` (ADMIN_LEVEL). 원천 A3 확정 = Cell 세분화 없음.
- **테넌시 결정 필요(C-6)**: 국가 HS 기준표·HS 상식은 표준 참조 → **(권장) 전 테넌트 공용(`ent_id NULL` + 쓰기 `@SuperAdminOnly()`)**, 단 원천 NFR-KB-001은 "모든 테이블 `ent_id` + OwnEntityGuard"를 명시. 두 정책이 상충하므로 **컬럼은 `ent_id` 보유(nullable)**하되, 공용/테넌트 여부를 `hsm_documents` 패턴(NULL=전역)과 동일하게 운용하는 것을 권장안으로 제시. 최종 확정 전까지 구현 착수 금지 항목.

### 3.5 RAG 승격 브릿지 (FR-KB-014)

```
hsm_kb_posts (큐레이션된 게시글)
   │  관리자 "RAG 코퍼스로 승격" 클릭 (SCR-KB-03, @AdminOnly)
   ▼
POST /api/v1/knowledge-base/posts/:postId/promote-to-rag
   │  KB Service → KnowledgeIngestService.ingest(...) 호출 (Repository 직접 import 금지, §2.2)

hsm_documents 신규 행 생성(doc_type/doc_title/doc_summary…) → 청킹·임베딩(hsm_doc_chunks)은 knowledge 도메인 책임
   ▼
hsm_documents.doc_id ──저장──▶ hsm_kb_posts.pst_promoted_doc_id, pst_is_promoted_to_rag = true (단방향)
```

- **Backend(신규)**: `domain/knowledge-base/` 하위 entity 7 · dto(request/response) · mapper · service · controller · `knowledge-base.module.ts`; `app.module.ts`(수정, 모듈 등록).
- **DB(신규)**: `sql/migrations/20260710-knowledge-base.sql`.
- **Frontend(신규)**: `pages/KnowledgeBaseDashboardPage.tsx`·`KnowledgeBaseListPage.tsx`·`KnowledgeBaseDetailPage.tsx`·`KnowledgeBasePostEditPage.tsx`·`KnowledgeBaseAdminPage.tsx`; `services/knowledge-base.service.ts`; `router.tsx`·`App.tsx`(수정).
- **i18n(신규/수정)**: `locales/id/` 신규, `i18n.ts`(id 등록), KB 키 4언어 추가.

### 4.3 DB 마이그레이션 전략

- 방식: 기존과 동일 — `synchronize` 비활성, `sql/migrations/20260710-knowledge-base.sql` **수동 적용(스테이징 먼저)**.

- 배포: `deploy-staging.sh` 경유(직접 `docker compose build` 금지).

## 5. 사용자 플로우

```
[일반 사용자 USER_LEVEL]
  지식창고 진입(SCR-KB-01) → 카테고리 바로가기/최신/인기 확인
     │
     ├─ 검색어/필터 입력 → 목록(SCR-KB-02) → 게시글 상세(SCR-KB-03)
     │      └─ 번역박스에서 대상언어 선택
     │            ├─ 캐시 HIT → 저장된 번역 표시
     │            └─ 캐시 MISS → Claude 번역 → hsm_kb_post_translations 저장 → 표시
     │      └─ 첨부 다운로드(≤50MB, 화이트리스트)
     │
[관리자 ADMIN_LEVEL] — 위 전체 + 편집
     ├─ 대시보드 [편집] 토글 → 공지 인라인 추가/삭제, 팁 카드 드래그 정렬(dsb_sort_order 저장)
     ├─ 게시글 작성/수정(SCR-KB-04) → 단일언어 작성 + 파일 업로드 → 저장(Soft Delete 지원)
     ├─ 카테고리/태그 관리(SCR-KB-05)
     └─ 게시글 상세 → [RAG 코퍼스 승격] → hsm_documents 생성 + pst_promoted_doc_id 역저장(단방향)
```

분기 조건:
- 권한: 편집 UI/버튼은 ADMIN_LEVEL에만 노출·동작(USER_LEVEL 숨김). 전역 공용 KB 채택 시 쓰기 = `@SuperAdminOnly()`(§3.4).
- 첨부 검증: `size>50MB` 또는 확장자 비화이트리스트 → KB 신규 에러범위(예: `HSC-E8001` 크기 초과 / `HSC-E8002` 포맷 위반) 거부. ※ 범위는 작업계획서에서 확정.
- 번역: `ptr_source=MANUAL` 존재 시 AI 번역으로 덮어쓰지 않음(NFR-KB-003).

## 6. 기술 제약사항

| 구분 | 제약 |
|------|------|
| 호환성 | PostgreSQL 15 + pgvector 유지. TypeORM nullable 컬럼 명시 `type:` 필수(`DataTypeNotSupportedError` 방지). 기존 12개 도메인·라우트 무영향 원칙. |
| 성능 | 통합 검색 다국어 토큰화(ko/en/vi/id) — PostgreSQL FTS 언어별 설정 조기 검증, 미흡 시 `pg_trgm` 폴백. 50MB 업로드는 스트리밍 처리(메모리/타임아웃 주의). 번역은 (pst_id, target_lang) 캐시로 read-time 재호출 최소화. |
| 보안/격리 | 전역 인증 가드(AMA JWT SSO). 읽기 `@Auth()`, 쓰기 `@AdminOnly()`. 멀티테넌시 `ent_id` — 전역/테넌트 정책 §3.4 결정. RAG 브릿지는 Service 경유(도메인 직접참조 금지). |
| i18n | id 추가는 전역 i18n 리소스 확장 — 기존 hscode 네임스페이스 3언어 회귀 없음 확인. UI 텍스트 하드코딩 금지. |
| 첨부 저장소 | 오브젝트 스토리지 미도입 상태 → 저장 매체 확정 필요(C-5). DB는 경로만 저장. |
