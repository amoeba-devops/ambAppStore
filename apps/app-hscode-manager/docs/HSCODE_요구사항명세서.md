# HS Code Manager — 요구사항 명세서 (SRS)

> 범위: 카고러시(베트남 물류통관)의 원부자재 HS코드 매칭 앱이 만족해야 하는 기능·비기능·데이터·인터페이스 요구사항.
> 전제 문서: 「HSCODE_설계문서」(개념·정책·DB 스키마), 「HSCODE_이벤트시나리오」(흐름).
> 작성 기조: 개념과 설계 수준에 머무른다. 화면 픽셀, 코드 인터페이스의 상세 시그니처, 인프라 구성은 별도 단계에서 다룬다. 각 요구는 *왜 필요한가*를 함께 적는다 — 시스템이 자라면서 가지치기할 때의 판단 근거가 된다.

---

## 1. 시스템 개요

### 1.1 목적

카고러시 담당자가 고객사(수출업체)로부터 받은 **원부자재 속성 정보(재질·성분·구성·기능·용도)**를 등록하면, 시스템이 *내부 누적 데이터*와 *베트남 관세청 등 외부 권위 데이터*를 검색하고 *AI(Claude 등)의 해석*을 결합해 베트남 수입에 적합한 HS코드 후보를 제시한다. 담당자가 후보 중 하나를 컨펌하면 그 결정이 *수출업체·수출국가·날짜*를 키로 누적되어 다음 매칭 작업의 1순위 참조 자료가 된다. 시스템의 목표는 *반복적인 분류 작업의 정확도와 일관성을 시간이 지날수록 자동으로 개선*하는 것이다.

### 1.2 범위

본 시스템의 범위 안에는 (a) 속성 정보의 다채널 등록(엑셀/직접/바코드 보조), (b) 내부·외부·AI 3단 검색 추천, (c) 사용자 컨펌과 영속화, (d) 사후 검증·피드백 루프, (e) 에스컬레이션과 전문가 검토가 포함된다. 범위 밖에는 (a) 실제 통관 신고서 작성·제출, (b) 결제·정산, (c) 화물 추적, (d) 고객사 회계 시스템 연동이 있다.

### 1.3 사용자

주 사용자는 **카고러시 담당자**다. 보조 사용자로 **전문가**(Mr. Nguyen 현지 통관사 / Ms. Hau 내부 전문가)와 **관리자**가 있다. 고객사(수출업체)는 본 시스템의 직접 사용자가 아니라 *데이터 제공자*다.

### 1.4 외부 시스템

베트남 BIEU THUE XNK 2026, 한국 관세청 HS 조회, FTA 협정세율 테이블, AI 추론 서비스(Claude 등). 이메일·메신저 채널은 입출력 보조다.

## 2. 이해관계자와 가치 흐름

## 3. 기능 요구사항 (Functional Requirements)

요구사항은 모듈 단위로 묶고, ID 체계는 `FR-{모듈}-{번호}`로 둔다. *우선순위*는 M(Must) / S(Should) / C(Could) 3단계로 표기한다. 각 요구의 끝에는 「이벤트 시나리오」의 대응 이벤트를 괄호로 인용한다.

### 3.1 입력(IN) — 다채널 등록

**FR-IN-01 (M)** 사용자는 고객사(수출업체)·수출국가를 지정한 `Inquiry` 단위로 작업을 시작할 수 있어야 한다. *왜*: 영속화 키 `(수출업체, 수출국가, 등록일자)`의 두 축이 진입 시점에 확정되어야 누적 자산이 생긴다. (E1)

**FR-IN-02 (M)** 시스템은 세 가지 입력 채널을 제공해야 한다 — 엑셀 일괄 등록, 앱 내 직접 입력, 바코드 스캔(기성품 보조). *왜*: 고객사 자료 형태가 다양하다. 단일 채널 강제는 운영을 막는다. (E2)

**FR-IN-03 (M)** 엑셀 일괄 등록은 헤더 기반 컬럼 매핑을 지원하고, 표준 템플릿을 다운로드 제공해야 한다. *왜*: 고객사마다 시트 구조가 다르므로 매핑은 사용자 통제 아래 둔다. (E3-a)

**FR-IN-04 (M)** 엑셀 행별 검증에서 실패한 행은 입력 큐가 아닌 *보류 큐*로 분리되어, 사용자가 인앱에서 수정·재검증할 수 있어야 한다. *왜*: 부분 성공을 막으면 사용자는 결국 엑셀을 시스템 밖에서 고치게 되며 정합성이 사라진다. (A1)

**FR-IN-05 (M)** 직접 입력은 카테고리(`chemical | steel_mechanical | equipment | other`) 선택에 따라 필수 속성 필드가 동적으로 바뀌어야 한다. *왜*: 화학물질의 CAS와 철강의 두께는 같은 폼에 둘 수 없다. (E3-b, 「설계문서」§4.2)

**FR-IN-06 (S)** 바코드 스캔으로 GTIN이 추출되면 ERP의 Item을 1차 조회해, 매칭된 경우 폼을 프리-필해야 한다. *왜*: 기성품은 드물지만 발생하며, 발생 시에는 입력 단계를 단축할 수 있다. (E3-c, A6)

**FR-IN-07 (M)** 입력 완성도 점수(`intake_completeness_score`)가 0.7 미만이면 분류 단계로의 진행은 *연성 차단(soft block)*되어야 하며, 강제 진행 시 사유 기록이 강제되어야 한다. *왜*: 정보 부족이 추징의 가장 흔한 원인이다. (E4 사전 검사, 「설계문서」§4.3)

**FR-IN-08 (S)** 결정적 속성이 결손된 경우(예: 화학물질의 CAS 미입력) 시스템은 *추가 정보 요청 양식*을 자동 생성해 담당자에게 노출해야 한다. *왜*: 무엇을 더 받아야 하는지 사람이 매번 떠올리지 않아도 되게 한다. (A4)

### 3.2 정규화·매칭(MA)

**FR-MA-01 (M)** 시스템은 입력 속성을 정규화해 *속성 정규화 해시(`composition_hash`)*를 산출해야 한다. 카테고리별 정규화 규칙은 별도 명세로 관리한다. *왜*: 해시가 일치하면 검색을 우회할 수 있다 — 누적의 본질적 가치. (E4)

**FR-MA-02 (M)** 시스템은 검색을 다음 우선순위로 수행해야 한다 — (1) 동일 수출업체·수출국가의 과거 채택 코드, (2) 동일 수출국가의 과거 채택 코드, (3) 속성 유사도 fuzzy 매칭, (4) 외부 권위 데이터. *왜*: 내부가 충분하면 외부를 부르지 않는다. 비용·지연·환각을 줄인다. (E5)

**FR-MA-03 (M)** 내부 매칭 신뢰도가 0.85 이상이면 외부 검색과 AI 추천은 *생략될 수 있어야* 한다. 단, 마지막 채택일이 12개월을 초과했거나 동일 코드에 추징 이력이 있으면 생략하지 않는다. *왜*: 신선도·위험도 게이트 없이 누적만 믿으면 시스템이 변화에 둔감해진다. (A2)

**FR-MA-04 (M)** 외부 검색은 베트남 *BIEU THUE XNK 2026*을 1차 권위, 한국 관세청을 보조로 둔다. FTA 협정세율은 별도 테이블에서 보강한다. *왜*: 베트남 수입이므로 수입국 권위가 1차다. (E6)

**FR-MA-05 (S)** 외부 데이터는 캐시되어야 하며, 외부 API 장애 시 캐시로 fallback 진행하되 신뢰도에 −0.2 페널티를 부여해야 한다. *왜*: 통관 업무는 멈추면 안 된다. 그러나 데이터 신선도 저하는 의사결정에 반영되어야 한다. (X2)

### 3.3 AI 추천(AI)

**FR-AI-01 (M)** 시스템은 정규화 속성·내부 후보·외부 검색 결과를 컨텍스트로 묶어 LLM에 전달하고, *검색된 후보 범위 내에서만* HS코드를 제안하도록 제약해야 한다. *왜*: AI 환각으로 존재하지 않는 코드가 추천되면 신뢰가 무너진다. (E7)

**FR-AI-02 (M)** AI는 각 후보에 대해 *분류 근거(어떤 속성이 어떤 호와 매칭되는가)*를 자연어로 생성해야 하며, 이 근거는 컨펌 시 영속화되어야 한다. *왜*: 사후에 "왜 이 코드였나"를 답할 수 있어야 한다. 책임 추적의 일급 자산. (E7, FR-DA-03)

**FR-AI-03 (M)** AI 추천이 실패하거나 형식적으로 부적합한 경우 시스템은 *AI 결과를 폐기하고 외부 검색 결과만으로* 후보를 구성해야 하며, 사용자에게 "AI 추천 미반영"을 표시해야 한다. *왜*: AI 의존이 단일 실패점이 되면 안 된다. (X3)

**FR-AI-04 (S)** 사용자는 작업별로 *AI 추천을 끄는 옵션*을 가져야 한다. *왜*: 검증·교육·정책상의 이유로 외부 자료만 보고 결정해야 할 때가 있다. (A7)

**FR-AI-05 (C)** AI 추천 모델·프롬프트·가드레일 변경 이력은 버전 태그로 관리되어, 영속화된 추천 근거에 *어떤 버전의 추천이었는지* 함께 저장되어야 한다. *왜*: 시간이 지나면서 모델 변경이 발생할 때, 과거 결정을 재현하려면 모델 버전이 필요하다.

### 3.4 컨펌·영속화(CO)

**FR-CO-01 (M)** 사용자는 추천 리스트에서 1건을 선택해 컨펌할 수 있어야 한다. 컨펌은 `Classification.status`를 `proposed → adopted`로 전환한다. (E10)

**FR-CO-02 (M)** 사용자가 동일 수출업체·수출국가의 가장 최근 채택 코드와 *다른* 후보를 선택한 경우, 선택 사유 입력은 강제되어야 한다. *왜*: 정책이 바뀐 것인지 일회성 예외인지 구분할 수 있어야 학습이 된다. (A5)

**FR-CO-03 (M)** 컨펌 시 다음이 함께 영속화되어야 한다 — 입력 속성, 정규화 해시, 내부 후보 목록, 외부 검색 결과 출처, AI 추천 후보·근거, 사용자 선택 항목·사유, 수출업체·수출국가·등록일자. *왜*: 사후 검증·학습·재현 가능성의 기반. (E12, FR-DA-02)

**FR-CO-04 (M)** 동일 `(수출업체, 수출국가, composition_hash, 등록일자)` 중복이 감지되면 시스템은 *기존 갱신*과 *신규 생성* 중 사용자에게 선택을 요구해야 한다. 갱신 시 기존은 `superseded`로 전환된다. *왜*: 중복 자체를 막으면 정정이 어렵고, 무조건 신규를 만들면 누적이 오염된다. (X6)

**FR-CO-05 (M)** `Classification`은 한 번 `adopted` 이상이 되면 *불변에 가깝게* 다뤄져야 한다. 정정 시 새 레코드를 만들고 기존을 `superseded` 처리한다. *왜*: "그때 무어라고 했는가"의 재현 가능성, 회계의 분개 원칙. (「설계문서」§3.3)

### 3.5 조회·재사용(QU)

**FR-QU-01 (M)** 새로운 매칭 작업이 시작되면 시스템은 입력 속성에 대해 *내부 누적을 가장 먼저* 조회해야 한다. *왜*: 본 앱이 가치를 만드는 방식의 핵심. (E5)

**FR-QU-02 (M)** 사용자는 `(수출업체, 수출국가, 기간, 카테고리, HS코드, 키워드)` 임의 조합으로 누적 분류를 조회할 수 있어야 한다. *왜*: 운영 중 가장 흔한 정보 요구. (FR-DA-04 보조 인덱스 전제)

**FR-QU-03 (S)** 시스템은 *추천 히트율*(추천 1순위가 컨펌된 비율)을 사용자·기간·카테고리별로 집계해 보여줘야 한다. *왜*: 누적의 효과를 사용자가 체감할 수 있어야 시스템이 더 잘 쓰인다.

### 3.6 사후 검증·피드백(VR)

**FR-VR-01 (M)** 시스템은 세 종류의 `VerificationEvent`를 수용해야 한다 — 샘플 분석 결과, 세관 추징 발생, 세관 더블체크 결과. *왜*: 분류의 정답을 사후에 받지 않으면 시스템은 학습할 수 없다. (「설계문서」§2.3)

**FR-VR-02 (M)** 추징 발생 시 해당 `Classification`은 `disputed`로 전환되고, *동일 코드를 사용한 다른 모든 Item이 자동으로 재검토 큐에 적재*되어야 한다. *왜*: 한 건의 추징은 같은 패턴 추징의 예고. (「설계문서」§2.3)

**FR-VR-03 (S)** 정정·추징·확인 이벤트는 월간 KPI(추징률·정정률·세관확인률) 대시보드의 입력이 되어야 한다. *왜*: 정책 임계값을 6개월 단위로 재교정하기 위한 근거. (「설계문서」§2.2 끝)

### 3.7 에스컬레이션(ES)

**FR-ES-01 (M)** 다음 6개 트리거 중 하나라도 해당하면 M3 전문가 검토가 자동 발동되어야 한다 — (a) 신뢰도 < 0.6, (b) 후보 ≥ 3개로 분기, (c) 수입금지·제한 키워드 매칭, (d) 동일 품목 과거 추징 이력, (e) 고객사 명시 요청, (f) 거래 금액 임계 초과. (「설계문서」§2.4)

**FR-ES-02 (M)** 라우팅 대상은 규제 플래그에 따라 결정되어야 한다 — 베트남 현지 규제→Mr. Nguyen, 사내 분류 정책·FTA 원산지→Ms. Hau, 둘 다 걸리면 병렬. *왜*: 권위가 다른 영역을 합쳐서 한 사람에게 보내면 검토 품질이 떨어진다. (「설계문서」§2.1)

**FR-ES-03 (M)** 에스컬레이션 중인 건은 M4 응대 단계로 진행되지 않아야 한다(blocking). *왜*: 전문가 회신 전에 응대가 나가면 분쟁의 시발점이 된다.

### 3.8 관리·통계(AD)

**FR-AD-01 (M)** 관리자는 사용자·권한, 정책 임계값(신뢰도 컷오프·세율 격차 임계·금액 임계), 에스컬레이션 라우팅 룰을 인앱에서 변경할 수 있어야 한다. *왜*: 환경이 바뀔 때마다 코드를 고치면 운영이 마비된다.

**FR-AD-02 (S)** 관리자는 추징·정정·세관확인 이벤트의 월간 추세를 대시보드로 볼 수 있어야 한다. (FR-VR-03 보조)

**FR-AD-03 (S)** 외부 API·AI 추천 호출의 *성공률·지연·비용*을 운영 지표로 제공해야 한다. *왜*: 누적이 늘수록 외부 호출은 줄어야 한다 — 그 추세를 모니터링하기 위함.

## 4. 비기능 요구사항 (Non-Functional Requirements)

### 4.1 성능(PF)

**NFR-PF-01 (M)** 내부 매칭(E5) 결과는 *90백분위 1.5초 이내*에 사용자에게 보여야 한다. *왜*: 입력→매칭 루프가 빠르지 않으면 누적의 가치가 체감되지 않는다.

**NFR-PF-02 (S)** 외부 검색·AI 추천을 포함한 전체 추천 응답은 *90백분위 8초 이내*. 그 이상은 단계별 진행 표시와 함께 점진 노출되어야 한다.

**NFR-PF-03 (M)** 엑셀 일괄 등록은 1,000행 이하에서 *동기 처리*, 초과는 *비동기 배치*로 처리한다.

### 4.2 가용성(AV)

**NFR-AV-01 (M)** 외부 데이터 소스나 AI 추천이 미응답이어도 시스템은 *내부 데이터만으로 동작*해야 한다(degraded mode). (X2, X3)

**NFR-AV-02 (S)** 평일 업무 시간(베트남/한국 공통) 가용률 99.5%.

### 4.3 보안(SE)

**NFR-SE-01 (M)** 고객사·수출업체 데이터는 *수출업체 단위 권한*으로 격리되어야 한다. (X4)

**NFR-SE-02 (M)** 컨펌 이력은 *감사 로그*로 별도 누적되어야 하며, 사용자/시각/IP/입력·출력 핵심 필드를 포함한다. *왜*: 추징·분쟁 시 책임 추적.

**NFR-SE-03 (M)** AI 추천 시 외부 모델로 *기밀 분류 데이터*가 노출되지 않도록 마스킹 규칙을 둔다(예: 고객사명 토큰 치환).

### 4.4 데이터 정합성(DI)

**NFR-DI-01 (M)** Classification의 불변성 원칙(FR-CO-05) 위반은 시스템 수준에서 차단되어야 한다.

**NFR-DI-02 (M)** GTIN·composition_hash 등 식별성을 가지는 키는 *유일성 제약과 quarantine 정책*을 가져야 한다(예: 동일 GTIN 복수 Item 매핑 감지 시 quarantine).

### 4.5 확장성·유지보수성(EM)

**NFR-EM-01 (S)** 카테고리(`chemical | steel_mechanical | equipment | other`)의 추가·세분화는 *스키마 변경 없이 설정*으로 가능해야 한다(예: 카테고리별 필수 필드를 메타데이터화).

**NFR-EM-02 (S)** AI 추천 프롬프트·모델·가드레일은 *코드 배포 없이* 운영 측에서 교체 가능해야 한다(FR-AI-05의 운영 측면).

### 4.6 다국어(LO)

**NFR-LO-01 (M)** UI 기본은 한국어, 베트남어·영어를 표시 가능하도록 한다(우선순위 한>베>영). *왜*: 사용자(카고러시 한국인 담당자), 검증(베트남 전문가), 외부 자료(영문) 혼재.

## 5. 데이터 요구사항

### 5.1 핵심 엔티티

「설계문서」§3.1의 5개 엔티티(Item, Inquiry, Classification, ExpertReview, VerificationEvent)와 그 보조(ClassificationCandidate)를 그대로 채택한다. 본 명세에서 추가·변경되는 항목은 다음과 같다.

**DR-01 (M) Inquiry 보강** — `exporter_id`(수출업체 FK), `export_country_code`(ISO 3166-1 alpha-2), `submitted_at`(등록일자) 컬럼을 필수로 둔다. *왜*: 영속화 보조 키 `(수출업체, 수출국가, 등록일자)`의 정의 자체.

**DR-02 (M) Classification 보강** — `recommendation_source`(internal | external | ai | mixed), `ai_reasoning`(text), `ai_model_version`(text nullable), `external_sources`(JSON, 인용 출처 목록), `selection_rationale`(text)를 추가한다. *왜*: 사후 재현·책임 추적.

**DR-03 (M) Exporter 마스터 신설** — `exporter_id`, `name`, `country_code`, `aliases`, `risk_flags`(JSON). *왜*: 수출업체별 누적이 본 앱의 일급 검색 축이다.

**DR-04 (M) ExcelImportBatch 신설** — 엑셀 일괄 등록의 배치 단위 추적. `batch_id`, `inquiry_id`, `total_rows`, `failed_rows`, `hold_rows`(보류 큐로 분리된 행), `mapping_snapshot`(JSON), `imported_at`.

**DR-05 (S) AIRecommendationLog 신설** — AI 호출 1회의 입력 컨텍스트·출력·모델 버전·지연·비용을 보존. `log_id`, `classification_id` (nullable, 컨펌 전에는 미연결), `prompt_hash`, `model_version`, `latency_ms`, `cost_usd`, `payload_blob_uri`.

### 5.2 인덱스·검색 전략

「설계문서」§3.2의 세 인덱스(trigram name_normalized / hs_code 역색인 / 추징 부분 인덱스)에 더해 다음을 추가한다.

**DR-06 (M)** `Inquiry.(exporter_id, export_country_code, submitted_at desc)` 복합 인덱스. *왜*: 본 앱의 가장 잦은 조회 패턴.

**DR-07 (M)** `Item.composition_hash` 인덱스. *왜*: 해시 기반 즉시 매칭이 1순위 검색 경로.

### 5.3 보존·삭제 정책

**DR-08 (S)** Classification·VerificationEvent는 *영구 보존*. Inquiry 원본 첨부(엑셀·이미지)는 5년 보존 후 익명화 보관(개인정보·민감정보 제거).

**DR-09 (S)** AIRecommendationLog의 `payload_blob_uri` 실제 콘텐츠는 90일 후 요약본만 남기고 삭제 가능. *왜*: 비용과 개인정보 노출을 같이 통제.

## 7. 제약사항 및 가정

**CN-01** 수입국은 베트남이 기본이다. 다른 수입국 확장은 별도 검토.

**CN-02** AI 추천은 *최종 결정자가 아니다*. 모든 컨펌은 사람의 행위로만 발생한다.

**CN-03** 본 시스템은 통관 신고 자체를 수행하지 않는다. 결과물은 응대 양식과 분류 기록까지다.

**AS-01** 베트남 BIEU THUE XNK 2026 데이터는 분기 단위로 갱신될 수 있다고 가정한다. 갱신 알림이 없으면 분기 첫째 주에 수동 점검.

**AS-02** 고객사가 제공하는 엑셀의 컬럼 명칭은 정형화되어 있지 않다고 가정한다(헤더 매핑이 필요한 이유).

**AS-03** 사용자는 베트남 통관 도메인 지식을 가진 카고러시 직원이라고 가정한다. UI 텍스트는 도메인 용어를 사용해도 무방하다.

## 9. 우선순위 요약과 다음 단계

본 명세의 Must 항목만 만족해도 *최소 운영 가능 시스템(MVP)*이 성립한다. Should는 누적이 쌓이기 시작한 시점에 가치가 살아나는 항목이고, Could는 운영이 안정된 후의 정교화다. MVP 범위는 다음과 같이 압축할 수 있다.

> **MVP 핵심**: 엑셀/직접 입력 → 내부·외부 검색 → AI 추천(가드레일 포함) → 사용자 컨펌(사유 기록 포함) → 수출업체·국가·날짜 키 영속화 → 다음 작업 시 내부 우선 조회.

다음 단계 설계 작업은 다음 순서를 권한다.

1. **속성 정규화 규칙 명세** — 카테고리별 정규화·해시 산출 알고리즘
2. **엑셀 템플릿 및 헤더 매핑 규칙** — 보류 큐 운영 정책 포함
3. **AI 추천 프롬프트 가드레일** — 후보 범위 제약, 환각 방지, 출처 인용 강제
4. **권한 모델** — 수출업체 단위 격리, 관리자/전문가/담당자 역할
5. **추천 리스트 UI 와이어프레임** — AI 근거·외부 출처·과거 이력의 동시 노출
