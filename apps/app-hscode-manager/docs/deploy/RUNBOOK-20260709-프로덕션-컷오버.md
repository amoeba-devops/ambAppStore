## 1. 선결조건 체크리스트 (컷오버 전 확정)
- [ ] **prod BFF `JWT_SECRET` = prod AMA 글로벌 secret** — 프로덕션 AMA가 서명한 ama_token을 prod hscode BFF가 검증해야 함. 타 prod 앱 BFF(.env)와 동일값 사용(5개 앱 공유 관례). **불일치 시 401**(스테이징에서 겪은 것과 동일).
- [ ] **prod AMA hscode 등록(`amb_entity_custom_apps` eca_id `fd5dcaef`)**
  - `eca_url`: 현재 `stg-apps.amoeba.site/app-hscode` → **`https://apps.amoeba.site/app-hscode`** 로 전환(prod 사용자용). (스테이징 테스트 유지가 필요하면 별도 등록 검토)
  - `eca_jwt_secret_enc`: **NULL(글로벌 fallback) 유지** — prod 글로벌 secret으로 서명되도록. (앱별 secret이 있으면 prod BFF 글로벌 검증과 불일치 → 401)
- [ ] **호스트 포트 충돌 확인** — hscode 컨테이너 host 포트(bff 3102 / web 5202 / postgres 5433 / redis 6380 / tei 8081)가 prod 기존 앱과 겹치지 않는지. 겹치면 compose ports 조정.
- [ ] **prod nginx** — `apps.amoeba.site` 호스트 nginx에 `/app-hscode/`·`/app-hscode/api/` 라우팅 추가 준비.
- [ ] **CLAUDE_API_KEY(유효)** 준비(설정 UI에서 저장할 유효 키). 없으면 AI층 폴백으로 동작(검색/RAG는 정상).
- [ ] **임베딩** — prod도 자체 `tei-hscode`(BGE-M3) 기동. 최초 모델 다운로드(~2GB) 시간 고려.

## 2. 컷오버 절차

### Step 1 — 소스 반영 (hscode 한정, 타 앱 미교란)
```bash
ssh amb-production
cd ~/ambAppStore
git fetch origin main
# hscode 앱 디렉토리만 origin/main 기준으로 갱신 (타 앱 소스 미변경)
git checkout origin/main -- apps/app-hscode-manager
```
> `git pull origin main`(전체)은 560bddc 이후 main의 **모든** 변경을 작업트리에 반영 → 타 앱 소스 드리프트. hscode만 필요하므로 **경로 한정 checkout** 권장. (실제 배포는 hscode 컨테이너만 재빌드하므로 타 앱 런타임엔 영향 없음.)
└─ 사이드 임팩트: 타 앱 소스 미변경. hscode 앱 파일만 갱신.

### Step 2 — 프로덕션 `.env` 작성 (git 미포함, 서버 직접)
`apps/app-hscode-manager/backend/.env` (`.env.example` 기준):
```
NODE_ENV=production
PORT=3102
DB_HOST=postgres-hscode
DB_PORT=5432
DB_USERNAME=hscode_app
DB_PASSWORD=<prod 강력암호>
DB_DATABASE=db_hsm
REDIS_HOST=redis-hscode
REDIS_PORT=6379
JWT_SECRET=<prod AMA 글로벌과 동일>          # ★ 선결조건 1
JWT_ISSUER=ama.amoeba.site
SETTINGS_ENC_KEY=<32바이트 prod 키>
CLAUDE_API_KEY=                              # UI에서 설정 저장 권장(비워도 폴백)
CLAUDE_MODEL_VERSION=claude-opus-4-8
AI_DAILY_BUDGET_USD=50
EMBEDDING_PROVIDER=bge-m3
EMBEDDING_DIMENSIONS=1024
# EMBEDDING_ENDPOINT는 compose가 http://tei-hscode:80 로 오버라이드
```
└─ 사이드 임팩트: 없음(파일 생성). 시크릿은 서버에만.

### Step 3 — 컨테이너 기동 (postgres→tei→bff/web)
```bash
cd ~/ambAppStore/apps/app-hscode-manager
# DB/Redis/TEI 먼저 (TEI는 모델 다운로드로 느림)
docker compose -f docker-compose.app-hscode.yml up -d postgres-hscode redis-hscode tei-hscode
# TEI 준비 대기(로그 "Ready") 후 앱
docker compose -f docker-compose.app-hscode.yml build bff-app-hscode web-app-hscode
docker compose -f docker-compose.app-hscode.yml up -d bff-app-hscode web-app-hscode
```
- postgres 최초 기동 시 `sql/hscode-manager-schema.sql` 자동 적용(pgvector/pgcrypto + hsm_ 10테이블 + `hsr_embedding vector(1024)`).
└─ 사이드 임팩트: 신규 컨테이너만 추가. 기존 prod 앱 무영향(별도 컨테이너·네트워크 공유만).

### Step 4 — nginx 라우팅 (apps.amoeba.site)
호스트 nginx conf에 추가(스테이징과 동일 패턴, 경로 스트립):
```
location /app-hscode/api/ { proxy_pass http://127.0.0.1:3102/api/; ... }
location /app-hscode/     { proxy_pass http://127.0.0.1:5202/;     ... }
```
`nginx -t && nginx -s reload` (또는 web nginx가 root+/app-hscode/ 동시 서빙하는 스테이징 구성 준용).
└─ 사이드 임팩트: 기존 `/`·타 앱 라우팅 보존 확인 필수(테스트 후 reload).

### Step 5 — prod AMA 등록 URL 전환
prod AMA DB에서 eca_url을 prod로:
```sql
-- ssh amb-production → docker exec amb-postgres-production psql -U amb_user -d db_amb
UPDATE amb_entity_custom_apps
SET eca_url='https://apps.amoeba.site/app-hscode'
WHERE eca_id='fd5dcaef-0b74-4051-a52b-b09a714c9cf1';
-- eca_jwt_secret_enc는 NULL(글로벌 fallback) 유지 확인
```
└─ 사이드 임팩트: 이후 AMA에서 hscode 진입이 prod 앱으로. 스테이징 진입은 끊김(테스트 유지 필요 시 별도 등록).
