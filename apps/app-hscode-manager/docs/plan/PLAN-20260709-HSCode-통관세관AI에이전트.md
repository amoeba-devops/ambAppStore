## 2. 단계별 구현 계획 (재정의 우선순위)

### Phase 0 — 스키마 (완료)
- 마이그레이션 `sql/migrations/20260709-hs-agent.sql` 스테이징 적용·검증 ✅. 프로덕션 적용은 배포 시.

### Phase 1 — 레퍼런스 RAG 구축 (최우선, R1/R2)
- **Step 1-1**: **면장 업로드 강화** — 기존 `reference/imports` 재사용, 임베딩 자동(TEI). 관리자 화면에서 다건 업로드·진행률.
  - └─ 사이드 임팩트: 기존 import 흐름 확장, 임베딩 백필 재사용.
- **Step 1-2**: **HS 기준표 적재** — VN(기준)+KR/CN/US 코드·구조를 `hsm_hs_codes`(마스터) + 해설/판단기준을 `hsm_documents`(지식) 적재. import/시드 도구.
  - └─ 사이드 임팩트: 신규 마스터/지식 데이터. VN 우선 가중 로직.
- **Step 1-3**: 지식 청킹·임베딩(문서유형별) → `hsm_doc_chunks`(pgvector). 검색에 편입.
  - └─ 사이드 임팩트: 다원 RAG(면장+기준표+지식) 통합.

### Phase 2 — 문서 업로드 매칭 (주 기능, R4)
- **Step 2-1**: **자유 양식 파서** — 업로드(엑셀/PDF) → 시트/텍스트 추출 → **LLM이 컬럼 의미 추론**(품명·성분·용도·수량 등) → 정규화 품목 리스트. 기존 어댑터는 알려진 양식 fast-path.
  - └─ 사이드 임팩트: LLM 파싱 비용 → 캐싱·행수 상한. 파싱 실패 행 플래그.
- **Step 2-2**: **품목별 RAG 매칭** — 각 품목 하이브리드 검색(면장+기준표) → HS 추천(신뢰도·근거[유사면장/기준]·확인필요). 대량=BullMQ 비동기.
  - └─ 사이드 임팩트: 기존 excel 배치 재사용·확장.
- **Step 2-3**: **추천 리스트 → 승인/컨펌 → 요청건 저장** — Recommendation 묶음(요청건) + 승인 시 확정분 면장/지식(LEARNED) 재저장.
  - └─ 사이드 임팩트: R5/R8 자기개선. 저품질 유입 게이트.

### Phase 3 — Q&A 챗봇 (R3)
- **Step 3-1**: 대화형 Q&A — 세션 이력 유지, RAG(면장+기준표+지식) 근거 답변, 되묻기(명확화). 기존 `search-qa` 확장.
  - └─ 사이드 임팩트: 응답 계약 확장(대화·근거). 폴백.

### Phase 4 — 쉬운 UI/UX (R7) & 프론트
- **Step 4-1**: **업로드 중심 홈** — 드래그&드롭 즉시 분석, 결과 리스트, 승인. 최소 클릭. (§4 와이어프레임)
- **Step 4-2**: Q&A 챗봇 UI(대화), 레퍼런스 구축 UI(면장/기준표), 요청건 이력, **고급 수동입력(별도 버튼)**.
- **Step 4-3**: i18n ko/en/vi.
  - └─ 사이드 임팩트: 라우트 재구성, 기존 화면 회귀.

### Phase 5 — 수동 입력(고급) + 규칙엔진 보조 (R6)
- Item/Composition 정형입력·`RuleEngineService`(주성분·위험점수)를 "고급" 경로로. 주 흐름 비침습.
  - └─ 사이드 임팩트: 선택 기능, 주 흐름 무영향.

### Phase 6 — 검증 & 배포
- 표본(면장+기준표) 시드 → 스테이징 E2E(업로드→매칭→승인→재저장, 챗봇) → 프로덕션(런북 준용, 스키마 적용).
