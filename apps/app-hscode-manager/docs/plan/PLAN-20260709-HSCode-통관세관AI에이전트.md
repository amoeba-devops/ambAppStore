## 1. 시스템 개발 현황 분석

### 1.1 재사용 자산(이번 세션 구축, 프로덕션 라이브)
| 자산 | 상태 |
|------|------|
| 임베딩 | BGE-M3(TEI 셀프호스트) dim 1024, pgvector, 하이브리드(벡터+키워드) |
| AI | `AiClassificationService`(설정 Claude 단일샷, 폴백·예산가드) |
| 코퍼스/저장 | `hsm_hs_references`(신고이력)+임베딩, `POST /reference/entries` save-back(dedupe·audit) |
| 설정 | 어드민 AI(api_key/model/budget), `hsm_app_settings` key-value, `@SuperAdminOnly` 전역쓰기 |
| 멀티테넌시 | `ent_id` 스코핑, JwtAuthGuard/EntityScopeGuard/RoleGuard |
| 배포 | 스테이징·프로덕션 컨테이너(bff/web/postgres/redis/tei), nginx, AMA SSO |

### 1.2 신규 요구(업로드 스펙) 대비 갭
| 스펙 요소 | 현재 | 갭 |
|-----------|------|-----|
| 4계층(마스터/입력/지식/판정) | 신고이력 1종 | Item·Composition·Document·Chunk·Case·Recommendation·마스터사전 신규 |
| 규칙엔진(주성분·본질특성·용도우선·위험점수) | 없음 | 신규 |
| 다중관점 RAG(5관점) | 단일 하이브리드 | 확장 |
| 출력(에스컬레이션·확정/검토·근거청크·미해결질문) | candidates+rationale | 스키마 확장 |
| 청킹 전략(문서유형별) | 신고이력 행 임베딩 | 지식문서 청킹 파이프 신규 |
| BOM/성분비 정형 입력 | 속성 폼 | Item+Composition 입력 신규 |

### 1.3 제약
- PostgreSQL synchronize 비활성 → **수동 SQL 마이그레이션**(업로드 `schema.sql` 채택·prefix 매핑).
- 콘텐츠 소싱(규칙/사례/사전심사/FTA·VN/KR/CN 자료) **선행 필수**(데이터).
- 커밋 `git add apps/app-hscode-manager` 범위 한정. 기본 모델 `claude-opus-4-8`.

## 2. 단계별 구현 계획 (Part D 로드맵 기반)

### Phase 0 — 결정 게이트 & 스키마
- **Step 0-1**: D1(옵션A·prefix)·Part C 오픈항목(대상 품목군·위험임계·에스컬레이션 채널·인니 범위·MVP 범위) 확정.
  - └─ 사이드 임팩트: 미확정 시 후속 재작업. **게이트**.
- **Step 0-2**: 업로드 `schema.sql`을 `hsm_` prefix로 매핑한 **수동 마이그레이션 SQL** 작성·적용(신규 테이블 + hnsw 인덱스). 기존 `hsm_*` 무변경.
  - └─ 사이드 임팩트: 신규 테이블만 추가, 기존 스키마 영향 없음.

### Phase 1 — 마스터/입력 계층 (우선순위 1·3)
- **Step 1-1**: 마스터 사전(hsm_hs_codes/materials/product_names/uses/processes) 엔티티·시드.
- **Step 1-2**: **Item**(hsm_items) + **Composition**(hsm_compositions) 엔티티/DTO/서비스/컨트롤러. BOM/성분비 CRUD(`/api/v1/items`, `/items/:id/compositions`), 성분비 합 검증, `ent_id` 스코핑.
  - └─ 사이드 임팩트: Feature C(속성) 확장 경로와 통합. 신규 API.

### Phase 2 — 규칙엔진 (우선순위 3, FR-004)
- **Step 2-1**: `RuleEngineService` — Composition에서 **주성분·주성분비율·본질적특성유형·혼합/적층/코팅 플래그·용도우선·가공도** 파생 계산 + **위험점수→`preRulingRequired`/`customsRiskLevel`**.
  - └─ 사이드 임팩트: 결정론적 힌트 → RAG 질의·LLM 컨텍스트 안정화. Item 파생컬럼 갱신.

### Phase 3 — 지식계층 & 다중관점 RAG (우선순위 2·5)
- **Step 3-1**: **Document**(hsm_knowledge_docs) + **Chunk**(hsm_doc_chunks) 엔티티. 문서유형별 **청킹 파이프**(법령=조문, 사례=1사례1청크, 기술=성분/물성 분리, HS해설=chapter-heading-subheading 태그, PDF=OCR후 조항). chunk 메타(chunk_type/rule_type/chapter_tags/material_tags/applies_to_mix/applies_to_ratio/embedding_text/citation_text). BGE-M3 임베딩(1024).
- **Step 3-2**: `MultiPerspectiveRetrievalService` — **5관점 병렬 검색**(①품명/거래명 ②재질/함량 ③용도/기능 ④가공공정 ⑤국가별HS차이·사전심사사례) → 신고이력 + 지식청크 융합, **VN 가중**. 슈퍼관리자 전역 지식(ent_id NULL) + 엔티티 LEARNED 결합.
  - └─ 사이드 임팩트: 검색 비용↑ → 관점별 topN 상한·캐싱. 기존 hybrid retrieval 재사용·확장.

### Phase 4 — LLM 종합 & 출력 (FR-005, A5, 우선순위 5)
- **Step 4-1**: `AiClassificationService` 확장 — **규칙결과 + 다중검색결과** 결합, **강화 통관 페르소나(설정 override)**, 구조화 출력 = **복수후보(VN HS 8/10 + KR/CN 매핑 + 신뢰도 + 추천사유 + 분류근거[근거청크 인용] + 확인쟁점 + VN최종확인 + 확정/검토 status)** + `advanceRulingNeeded`. JSON 계약·그라운딩 강제.
- **Step 4-2**: **Recommendation**(hsm_recommendations) 저장(후보·근거청크·rule_signals·미해결질문·에스컬레이션·final_user_action).
  - └─ 사이드 임팩트: 출력 계약 변경 → 프론트 동반. 폴백(키없음/파싱실패).

### Phase 5 — 판정계층 & 자기개선 (우선순위 6, FR-008/009)
- **Step 5-1**: **Classification Case**(hsm_class_cases) — 확정/반려 이력 축적. 확정 시 (기존)신고이력 + (신규)Case + 지식(LEARNED) 재저장·임베딩.
- **Step 5-2**: 에스컬레이션(사전심사 필요) → 관세사 검토 채널 연동(**Part C 채널 확정 후**: Slack/메일/티켓).
- **Step 5-3**: 품질지표(확정일치율·반려율) 수집 → 검색 재정렬·가중.
  - └─ 사이드 임팩트: 자기개선 루프. 저품질 확정 유입 방지 게이트.

### Phase 6 — 어드민(지식/설정) 관리
- **Step 6-1**: 지식문서 관리 UI/API(`@SuperAdminOnly`) — 업로드·태그·신뢰도·버전·청킹.
- **Step 6-2**: 에이전트 설정(페르소나 `system_prompt`·`customs_rules`·모델·위험임계) 어드민 엔티티별.
  - └─ 사이드 임팩트: 전역 지식은 슈퍼관리자, LEARNED는 엔티티.

### Phase 7 — 프론트(화면) & i18n (§5 와이어프레임)
- Item/BOM 입력·추천결과·지식관리·에이전트설정·사례이력 화면 + ko/en/vi.
  - └─ 사이드 임팩트: 신규 라우트, 기존 화면 회귀.

### Phase 8 — 검증 & 배포
- 시드 품목군(화학원료·도료·섬유·플라스틱) 표본 검증 → 스테이징 → 프로덕션(런북 준용).
