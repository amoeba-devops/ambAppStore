# 작업계획서 — 문서 업로드 매칭 PDF 파싱

- 문서 ID: PLAN-20260710-PDF문서파싱
- 선행: REQ-20260710-PDF문서파싱
- 재사용: DocumentParserService(AppConfigService/ConfigService/Anthropic 이미 주입), 비동기 매칭 파이프라인(#101), 예산/키 해석 패턴(AiClassificationService)

## 1. 시스템 현황
- DocumentParserService: 엑셀/CSV(SheetJS) + AI 컬럼추론(Claude). PDF는 400.
- Anthropic SDK `@anthropic-ai/sdk ^0.110` — document(base64 PDF) 콘텐츠 블록 지원.
- 매칭은 uploadAndEnqueue→BullMQ 워커(비동기). PDF 추출만 추가하면 이후 흐름 동일.

## 2. 단계별 구현

### Phase 1 — PDF 추출(백엔드)
- **Step 1-1**: DocumentParserService에 `parsePdf(entId, buffer)` 추가
  - 키 해석(설정>env). 없으면 `BusinessException(KNOWLEDGE_PARSE_FAILED, "PDF 분석은 AI 설정 필요", 400)`.
  - Anthropic `messages.create({ model, max_tokens, messages:[{role:'user', content:[ {type:'document', source:{type:'base64', media_type:'application/pdf', data}}, {type:'text', text: PDF_EXTRACT_PROMPT} ]}] })`.
  - 응답 JSON `{items:[{name,material,usage,quantity}]}` 파싱(펜스 제거, 실패 시 400).
  - ParsedItem[] 매핑(rowIndex 순번, 품명 없으면 needsReview). MAX_ITEMS 상한 적용.
  - └─ 사이드 임팩트: PDF 추출은 업로드 요청 내 동기 1콜(수 초). 비용↑ → max_tokens 상한.
- **Step 1-2**: `parse()`의 PDF 분기 교체 — 기존 400 throw → `return this.parsePdf(entId, buffer)`.
  - └─ 사이드 임팩트: 없음(엑셀/CSV 경로 무변경).

### Phase 2 — 프론트
- **Step 2-1**: MatchUploadPage `accept`에 `.pdf` 추가, 안내문(엑셀/CSV/PDF) i18n.
- **Step 2-2**: 업로드 에러 메시지(키 없음/PDF 실패) 기존 m.uploadError로 노출(코드 기반). 필요 시 세분 키.
  - └─ 사이드 임팩트: 키 없을 때 PDF는 400 → 기존 에러 토스트.

### Phase 3 — 검증·배포
- 스테이징(키 없음): PDF 업로드→키 안내 400 확인. 프로덕션(키 있음): 텍스트 PDF·스캔 PDF→품목 추출→비동기 매칭.
- 스테이징 먼저 → 프로덕션.
