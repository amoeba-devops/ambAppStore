## 1. 시스템 개발 현황 분석

### 1.1 디렉토리 구조 (실측)
```
backend/src/
├── domain/{reference,knowledge,matching,chat,admin-settings,...12개}   # 기존 도메인
│   └── {controller,service,entity,dto/{request,response},mapper}/*.ts   # 표준 서브폴더
├── auth/decorators/{auth,admin-only,super-admin-only,...}.decorator.ts
├── common/{error-codes.ts, exceptions/business.exception.ts, filters/global-exception.filter.ts}
└── app.module.ts                                                        # 도메인 모듈 등록
frontend/src/
├── pages/*.tsx (11) · services/*.service.ts (10) · stores/auth.store.ts
├── router.tsx (createBrowserRouter, basename '/app-hscode') · App.tsx (NAV 배열)
└── i18n/{i18n.ts, locales/{ko,en,vi}/hscode.json}
sql/migrations/YYYYMMDD-{feature}.sql   # synchronize=false, 수동 적용
```

### 1.2 기술 스택 (실측)
- BE: NestJS 10 + TypeORM 0.3 + PostgreSQL 15 + pgvector(1024, BGE-M3/TEI). 전역 `JwtAuthGuard`(APP_GUARD) + `EntityScopeGuard` + `RoleGuard`. 글로벌 prefix `api/v1`.
- FE: React 18 + Vite + TailwindCSS + react-router-dom + Zustand + React Query + i18next.
- 배포: `deploy-staging.sh` 경유(직접 build 금지), 수동 SQL 마이그레이션(스테이징 먼저).

### 1.3 기존 코드 재사용 포인트
| 재사용 대상 | 위치 | 용도 |
|-------------|------|------|
| `KnowledgeIngestService`(export됨) | `domain/knowledge/knowledge.module.ts` | RAG 승격 브릿지(FR-KB-014) → `hsm_documents` 삽입·청킹·임베딩 |
| `@Auth()`/`@AdminOnly()`/`@SuperAdminOnly()` | `auth/decorators/` | 권한 데코레이터 그대로 사용 |
| `@CurrentUser()`, `AmaJwtPayload` | `auth/` | userId/entityId/level/role 접근 |
| AI 연결(Claude) | `domain/admin-settings/service/ai-connection.service.ts` | 온디맨드 번역 엔진 |
| `BusinessException`+`ERROR_CODES` | `common/` | 표준 에러 응답 |
| axios client(`/app-hscode/api/v1`) | `frontend/src/lib/api-client.ts` | FE 서비스 계층 |

### 1.4 제약사항
- `synchronize: false` → **모든 스키마는 수동 SQL**. TypeORM nullable 컬럼 `type:` 명시 필수.
- `E5xxx`(reference/import)·`E7xxx`(knowledge/RAG) 이미 점유 → KB는 **`E8xxx` 신규 범위** 할당.
- i18n 평면 점표기(`keySeparator/nsSeparator=false`) — 신규 키도 동일 방식.
- 파일 업로드: 현재 앱에 multer/스트리밍 업로드 엔드포인트 부재 → 신규 도입.

## 5. DB 마이그레이션 (수동 SQL)

`sql/migrations/20260710-knowledge-base.sql` — `synchronize=false`, 스테이징 먼저 수동 적용. `CREATE TABLE IF NOT EXISTS`.

```
hsm_kb_categories   (cat_id PK, ent_id NULL, cat_name, cat_sort_order, cat_dot_color,
                     cat_created_at, cat_updated_at, cat_deleted_at)
hsm_kb_posts        (pst_id PK, ent_id NULL, pst_title, pst_content, pst_source_lang,
                     pst_category_id FK→hsm_kb_categories, pst_is_pinned, pst_view_count,
                     pst_is_promoted_to_rag, pst_promoted_doc_id uuid NULL, timestamps, pst_deleted_at)
hsm_kb_post_translations (ptr_id PK, pst_id FK, ptr_target_lang, ptr_translated_title,
                     ptr_translated_content, ptr_source(AI/MANUAL), ptr_translated_at,
                     UNIQUE uq_hsm_kb_post_translations_pst_lang(pst_id, ptr_target_lang))
hsm_kb_attachments  (att_id PK, pst_id FK, att_file_path, att_file_name, att_file_size BIGINT,
                     att_mime_type, att_file_ext, att_created_at)
hsm_kb_dashboard_blocks (dsb_id PK, ent_id NULL, dsb_block_type(NOTICE/TIP), dsb_title, dsb_body,
                     dsb_flag_label, dsb_sort_order, dsb_is_active, timestamps)
hsm_kb_tags         (tag_id PK, ent_id NULL, tag_name, tag_type(COUNTRY/HS_CHAPTER), timestamps)
hsm_kb_post_tags    (ptg_id PK, pst_id FK, tag_id FK, UNIQUE uq_hsm_kb_post_tags(pst_id, tag_id))
```

인덱스: `idx_hsm_kb_posts_category`, `idx_hsm_kb_posts_view_count`, `idx_hsm_kb_posts_pinned`, `idx_hsm_kb_posts_search`(GIN tsvector 또는 pg_trgm), `idx_hsm_kb_dashboard_blocks_type_sort`, FK 인덱스.
제약: `pk_*` PRIMARY KEY, `fk_hsm_kb_posts_categories`, `fk_hsm_kb_post_translations_posts`(ON DELETE CASCADE), `fk_hsm_kb_attachments_posts`, `fk_hsm_kb_post_tags_*`.
주의: `pst_promoted_doc_id`는 FK 제약 없이 uuid NULL(도메인 격리 — `hsm_documents` 참조는 논리적). TypeORM 엔티티에 `type:'uuid'` 명시.

배포: `ssh ambAppStore@stg-apps.amoeba.site` → psql로 SQL 적용 → `deploy-staging.sh` 빌드·재기동.
