# HS Code Manager — 이벤트 시나리오 (Rev.2)

> 범위: 카고러시(베트남 물류통관)의 담당자가 **고객사(수출업체)가 제공한 원부자재의 속성 정보(재질·성분·구성·기능·용도)**를 등록하여, 시스템이 내부 누적 데이터와 외부 권위 데이터를 검색하고 **AI 추천**을 통해 베트남 수입에 맞는 HS코드 후보를 제시하면, 담당자가 그중 하나를 **컨펌**해 수출업체·수출국가·날짜별로 영속화하기까지의 흐름.
> 전제: 본 앱의 주 대상은 **원부자재**이며, 바코드를 가진 기성 완제품은 보조 트랙으로 다룬다. 본 시나리오 Rev.1의 "바코드 스캔"이 주 진입점이었던 가정은 폐기한다.
> 작성 기조: 「HSCODE_설계문서」의 4단계 파이프라인(M1~M4)·5개 엔티티 구조 위에서 *진입 이벤트와 데이터 흐름*만을 정의한다. 본 문서는 흐름이고, 어떤 요구를 만족해야 하는가는 「HSCODE_요구사항명세서」가 다룬다.

---

## 1. 시나리오의 의미와 위치

원부자재 통관 업무의 본질은 *제품 그 자체를 보는 것이 아니라, 제품을 구성하는 속성을 본다는 것*이다. 화학물질이면 성분과 CAS, 철강이면 재질과 두께, 기계류면 기능과 구성품 — 이런 속성의 조합이 HS코드를 결정한다. 따라서 본 앱의 진입 이벤트는 "바코드 스캔"이 아니라 **"속성 정보의 등록"**이다. 바코드 스캔은 우연히 GTIN이 부착된 기성 완제품에 대해서만 의미가 있고, 일반 원부자재 흐름에서는 보조 입력 채널의 위치를 가진다.

이 흐름의 또 다른 본질은 **AI를 의사결정 엔진이 아니라 검색·해석의 보조자로 둔다는 점**이다. AI(Claude 등)는 정규화된 속성 정보를 받아 베트남 관세청 등의 외부 자료를 해석하고 후보 HS코드를 제안하지만, *최종 확정은 사람*이다. 사용자의 컨펌은 형식적 절차가 아니라 시스템 학습의 라벨이 되며, 컨펌된 결과는 *수출업체·수출국가·날짜*를 키로 누적되어 다음 매칭 작업의 1순위 참조 자료가 된다. 즉 본 앱은 매 작업마다 자기 자신의 과거 결정을 먼저 본 뒤 외부를 본다.

핵심 식별자는 GTIN이 아니라 **속성 집합의 정규화 해시**다. 같은 재질·성분·기능을 가진 원부자재는 고객사가 달라도 동일 코드로 분류될 가능성이 높으므로, 속성 기반 매칭이 GTIN 매칭보다 일반화 가능성이 크다. 다만 수출업체와 수출국가 정보가 함께 누적되어야 *원산지 판정과 FTA 협정세율 분기*가 가능하다. 따라서 영속화 단위는 `(수출업체, 수출국가, 등록일자)`의 3항 키다.

## 2. 주요 이벤트 흐름 (Primary Flow)

가장 흔한 경로 — *고객사가 신규 원부자재 정보를 시트로 전달하거나 메일로 보내, 담당자가 앱에 등록하고 HS코드를 매칭하는 경우*다. 사용자 트리거(U)와 시스템 처리(S)로 표기한다.

**E1 (U) 고객사 정보 접수.** 담당자가 고객사(수출업체)로부터 원부자재 정보를 받는다. 입력 자료의 형태는 이메일 본문·첨부 엑셀·PDF·메신저 등 다양하다. 이 시점에 담당자는 `Inquiry` 1건을 생성하면서 **수출업체와 수출국가**를 함께 지정한다.

**E2 (U) 입력 방식 선택.** 담당자는 세 가지 입력 채널 중 하나를 선택한다 — (a) 엑셀 일괄 등록(다수 행), (b) 앱 내 직접 입력(단건/소량), (c) 바코드 스캔(기성품 보조). 일반 원부자재 흐름은 (a) 또는 (b)다.

**E3 (U) 속성 정보 입력.** 채널별 세부 흐름은 다르지만 결과는 동일하다 — 각 원부자재에 대해 *카테고리(chemical/steel_mechanical/equipment/other)와 그 카테고리의 필수 속성(재질·성분·구성·기능·용도)*이 채워진 레코드들이 입력 큐에 적재된다.

- (a) **엑셀 일괄 등록**: 사용자가 파일을 업로드하면 시스템은 헤더 기반으로 컬럼 매핑을 제안한다. 사용자가 매핑을 확정하면 행별로 파싱·검증되고, 검증 실패 행은 보류 큐로 분리된다. 정상 행은 입력 큐에 적재된다.
- (b) **직접 입력**: 앱의 동적 폼(§4 설계문서 기반)을 통해 카테고리 분기 후 속성을 채운다. 입력 완료 시 1건이 입력 큐에 적재된다.
- (c) **바코드 스캔(보조)**: GTIN을 추출해 ERP의 Item을 우선 조회한다. 매칭되면 그 Item의 누적 속성이 폼에 프리-필되어 (b)로 합류한다. 매칭되지 않으면 (b)의 신규 입력으로 떨어진다.

**E4 (S) 정규화 및 카테고리 판별.** 입력 큐의 각 레코드를 정규화한다 — 재질 표준명(예: "스뎅" → "SUS304" 후보), CAS 번호 표기 정리, 기능 키워드 추출(예: "압연", "주조"). 정규화 결과로부터 *속성 정규화 해시(`composition_hash`)*가 산출된다. 카테고리가 비어 있거나 모호하면 키워드 분류기로 잠정 카테고리를 부여하고 사용자 확인을 요청한다.

**E5 (S) 1순위 검색 — 내부 ERP 매칭.** 정규화 해시·카테고리·핵심 속성을 키로 ERP의 과거 `Classification` 누적을 조회한다. 매칭 우선순위는 (1) 동일 수출업체·동일 수출국가의 과거 채택 코드, (2) 동일 수출국가의 과거 채택 코드, (3) 속성 유사도 기반 fuzzy 매칭이다. 매칭 결과의 신뢰도가 임계(0.85) 이상이면 *내부 후보*로 채택되고, 외부 검색을 생략할 수 있다(A3로 분기). 미만이면 E6로 진행한다.

**E6 (S) 2순위 검색 — 외부 권위 데이터.** 베트남 *BIEU THUE XNK 2026*을 1차 권위로 두고, 한국 관세청 HS, FTA 협정세율 테이블, 기타 분류표를 보조로 조회한다. 검색 키워드는 정규화된 속성에서 추출되며(예: 재질·CAS·기능), 각 출처에서 후보 코드와 세율·요건 정보를 수집한다.

**E7 (S) AI 추천 엔진 호출.** 정규화된 속성 + 내부 후보 + 외부 검색 결과를 한 컨텍스트로 묶어 LLM(Claude 등)에 전달한다. AI의 역할은 두 가지다 — (i) *후보 HS코드를 베트남 수입 기준에 맞게 좁힌다*, (ii) *각 후보에 대해 분류 근거(어떤 속성이 어떤 호와 매칭되는가)를 자연어로 생성한다*. AI는 새로운 코드를 발명하지 않으며, 반드시 내부·외부 검색 결과 범위 내에서만 후보를 제시한다.

**E8 (S) 후보 랭킹.** AI 추천 결과에 §2.2의 보수적 세율 룰과 §2.4 에스컬레이션 게이트 사전 검사를 결합해 정렬한다. 동일 수출업체·국가의 과거 채택 코드가 후보에 포함되어 있으면 우선순위를 가산한다. 결과는 1순위 + 대안 후보 N개의 리스트다.

**E9 (S) 추천 리스트 렌더링.** 사용자에게 후보 리스트를 제시한다. 각 항목은 HS코드, 기본세율, FTA 협정세율, 신뢰도 점수, *AI가 생성한 근거 문장*, 외부 출처 링크(BIEU THUE 조항 등)를 포함한다. 동일 수출업체·국가의 과거 채택 이력은 별도 마커로 강조하고, 12개월 초과·추징 이력은 §2.3 정책에 따라 경고로 표시한다.

**E10 (U) 사용자 컨펌.** 담당자가 후보 중 1건을 선택해 컨펌한다. 컨펌 시점에 *선택 사유(`selection_rationale`)*를 함께 기록할 수 있다(과거 사례와 다른 선택을 한 경우 사유 입력은 필수다). 컨펌은 분류의 라벨이 되어 시스템 학습 데이터로 누적된다.

**E11 (S) 에스컬레이션 게이트 검사.** §2.4의 6개 트리거를 검사한다. 해당 시 M3 Expert Review로 라우팅되며 본 흐름은 일시 정지한다. 해당 없으면 E12로 진행한다.

**E12 (S) 영속화 — 수출업체·수출국가·날짜 키 누적.** 컨펌된 분류는 `Classification` 레코드로 ERP에 저장되며, 검색 인덱스 측면에서 *(수출업체, 수출국가, 등록일자)*가 별도 보조 키로 부착된다. 입력 정보(속성), AI 추천 결과(후보 N개와 근거), 사용자 선택(채택 1건과 사유)은 함께 저장되어 사후 검증·재학습의 자료가 된다. 동일한 입력 패턴이 다음에 들어오면 E5의 1순위 매칭이 즉시 응답할 수 있게 된다.

**E13 (S) 다음 단계 핸드오프.** M4 Respond & Archive로 컨트롤이 넘어가며 고객사 응대 양식이 생성된다. 본 시나리오는 여기서 종료된다.

이 흐름의 핵심 설계 의도는 *내부 데이터를 먼저 본다*는 정책이다. 외부 검색과 AI 추천은 비용·지연·불확실성을 가지므로, 내부 누적이 충분한 케이스에서는 호출 자체를 생략해 빠르게 응답한다. 누적이 시간이 지나며 외부 호출의 비율을 점진적으로 줄이는 것이 본 앱이 가치를 만드는 방식이다.

## 3. 대안 흐름 (Alternate Flows)

**A1. 엑셀 일괄 등록의 부분 실패.** E3-(a)에서 일부 행의 검증이 실패하는 경우다. 정상 행은 입력 큐로, 실패 행은 *보류 큐*로 분리되어 사용자에게 행별 오류 원인이 함께 표시된다. 사용자는 보류 큐를 인앱 편집기로 수정해 재검증을 시도할 수 있고, 수정이 어려운 행은 건너뛰고 진행할 수 있다. 보류된 행은 Inquiry에 묶여 추적된다.

**A2. 내부 매칭 즉시 — 외부 검색 생략.** E5에서 내부 매칭 신뢰도가 0.85 이상인 경우다. 외부 검색(E6)과 AI 추천(E7)을 생략하고 내부 후보 단일 항목만 추천 리스트에 표시한다. 단, 마지막 채택일이 12개월을 초과했거나 동일 코드에 대한 추징 이력이 있는 경우는 본 분기로 들어오지 않고 정상 흐름을 따른다 — *경고는 외부 데이터로 검증되어야* 의미가 있기 때문이다.

**A3. 다중 후보 분기 — 자동 에스컬레이션.** E8에서 후보가 3개 이상으로 분기되고 1·2순위 사이의 신뢰도 차가 작은 경우다. 추천 리스트는 정상 표시하되 *"전문가 검토 필요"* 배너를 띄우고, E10 사용자 선택 즉시 E11에서 §2.4 트리거 (b)가 발동되어 M3로 라우팅된다.

**A4. 정보 부족 — 추가 정보 요청 루프.** E4의 정규화 또는 E7의 AI 추천 단계에서 *결정적 속성의 결손*이 감지되는 경우다(예: 화학물질인데 CAS가 모두 비어 있음). 시스템은 결손 항목을 명시한 *추가 정보 요청 양식*을 생성해 담당자에게 노출하며, 담당자는 이를 고객사에 전달해 보강한 뒤 E3로 복귀한다. 이 분기는 §4 동적 폼의 `intake_completeness_score`가 0.7 미만일 때 자동 발동된다.

**A5. 동일 수출업체·국가의 과거 채택과 다른 선택.** E10에서 사용자가 동일 수출업체·수출국가의 가장 최근 채택 코드와 다른 후보를 선택한 경우다. 시스템은 *사유 입력을 강제*하고, 컨펌 후 해당 차이를 검토 대기 큐에 별도로 적재한다(인지된 정책 변경인지, 일회성 예외인지 사후 분류하기 위함).

**A6. 기성 완제품 — 바코드 보조 매칭.** E2에서 (c)를 선택한 경우다. GTIN으로 Item을 즉시 매칭해 E3 단계를 단축한다. 매칭된 Item의 누적 속성을 폼에 프리-필한 뒤 (b)의 직접 입력 흐름과 합류한다. 본 분기는 원부자재 흐름에서는 드물게 발생한다.

**A7. AI 추천 비호출 — 단순 외부 조회.** 사용자가 *AI 추천을 끄고 외부 검색 결과만 보겠다*고 명시적으로 선택한 경우다(검증·교육·정책상의 이유). E7이 생략되고 외부 검색 결과(E6)가 그대로 추천 리스트로 표시된다. 신뢰도 계산에서 AI 가산점이 빠진다.

## 4. 예외 흐름 (Exception Flows)

**X1. 엑셀 포맷 비호환.** E3-(a)에서 헤더 매핑이 실패하거나 필수 컬럼이 모두 누락된 경우다. 시스템은 *표준 템플릿 다운로드*를 안내하고 업로드를 거부한다.

**X2. 외부 데이터 소스 장애.** E6에서 BIEU THUE XNK 또는 한국 관세청 API가 미응답하는 경우다. 사용 가능한 내부 데이터와 캐시된 외부 데이터만으로 E7~E9를 진행하되, 모든 후보의 신뢰도에 −0.2 페널티를 가산하고 *"외부 데이터 미반영"* 경고를 띄운다.

**X3. AI 추천 엔진 실패.** E7에서 AI 호출이 실패하거나 결과가 형식적으로 부적합한 경우(예: 환각으로 존재하지 않는 코드를 제안)다. 시스템은 AI 결과를 폐기하고 외부 검색 결과(E6)만으로 E8 랭킹을 수행한다. 모든 후보에 *"AI 추천 미반영"* 마커가 부착되며 사용자 컨펌 시 사유 입력이 권고된다.

**X4. 권한 부족.** 일부 고객사 데이터는 기밀로 분류되어 있을 수 있다. 권한이 없는 담당자가 해당 수출업체의 누적을 조회·등록하려 하면 *권한 요청 흐름*으로 전환되며 본 시나리오는 거기서 종료된다.

**X5. 추징·분쟁 이력으로 잠긴 코드.** E5에서 매칭된 내부 후보가 `disputed` 상태이면 해당 후보는 추천 리스트에 표시되되 *선택 불가* 상태로 잠금된다. 사용자는 동일 속성에 대해 새 분류를 시도해야 하며, 자동으로 §2.4 트리거 (d)에 의해 M3 에스컬레이션이 발동된다.

**X6. 중복 컨펌 — 동일 입력에 대한 재작업.** E10에서 컨펌 직전에 동일 `(수출업체, 수출국가, composition_hash, 등록일자)`가 이미 존재함이 감지되는 경우다. 시스템은 *기존 레코드 갱신*과 *신규 레코드 생성* 중 선택을 요구하며, 갱신을 택하면 기존 레코드를 `superseded`로 전환하고 새 레코드로 대체한다.

## 5. 기존 설계문서와의 매핑

본 시나리오의 각 이벤트는 「HSCODE_설계문서」의 다음 부분에 대응한다.

E1·E2는 M1 Intake의 *진입 단계*이며, 기존 §4 동적 폼 설계에 **엑셀 일괄 등록 채널**을 추가해야 한다. E3은 §4.1·§4.2의 공통+카테고리 필드를 그대로 사용한다. E4는 §4.4의 "동일 품목 자동 매칭 흐름"을 *속성 정규화 해시 기반*으로 일반화한 것이다. E5~E7은 §1.2의 M2 Classify를 *내부 1순위 → 외부 2순위 → AI 추천*의 3단 검색으로 구체화한 것이다(기존 설계에는 검색 우선순위가 명시되지 않았다). E8은 §2.2의 보수적 세율 룰을 적용하는 지점이다. E9·E10은 사용자 인터페이스 영역으로, 부록 §3 화면 설계 단계에서 다룬다. E11은 §2.4 에스컬레이션 트리거 검사다. E12는 §3.1 Classification 영속화이지만, *(수출업체, 수출국가, 등록일자)*의 보조 키와 *AI 추천 근거 저장 필드*가 신규 설계로 필요하다.

이 매핑이 드러낸 *후속 설계 필요 지점*은 다음과 같다.

1. **엑셀 일괄 등록 채널**의 헤더 매핑 규칙·검증 정책·보류 큐 모델
2. **속성 정규화 해시(composition_hash)** 산출 알고리즘과 카테고리별 정규화 규칙
3. **AI 추천 엔진**의 입력 컨텍스트 스키마, 출력 검증 규칙, 환각 방지 가드레일
4. **수출업체·수출국가** 마스터 테이블과 Classification에의 보조 키 부착
5. **검색 우선순위** 정책(내부 → 외부 → AI)의 임계값과 fallback 규칙
6. **AI 추천 근거**(reasoning) 저장 필드 및 외부 출처 인용 모델
