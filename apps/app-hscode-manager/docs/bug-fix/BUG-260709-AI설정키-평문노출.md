# BUG-260709 — 어드민(설정) AI api_key 평문 노출 (보안)

- **작성일**: 2026-07-09
- **심각도**: 🔴 High (시크릿 노출, POL-005 위반)
- **대상**: HS Code Manager `/app-hscode/admin`, `GET /api/v1/admin/settings/AI`
- **관련**: 어드민(설정) SCR-006, `app-config.service`, `crypto.util`

## 1. 증상
`GET /admin/settings/AI` 응답이 `api_key`(Anthropic 키 `sk-ant-…`)를 **마스킹 없이 전체 평문**으로 반환. `is_secret: true`로 표기되지만 값은 완전 노출.

```json
{ "key": "api_key", "value": "sk-ant-api03-…(전체)", "is_secret": true }
```

## 2. 원인
정상 코드(`crypto.util.maskSecret`=`••••`+끝4자, `app-config.viewValue`가 secret 복호화 후 마스킹)와 스테이징 응답이 불일치. 아래 둘 중 하나 이상:

- **(A) 스테이징 구버전 빌드**: 마스킹 도입 이전의 `viewValue`(복호화 원문 그대로 반환)가 rsync 오버레이 git-드리프트로 잔존.
- **(B) 평문 저장**: 과거 프론트가 `is_secret`를 누락 전송 → `putByCategory`의 `isSecret=false` → **암호화 없이 평문 저장** → `GET`의 `!isSecret` 경로가 평문 반환. (응답의 `is_secret:true`는 프론트 필드 스키마 라벨일 수 있음.)

두 경로 모두 "비밀키가 응답에 평문 노출"로 귀결.

## 3. 수정
**서버측 방어(클라이언트 신뢰 제거)** — `backend/src/domain/admin-settings/service/app-config.service.ts`:

1. `SECRET_KEYS`(현재 `['api_key']`) 도입. 키 이름 자체가 비밀이면 강제 처리.
2. **쓰기**: `isSecret = isSecretKey(key) || (item.is_secret ?? existing ?? false)` → api_key는 클라이언트 값과 무관하게 **항상 암호화 저장**(평문 저장 원천 차단).
3. **읽기(`viewValue`)**: `r.isSecret || isSecretKey(key)`면 절대 평문 노출 금지. 암호화 저장분은 복호화→마스킹, **레거시 평문(복호화 실패)도 원문 대신 마스킹만**(`maskSecret(r.value)`) → 기존 평문 행도 재저장 없이 즉시 안전.
4. `getByCategory`의 `isSecret` 응답도 `r.isSecret || isSecretKey(key)`로 일관.

→ (A)든 (B)든, 이 코드가 배포되면 `api_key`는 항상 `••••XXXX`로만 노출.

## 4. 조치(운영 필수, 순서)
1. **🔴 노출된 Anthropic 키 즉시 폐기·재발급**(console.anthropic.com). 응답으로 유출된 키는 재사용 금지.
2. 본 수정 포함 **현재 빌드를 스테이징 재배포**(git-드리프트 정합) → (A) 제거.
3. 어드민(설정)에서 **새 키 재저장** → 암호화 저장 + 마스킹 확인(`GET`이 `••••XXXX` 반환).
4. (선택) 스테이징 `hsm_app_settings`에서 category='AI', key='api_key' 행의 `aps_is_secret`·값 포맷 점검(암호화 `iv:tag:data` 형태인지)으로 (A)/(B) 확정.

## 5. 검증
- 단위: 평문 저장 행/암호화 행 모두 `viewValue`가 `••••` 마스킹 반환.
- E2E: `GET /admin/settings/AI` → api_key `••••XXXX`. 저장 후 재조회 동일. `getSecret`(런타임 내부)은 평문 정상 반환(분류/연결테스트 동작).
- `nest build` 그린.

## 6. 비고
- 별개 이슈: 같은 화면 "연결 테스트" 401(HSC-E9999 "Unauthorized")은 **인증 토큰(만료/미갱신) 문제**로 추정 — AMA 호스트 재진입으로 새 ama_token 확보 후 재시도. 마스킹 수정과 무관.
