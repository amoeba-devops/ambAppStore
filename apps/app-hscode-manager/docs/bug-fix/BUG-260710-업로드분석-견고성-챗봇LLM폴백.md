# BUG-260710 — 문서 업로드 분석 견고성 + 챗봇 LLM 폴백 + 면장 임의양식 분석

- **작성일**: 2026-07-10
- **환경**: 프로덕션 apps.amoeba.site/app-hscode (Claude 키 미설정, RAG 코퍼스 비어있음)
- **분류**: 기능/버그 수정 (통관 AI 에이전트)

## 증상

### #1 HS Code 자동 매칭 업로드 400
`POST /matching/upload → 400 (Bad Request)`, 프론트 "업로드에 실패했습니다."
- 재현: 헤더가 `품명/성분/용도`류 토큰과 맞으면 200, **임의 헤더(A,B,C)면 400 HSC-E7003 "Could not identify a product-name column"**.
- 원인: AI 키 미설정 → 휴리스틱만 동작 → 품명 컬럼 미검출 시 **하드 400**. 실제 회사 파일은 (a) 헤더 토큰 불일치, (b) **상단 제목/메타 행이 있어 1행을 헤더로 오인**.

### #2 챗봇 — RAG 없으면 즉시 검색 폴백
"면 50%, 의류 상의" → "관련 참조를 찾지 못했습니다…(AI 미설정 시 검색 기반 답변)".
- 원인: `ChatService.buildAnswer`가 **`refs.length>0 || snippets.length>0`일 때만 Claude 호출**. RAG 비면 키가 있어도 LLM 미시도 → 항상 되묻기 폴백.
- 요구: RAG에 없으면 **LLM 일반지식 기반 추론 답변**(베트남 기준·혼합물 규칙·단계별 추론·구조화 출력)을 시도.

### #3 레퍼런스 면장 업로드 "0건 적재"
면장 파일 업로드 → "✓ 0건 적재 완료".
- 원인: `reference/imports`가 **3개 고정 어댑터(BaoCaoHangChiTiet/ToKhai/VMSG)** detect 실패 시 formatType=OTHER, 0 적재. 헤더행 탐지도 **베트남어 HS 토큰(`mã hs` 등)만** 인식.
- 요구: 업로드 파일을 **실제 분석**(임의 양식에서 HS·품명 컬럼 추론)해 적재.

## 원인 요약
세 건 공통 = **임의 양식(다양한 고객 문서) 분석 견고성 부족** + AI 키 없을 때 휴리스틱 폴백이 약함.

## 수정 방안

### #1 matching `DocumentParserService`
- **헤더행 자동 탐지**: 첫 ~8행 중 품명/성분/용도/수량 토큰 매칭 점수가 가장 높은 행을 헤더로 선택(상단 제목행 스킵).
- **Graceful 폴백**: 품명 컬럼 미검출 시 400 대신 **1열을 품명으로 가정 + 전 품목 검토필요 + parseNote 안내**(하드 실패 제거).

### #2 chat `ChatService`
- **키 있으면 RAG 비어도 Claude 호출**(일반지식 모드, `source=AI_GENERAL`, disclaimer).
- **그라운딩 조건부**: refs 있으면 후보를 refs로 제한, 없으면 LLM 제안 HS 허용(신뢰도 하향).
- **SYSTEM_PROMPT 강화**: 베트남 수입통관 기준·일반 분류원칙·혼합물/복합소재 규칙·원산지 vs HS 구분·단계별 추론·구조화 출력.

### #3 reference import
- **HS 헤더 토큰 확장**(ko/en/vi: `hs code`,`hscode`,`hs`,`세번`,`hs코드`,`mã hs`…).
- **휴리스틱 폴백 어댑터** 추가(마지막 순위): 임의 헤더에서 HS 컬럼 + 품명 컬럼 추론 → 정규화 적재.

## 검증
- #1: 임의 헤더·제목행 파일 업로드 → 200(검토필요 표시). 표준 헤더 회귀 정상.
- #2: 키 설정 시 RAG 빈 상태 "면 50% 의류 상의" → LLM HS 후보+근거+disclaimer. 키 없으면 기존 폴백.
- #3: 임의 면장 파일 → 적재 건수 > 0, 임베딩 생성.

## 배포
스테이징 먼저 → 검증 → 프로덕션.
